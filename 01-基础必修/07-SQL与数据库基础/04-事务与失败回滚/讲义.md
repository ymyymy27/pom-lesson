# 事务与失败回滚

课程编号：B29 · 建议投入：3 小时（含练习与复盘） · 状态：可试学

## 本课任务

确保一组必须共同成功的修改不会只完成一半。

## 先修检查

完成上一课，能独立运行其示例并用自己的话解释结果。若尚不能，先回到上一课完成独立练习。

## 理解过程

事务让一组操作整体提交或整体回滚。失败后应检查数据是否仍符合原约束。连接上下文处理事务，但连接生命周期也需要管理。

先在纸上预测示例的输出，再逐行跟踪执行。把“代码做什么”和“为什么要这样做”分别说清楚。运行后若结果与预测不同，标记第一个出现差异的位置。

## 完整示例

文件：[示例.py](示例/示例.py)。从仓库根目录在 PowerShell 执行：

```powershell
python "01-基础必修/07-SQL与数据库基础/04-事务与失败回滚/示例/示例.py"
```

```python
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE tasks(id INTEGER PRIMARY KEY)")
try:
    with db:
        db.execute("INSERT INTO tasks VALUES(1)")
        db.execute("INSERT INTO tasks VALUES(1)")
except sqlite3.IntegrityError:
    print("已回滚")
print(db.execute("SELECT COUNT(*) FROM tasks").fetchone()[0])
db.close()
```

代码中的数据可直接修改。跟做时每次只改变一个输入，记录修改前的预测与修改后的输出。恢复原始输入再次运行，确认结果可重复。

## 常见错误与排查

捕获错误后继续提交可能保留部分修改，破坏“一起成功或一起失败”的要求。

遇到问题先记录执行命令、完整错误和最小输入，再定位到对应行。只描述“不能运行”不足以复现问题。
