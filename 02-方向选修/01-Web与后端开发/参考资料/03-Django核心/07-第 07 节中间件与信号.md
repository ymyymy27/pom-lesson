# 第 07 节：中间件与信号

## 一、中间件（Middleware）

### 1.1 什么是中间件？

中间件是 Django 处理请求和响应的 **钩子系统**。每个请求/响应都会经过所有中间件，类似于一层层"洋葱"。

```
请求进入方向 →

Request → Middleware1 → Middleware2 → Middleware3 → View
                                                      ↓
Response ← Middleware1 ← Middleware2 ← Middleware3 ← View

← 响应返回方向
```

### 1.2 内置中间件

```python
# config/settings.py
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',           # 安全头
    'django.contrib.sessions.middleware.SessionMiddleware',    # Session 管理
    'django.middleware.common.CommonMiddleware',               # URL 重写（APPEND_SLASH）
    'django.middleware.csrf.CsrfViewMiddleware',               # CSRF 防护
    'django.contrib.auth.middleware.AuthenticationMiddleware', # 用户认证（request.user）
    'django.contrib.messages.middleware.MessageMiddleware',    # 消息框架
    'django.middleware.clickjacking.XFrameOptionsMiddleware',  # 防点击劫持
]
```

> ⚠️ 中间件的 **顺序很重要**！Session 中间件必须在 Auth 之前，因为 Auth 依赖 Session。

### 1.3 自定义中间件

```python
# apps/core/middleware.py
import time
import logging
import json

logger = logging.getLogger(__name__)

class RequestTimingMiddleware:
    """记录每个请求的处理时间"""
    
    def __init__(self, get_response):
        self.get_response = get_response
        # 一次性初始化（服务器启动时）
    
    def __call__(self, request):
        # ===== 请求到达视图之前 =====
        start_time = time.time()
        
        # 调用下一个中间件或视图
        response = self.get_response(request)
        
        # ===== 视图处理完成之后 =====
        duration = time.time() - start_time
        logger.info(
            f"{request.method} {request.path} → {response.status_code} "
            f"({duration:.3f}s)"
        )
        
        # 在响应头中添加处理时间
        response['X-Request-Duration'] = f"{duration:.3f}s"
        
        return response


class JSONErrorMiddleware:
    """将 Django 错误响应转换为 JSON 格式（前后端分离必备）"""
    
    def __init__(self, get_response):
        self.get_response = get_response
    
    def __call__(self, request):
        response = self.get_response(request)
        
        # 只处理 API 请求
        if request.path.startswith('/api/'):
            if response.status_code == 404 and response['Content-Type'] != 'application/json':
                from django.http import JsonResponse
                return JsonResponse({'error': '资源不存在', 'status': 404}, status=404)
            if response.status_code == 403 and response['Content-Type'] != 'application/json':
                from django.http import JsonResponse
                return JsonResponse({'error': '无权限访问', 'status': 403}, status=403)
        
        return response


class CORSMiddleware:
    """简易 CORS 中间件（后续用 django-cors-headers 替代）"""
    
    def __init__(self, get_response):
        self.get_response = get_response
    
    def __call__(self, request):
        # 处理预检请求
        if request.method == 'OPTIONS':
            from django.http import HttpResponse
            response = HttpResponse()
        else:
            response = self.get_response(request)
        
        # 添加 CORS 头
        response['Access-Control-Allow-Origin'] = '*'
        response['Access-Control-Allow-Methods'] = 'GET, POST, PUT, PATCH, DELETE, OPTIONS'
        response['Access-Control-Allow-Headers'] = 'Content-Type, Authorization'
        
        return response
```

## 二、信号（Signals）

### 2.1 什么是信号？

信号是 Django 的 **事件系统**。当某些操作发生时（如保存模型、删除模型、用户登录），Django 发出信号，你可以监听这些信号并执行自定义逻辑。

```
模型保存 → 发出 post_save 信号 → 你的处理函数执行
用户登录 → 发出 user_logged_in 信号 → 你的处理函数执行
```

### 2.2 内置信号

| 信号 | 触发时机 | 常用场景 |
|------|---------|---------|
| `pre_save` | 模型保存之前 | 数据预处理 |
| `post_save` | 模型保存之后 | 创建关联数据、发送通知 |
| `pre_delete` | 模型删除之前 | 清理关联资源 |
| `post_delete` | 模型删除之后 | 日志记录 |
| `m2m_changed` | 多对多关系变更 | 同步缓存 |
| `request_started` | 请求开始 | 日志 |
| `request_finished` | 请求结束 | 清理 |
| `user_logged_in` | 用户登录 | 记录登录日志 |
| `user_logged_out` | 用户登出 | 清理会话 |

### 2.3 使用信号

```python
# apps/users/signals.py
from django.db.models.signals import post_save
from django.dispatch import receiver
from django.conf import settings
from .models import Profile

@receiver(post_save, sender=settings.AUTH_USER_MODEL)
def create_user_profile(sender, instance, created, **kwargs):
    """用户创建时自动创建 Profile"""
    if created:
        Profile.objects.create(user=instance)

@receiver(post_save, sender=settings.AUTH_USER_MODEL)
def save_user_profile(sender, instance, **kwargs):
    """用户保存时同时保存 Profile"""
    if hasattr(instance, 'profile'):
        instance.profile.save()
```

```python
@receiver(pre_save, sender=Task)
def task_pre_save(sender, instance, **kwargs):
    """任务保存前：记录状态变更"""
```

```python
# apps/tasks/signals.py
from django.dispatch import Signal

# 定义自定义信号
task_completed = Signal()    # 任务完成时发出
task_assigned = Signal()     # 任务分配时发出

# 发送信号（在模型方法或视图中）
class Task(models.Model):
    def complete(self):
        self.status = 'completed'
        self.save()
        # 发送自定义信号
        task_completed.send(sender=self.__class__, task=self)
    
    def assign_to(self, user):
        self.assignee = user
        self.status = 'in_progress'
        self.save()
        task_assigned.send(sender=self.__class__, task=self, user=user)

# 接收信号
@receiver(task_completed)
def on_task_completed(sender, task, **kwargs):
    logger.info(f"任务完成: #{task.pk} {task.title}")
    # 更新项目统计、发送通知等

@receiver(task_assigned)
def on_task_assigned(sender, task, user, **kwargs):
    logger.info(f"任务 #{task.pk} 分配给 {user.username}")
```

### 2.6 信号使用原则

**适合用信号的场景：**
- 解耦不同应用之间的逻辑（用户创建 → 自动创建 Profile）
- 第三方应用的扩展点
- 不方便直接修改模型代码的场景

**不适合用信号的场景：**
- 同一应用内的简单逻辑 → 直接在 `save()` 方法中处理
- 复杂的业务流程 → 使用 Service 层
- 信号调试困难，过度使用会导致"隐式"逻辑难以追踪

```python
# ❌ 不推荐：同一应用内用信号
@receiver(post_save, sender=Task)
def update_task_count(sender, instance, **kwargs):
    instance.project.task_count = instance.project.tasks.count()
    instance.project.save()

# ✅ 推荐：直接在视图或 Service 层处理
def create_task(data, user):
    task = Task.objects.create(**data, creator=user)
    task.project.update_task_count()
    return task
```

```python
# apps/tasks/management/commands/cleanup_tasks.py
from django.core.management.base import BaseCommand
from django.utils import timezone
from datetime import timedelta
from apps.tasks.models import Task

class Command(BaseCommand):
    help = '清理过期的已取消任务'
    
    def add_arguments(self, parser):
        parser.add_argument(
            '--days',
            type=int,
            default=30,
            help='清理多少天前的任务（默认30天）',
        )
        parser.add_argument(
            '--dry-run',
            action='store_true',
            help='只显示将要删除的数量，不实际删除',
        )
    
    def handle(self, *args, **options):
        days = options['days']
        dry_run = options['dry_run']
        
        cutoff_date = timezone.now() - timedelta(days=days)
        
        queryset = Task.objects.filter(
            status='cancelled',
            updated_at__lt=cutoff_date,
        )
        
        count = queryset.count()
        
        if dry_run:
            self.stdout.write(
                self.style.WARNING(f'[DRY RUN] 将删除 {count} 个已取消的过期任务')
            )
        else:
            deleted, _ = queryset.delete()
            self.stdout.write(
                self.style.SUCCESS(f'成功删除 {deleted} 个已取消的过期任务')
            )
```
