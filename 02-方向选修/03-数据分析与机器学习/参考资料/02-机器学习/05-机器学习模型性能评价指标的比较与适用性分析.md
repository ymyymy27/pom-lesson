## 1. 分析框架：逻辑轴、受众视角与业务成本

### 1.1 为什么需要一条逻辑轴

评价指标看似是一个"结果"层面的问题——模型训练完了，拿几个数字汇报一下。但实际上，**指标的选择会反向塑造整个研发过程**：

- 你选择监控什么指标，就决定了你在 Dataflow 阶段关注哪些数据分布问题
- 你选择优化什么指标，就决定了 PyTorch 训练中 Loss 函数的设计方向
- 你选择验证什么指标，就决定了量化前后对比的核心维度
- 你选择部署后监控什么指标，就决定了 vLLM 服务需要暴露哪些可观测性数据

没有"最好"的指标，只有"最适合当前受众"的指标。这条逻辑轴将指标选择拆解为三个受众视角：

| 受众 | 核心关切 | 典型指标 | 业务场景举例 |
|---|---|---|---|
| **算法工程师**（你） | 模型对各类别的泛化能力，调参方向 | Macro-F1、Per-class Recall、AUC | 训练时监控每个类的 F1 收敛曲线 |
| **产品 / 业务方** | 预测结果对业务指标的因果影响 | Precision vs Recall 的业务权衡 | 欺诈检测：漏检代价 vs 误报代价 |
| **终端用户 / 系统** | 模型输出的直接可用性 | 服务延迟、吞吐量、准确率阈值 | vLLM 推理时的 P99 延迟 + Accuracy |

> **核心洞察**：不均衡数据集和多分类宏微均分，本质上都是"受众视角切换"带来的计算方式调整。当你的视角从"算法工程师看整体性能"转向"业务方看某个类别的召回率"，指标的选取和计算方式就需要重新适配。

### 1.2 混淆矩阵：所有指标的起点

无论数据集多么不均衡、分类任务多么复杂，一切分类指标都从混淆矩阵的四个格子出发：

```
                    预测结果
                 正类(Positive)   负类(Negative)
  实际   正类(Positive)     TP              FN
  情况   负类(Negative)     FP              TN
```

- **TP（True Positive）**：实际为正，预测也为正 → 正确识别
- **FP（False Positive）**：实际为负，预测为正 → 误报
- **FN（False Negative）**：实际为正，预测为负 → 漏检
- **TN（True Negative）**：实际为负，预测也为负 → 正确排除

牢记这四个字母的含义，所有衍生指标都是这四个数字的不同组合。

### 1.3 业务成本矩阵：指标的真正度量衡

混淆矩阵的四个格子里藏着**业务代价**，而不仅仅是数字。定义业务成本后，指标的优先级就会完全不同：

$$
\text{总代价} = C_{FN} \times FN + C_{FP} \times FP
$$

| 场景 | FN（漏检）代价 | FP（误报）代价 |
|---|---|---|
| 欺诈检测 | 高（直接损失金钱） | 低（人工复核成本） |
| 垃圾邮件过滤 | 低（漏一封正常邮件） | 高（用户丢失重要信息） |
| 癌症早筛 | 极高（生命代价） | 中（进一步检查成本） |
| 内容推荐 | 低（用户体验略降） | 极低（反正不强制推送） |

**这个成本矩阵是决定 Precision vs Recall 优先级的最终依据**，而不是哪个指标数字更好看。

## 2. 二分类完整指标体系：从混淆矩阵到每个数字的含义

### 2.1 从混淆矩阵衍生的完整指标家族

混淆矩阵的四个数字可以组合出远超 Accuracy/Precision/Recall 的丰富指标体系：

```
┌──────────────────────────────────────────────────────────────┐
│                    混淆矩阵完整指标家族                         │
├──────────────────────────────────────────────────────────────┤
│  基础计数     TP、FP、FN、TN（所有指标的原材料）               │
│  比率家族     Precision、Recall(Sensitivity)、Specificity     │
│              FPR、FNR、TNR                                   │
│  综合指标     F1、Fβ、Accuracy、MCC                          │
│  概率指标     ROC-AUC、PR-AUC、G-Mean、Brier Score           │
│  诊断指标     LR+、LR-、DOR、PPV、NPV                        │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 完整比率家族

**查准率（Precision / Positive Predictive Value）**

$$
\text{Precision} = \frac{TP}{TP + FP}
$$

"你预测为正的里面，有多少真的对了？" 当 FP 很高时，Precision 急剧下降。

**召回率（Recall / Sensitivity / True Positive Rate）**

$$
\text{Recall} = \frac{TP}{TP + FN}
$$

"实际为正的，你召回了多少？" 当 FN 很高时，Recall 急剧下降。

**特异度（Specificity / True Negative Rate）**

$$
\text{Specificity} = \frac{TN}{TN + FP}
$$

"实际为负的，你正确排除了多少？" 当 FP 很高时，Specificity 下降。

**假阳性率（False Positive Rate）**

$$
\text{FPR} = \frac{FP}{TN + FP} = 1 - \text{Specificity}
$$

**假阴性率（False Negative Rate）**

$$
\text{FNR} = \frac{FN}{TP + FN} = 1 - \text{Recall}
$$

**阳性预测值（PPV）** 和 **阴性预测值（NPV）**：

$$
\text{PPV} = \frac{TP}{TP + FP} = \text{Precision} \quad \text{（两者等价）}
$$

$$
\text{NPV} = \frac{TN}{TN + FN}
$$

NPV 的含义是"预测为负的样本中，有多少真的对了"。注意：**NPV 和 NPV 的数值高度依赖于疾病的实际患病率**，在患病率极低的场景下，即使模型的特异性很高，NPV 也可能接近 100%（因为 TN 占绝大多数）。这意味着 NPV 不是一个模型的固有属性，而是模型性能与数据分布共同决定的。

### 2.3 诊断能力指标：似然比

**阳性似然比（LR+）** 和 **阴性似然比（LR-）** 是比单独的 Precision/Recall 更有信息的诊断指标：

$$
\text{LR+} = \frac{\text{Recall}}{1 - \text{Specificity}} = \frac{TPR}{FPR}
$$

$$
\text{LR-} = \frac{1 - \text{Recall}}{\text{Specificity}} = \frac{FNR}{TNR}
$$

LR+ 的含义：**当真实标签为正时，模型给出正预测的概率是给出负预测概率的多少倍？** LR+ 越大，模型的阳性诊断能力越强。LR- 越小（接近 0），模型的排除阴性能力越强。

**诊断优势比（Diagnostic Odds Ratio, DOR）**：

$$
\text{DOR} = \frac{\text{LR+}}{\text{LR-}} = \frac{TP \times TN}{FP \times FN}
$$

DOR 的取值范围是 \[0, +∞），值越大模型诊断能力越强。**DOR 的优势在于它综合了 LR+ 和 LR-，是一个不需要阈值的单一数字**，常用于医学诊断模型的元分析中。

### 2.4 综合数值例子：所有指标一网打尽

设混淆矩阵为：

```
TP = 80, FP = 20, FN = 30, TN = 870
总样本 = 1000，正类 = 110（10%），负类 = 890（90%）
```

**所有指标计算如下：**

| 指标 | 计算公式 | 计算过程 | 结果 | 含义 |
|---|---|---|---|---|
| Accuracy | (TP+TN)/(TP+FP+FN+TN) | (80+870)/1000 | **95.0%** | 整体分对的比例 |
| Precision | TP/(TP+FP) | 80/100 | **80.0%** | 预测为正的中有多少对 |
| Recall (TPR) | TP/(TP+FN) | 80/110 | **72.7%** | 实际为正的召回了多少 |
| Specificity (TNR) | TN/(TN+FP) | 870/890 | **97.8%** | 实际为负的正确排除了多少 |
| FPR | FP/(TN+FP) | 20/890 | **2.2%** | 负样本被误标为正的比例 |
| FNR | FN/(TP+FN) | 30/110 | **27.3%** | 正样本被漏检的比例 |
| F1-Score | 2·P·R/(P+R) | 2·0.8·0.727/(0.8+0.727) | **76.2%** | Precision-Recall 调和平均 |
| G-Mean | √(Recall·Specificity) | √(0.727·0.978) | **84.3%** | 两类识别率的平衡 |
| MCC | (TP·TN-FP·FN)/√(...) | (69600-600)/√(100·110·890·980) | **0.735** | 四个值的综合相关度 |
| LR+ | TPR/FPR | 0.727/0.022 | **33.0** | 正预测 vs 负预测的概率比 |
| LR- | FNR/TNR | 0.273/0.978 | **0.28** | 接近 0 说明阴性排除能力强 |
| DOR | TP·TN/(FP·FN) | 69600/600 | **116** | 综合诊断优势比 |

### 2.5 调和平均的深层含义：为什么 F1 而不是算术平均？

Precision 和 Recall 的算术平均是 **(P + R) / 2**，但 F1 使用的是调和平均 **2PR/(P+R)**。两者有什么本质区别？

假设 Precision = 0.9，Recall = 0.1：

- 算术平均 = (0.9 + 0.1) / 2 = **0.5**（看起来还行）
- 调和平均 F1 = 2 × 0.9 × 0.1 / (0.9 + 0.1) = 0.18 / 1.0 = **0.18**（揭示了真实问题）

调和平均惩罚了 P 和 R 之间的巨大差距。**F1 只有在 P 和 R 都处于中高水平时才会给出高分**——这正是我们想要的，因为一个只追求 Precision 而忽略 Recall（或反之）的模型在实际业务中往往不可用。

推广到更一般的 **Fβ-Score**，β 参数控制的正是对 Recall 的相对重视程度：

$$
F_\beta = \frac{(1 + \beta^2) \times \text{Precision} \times \text{Recall}}{(\beta^2 \times \text{Precision}) + \text{Recall}}
$$

- **β = 0**：退化为 Precision
- **β = 1**：标准 F1
- **β → +∞**：退化为 Recall

## 3. 不均衡数据集下的指标适用性

### 3.1 不均衡的本质：少数类的声音被淹没

**不均衡（Imbalance）**指的是分类任务中各类别的样本数量差异显著。当比例超过 10:1 时，传统的 Accuracy 指标就开始失效；超过 100:1 时，几乎所有基于计数的指标都会产生误导。

**为什么 Accuracy 会骗人？** 考虑一个 1:100 不均衡的数据集（欺诈检测，10000 样本中 99 个欺诈）：

| 模型策略 | TP | FP | FN | TN | Accuracy | Recall | Precision | F1 |
|---|---|---|---|---|---|---|---|---|
| 全部预测为负 | 0 | 0 | 99 | 9901 | **99.01%** | **0%** | N/A | **0** |
| 随机预测（p=0.01） | ~1 | ~99 | ~98 | ~9802 | ~98% | ~1% | ~1% | ~1% |
| 正常模型 | 85 | 150 | 14 | 9751 | **98.36%** | **85.9%** | **36.2%** | **50.9%** |

三行模型的 Accuracy 都在 98% 以上，但 Recall 从 0% 到 85.9% 差距巨大。**Accuracy 是一个被多数类稀释的平均值，它掩盖了少数类上的灾难性失败。**

### 3.2 各指标在不均衡场景下的系统性分析

| 指标 | 不均衡下的表现 | 不均衡时的数值变化 | 根本原因 |
|---|---|---|---|
| **Accuracy** | 严重高估 | 随不均衡加剧趋近于 1.0 | 被多数类主导 |
| **Error Rate** (= 1-Accuracy) | 严重低估 | 趋近于 0 | Accuracy 的镜像 |
| **Precision** | 虚高风险 | 当模型极少预测正类时，Precision 可以很高但 Recall 极低 | 不包含 FN |
| **Recall** | 真实反映少数类能力 | 少数类识别率 | 不包含 TN |
| **Specificity** | 真实反映多数类能力 | 多数类识别率 | 不包含 FN |
| **F1-Score** | 相对可靠但不稳定 | 对正类比例敏感 | 同时受 P 和 R 影响 |
| **ROC-AUC** | 鲁棒 | 对比例变化不敏感 | 基于排序而非计数 |
| **PR-AUC** | 敏感 | 在极端不均衡时快速下降 | 直接受 base rate 影响 |
| **G-Mean** | 高度适用 | 同时惩罚 Recall 和 Specificity 任何一方的下降 | 几何平均的特性 |
| **MCC** | 均衡 | 随不均衡加剧趋于保守 | 四个值的归一化乘积 |

### 3.3 ROC-AUC 的深入分析：不依赖阈值的排序能力

ROC-AUC 的核心优势在于它描述的是模型的**排序能力**而非决策能力：

**AUC 的物理含义（重复但关键）：** 在所有正负样本对中，模型把正样本的预测分数排在负样本之前的比例是多少？

$$
\text{AUC} = P(\text{score}(x^+) > \text{score}(x^-))
$$

这个定义的强大之处在于：**AUC 不需要你选任何阈值**。它衡量的是"模型有多擅长区分正负样本"，而这个能力本身不依赖于你选择在哪里划定正负边界。

**不均衡数据下 ROC-AUC 为什么依然可靠：**

```
假设正样本 100 个，负样本 9900 个（1:99 不均衡）

情况 A：模型随机预测
  所有样本 score 都在 0.5 附近
  正样本排在前面的概率 = 50%
  AUC = 0.5

情况 B：模型有较强能力
  正样本 score 平均高于负样本
  即使正样本只有 100 个，只要排序正确，AUC 仍然可以很高
  AUC ≈ 0.95

关键：AUC 关心的是"排名"而非"数量"
即使正样本只有 1%，只要它们排在前面，AUC 就高
```

**但 ROC-AUC 有一个致命弱点**：在极端不均衡时（>1:1000），AUC 可能接近 1.0，给人"模型完美"的错觉，但实际的 Precision-Recall trade-off 可能很差。这是因为 ROC-AUC 的 x 轴 FPR 在极端不均衡时，FP 的微小变化被巨大的 TN 分母稀释了。

### 3.4 PR-AUC：正类视角下的真实战场

PR-AUC（Precision-Recall Curve 下面积）直接刻画"召回率增加过程中 Precision 的衰减速度"：

```
PR 曲线示例（1:100 不均衡）：
Precision
  1.0 |┤
      │  ╲
  0.5 |    ╲___
      └──────────── Recall
     0.0          1.0

PR-AUC = 0.82 → 在提高召回率的过程中保持了较好的 Precision
```

**PR-AUC 与 ROC-AUC 的关键区别**：

| 维度 | ROC-AUC | PR-AUC |
|---|---|---|
| x 轴 | FPR（负类视角） | Recall（正类视角） |
| y 轴 | TPR（正类视角） | Precision（正类视角） |
| 对负样本数量的敏感性 | 低（分母是 TN+FP） | **高**（不直接涉及负样本） |
| 极端不均衡时的表现 | 可能接近 1.0 但不真实 | 快速下降，揭示真相 |
| 推荐场景 | 评估整体排序能力 | 关注正类预测质量 |

**什么时候同时看两者**：当不均衡比率超过 20:1 时，同时报告 ROC-AUC 和 PR-AUC。两者的比值（ROC-AUC / PR-AUC）可以作为不均衡程度的指标——比值越大，说明正负样本分布越悬殊，单看 ROC-AUC 越容易产生误导。

### 3.5 Balanced Accuracy：不均衡下的"公平 Accuracy"

Balanced Accuracy 是 Accuracy 的一种改进，专门用于不均衡数据：

$$
\text{Balanced Accuracy} = \frac{\text{Recall} + \text{Specificity}}{2}
$$

它的本质是**两类各自准确率的算术平均**，与每个类的样本数量无关。

回到前面的例子（TP=80, FP=20, FN=30, TN=870）：

- Standard Accuracy = (80 + 870) / 1000 = **95.0%**
- Balanced Accuracy = (0.727 + 0.978) / 2 = **85.25%**

Balanced Accuracy（85.25%）比 Standard Accuracy（95.0%）更能反映模型的真实综合能力。**Balanced Accuracy 在 sklearn 中可以通过 `balanced_accuracy_score` 直接计算**，它是不均衡二分类场景下 Accuracy 的首选替代。

### 3.6 Cohen's Kappa 系数：消除随机性的影响

Kappa 系数衡量的是"观察一致率"相对于"随机一致率"的提升幅度：

$$
\kappa = \frac{p_o - p_e}{1 - p_e}
$$

- $p_o$：观察一致率（Observed Agreement）= Accuracy
- $p_e$：随机期望一致率（Expected Agreement by Chance）

**Kappa 的取值标准：**
- κ < 0：比随机还差
- 0.0 ~ 0.2：轻微一致（slight）
- 0.2 ~ 0.4：一般一致（fair）
- 0.4 ~ 0.6：中等一致（moderate）
- 0.6 ~ 0.8：高度一致（substantial）
- 0.8 ~ 1.0：几乎完美一致（almost perfect）

**为什么 Kappa 有用**：在高度不均衡的数据中，即使模型有一定预测能力，随机猜测也能达到很高的 Accuracy（因为大多数样本是负类）。Kappa 扣除了随机因素的影响，告诉你模型带来的"额外提升"有多少。

### 3.7 不均衡场景下的采样策略与指标联动

不均衡处理通常有两个方向：**采样策略**（改变训练数据分布）和**代价敏感学习**（改变 Loss 权重）。两者都会影响指标的含义。

**采样策略对指标解读的影响：**

| 策略 | 做法 | 对指标的影响 |
|---|---|---|
| **欠采样**（随机删除多数类） | 减少多数类样本 | 改变了训练集的 base rate，后续指标计算必须在独立验证集上进行 |
| **过采样**（复制/生成少数类，如 SMOTE） | 增加少数类样本 | 容易导致过拟合，需要交叉验证 |
| **SMOTE**（合成少数类） | 在少数类样本之间插值生成新样本 | 新样本不是真实数据，可能引入噪声 |
| **欠采样 + 集成**（BalancedBagging） | 对多数类多次欠采样，训练多个模型集成 | 保持原始分布的同时缓解不均衡 |

**关键原则**：无论用哪种采样策略，**指标计算必须始终在原始分布的验证集上进行**。用上采样后的数据训练的模型，在同样上采样后的测试集上评估是毫无意义的——你无法向业务方汇报"在 1:1 平衡数据集上，F1=0.95"。

## 4. 多分类场景：宏均分、微均分与加权均分

### 4.1 多分类的本质：K 个二分类问题的叠加

多分类问题（假设 K 个类别）可以分解为 K 个"类别 i vs 非类别 i"的二分类问题：

```
真实标签:  [0, 1, 2, 2, 1, 0, 2, 0, 1, 2]
预测标签:  [0, 1, 1, 2, 1, 0, 2, 1, 1, 2]

混淆矩阵（3 分类）：
              预测
            0    1    2
真实  0   [3    1    0]   → 类别 0 共 4 个样本
      1   [0    3    0]   → 类别 1 共 3 个样本
      2   [0    1    2]   → 类别 2 共 3 个样本
```

从这 K×2 的矩阵中，对每个类别 i 可以计算：

```
类别 0 的二分类视角：
  TP_0 = 3（类别 0 预测为 0）
  FP_0 = 1（类别 1 误报为 0）
  FN_0 = 1（类别 0 漏检为 1）
  TN_0 = 5（类别 1,2 不被误报为 0）
```

### 4.2 OvR（One-vs-Rest）策略：多分类指标的计算框架

多分类场景下的宏/微/加权均分，本质上都是 **OvR（One-vs-Rest）策略** 的不同聚合方式。OvR 把 K 分类问题分解为 K 个二分类问题，然后以不同方式合并。

### 4.3 微均分（Micro-Averaging）：全局聚合

**定义**：把所有类别的 TP/FP/FN/TN 在全局上加起来，得到一个聚合的混淆矩阵，再算一次指标。

$$
\text{Micro-P} = \frac{\sum_{i=1}^{K} TP_i}{\sum_{i=1}^{K} TP_i + \sum_{i=1}^{K} FP_i} = \frac{\sum TP}{\text{全部预测为正的总数}}
$$

$$
\text{Micro-R} = \frac{\sum_{i=1}^{K} TP_i}{\sum_{i=1}^{K} TP_i + \sum_{i=1}^{K} FN_i} = \frac{\sum TP}{\text{全部实际为正的总数}}
$$

**重要性质**：在多分类中，Micro-P + Micro-R = Micro-Accuracy（因为所有预测正确的 TP 之和等于所有预测正确的样本之和）。

**特点**：
- 等同于多分类 Accuracy
- **被大类严重主导**：1000 个样本中类别 A 占 900 个，类别 A 的准确率直接决定了 Micro 指标
- 当你只需要一个数字来粗略评估模型，且各类别相对均衡时，Micro-F1 ≈ Accuracy 是合理的

### 4.4 宏均分（Macro-Averaging）：类别公平

**定义**：先对每个类单独计算 Precision/Recall/F1，再对所有类取算术平均。

$$
\text{Macro-P} = \frac{1}{K} \sum_{i=1}^{K} P_i
$$

$$
\text{Macro-R} = \frac{1}{K} \sum_{i=1}^{K} R_i
$$

$$
\text{Macro-F1} = \frac{1}{K} \sum_{i=1}^{K} F1_i
$$

**特点**：
- **每个类无论大小，权重相同**
- 某个只有 10 个样本的类，如果 F1=0，宏 F1 也会下降 1/K（约 7% 在 14 分类问题中）
- **对小类公平，但对业务方不友好**：当大小类差异巨大时，宏 F1 的数值可能很低

**Macro-F1 的业务含义**：模型在每个类别上的平均表现，每个类同等重要。这是医疗诊断、工业缺陷检测等场景的首选指标。

### 4.5 加权均分（Weighted-Averaging）：样本量加权

$$
\text{Weighted-P} = \frac{\sum_{i=1}^{K} n_i \cdot P_i}{\sum_{i=1}^{K} n_i}
$$

$$
\text{Weighted-R} = \frac{\sum_{i=1}^{K} n_i \cdot R_i}{\sum_{i=1}^{K} n_i}
$$

$$
\text{Weighted-F1} = \frac{\sum_{i=1}^{K} n_i \cdot F1_i}{\sum_{i=1}^{K} n_i}
$$

### 4.6 三种均分方式的系统性对比

**完整数值推导示例**：四分类，样本分布极度不均衡

| 指标 | 类 0 (5000 样本) | 类 1 (500 样本) | 类 2 (50 样本) | 类 3 (5 样本) |
|---|---|---|---|---|
| Precision | 0.960 | 0.714 | 0.400 | 0.000 |
| Recall | 0.950 | 0.600 | 0.200 | 0.000 |
| F1 | 0.955 | 0.652 | 0.267 | 0.000 |
| 样本占比 | 90.1% | 9.0% | 0.9% | 0.09% |

**计算三种均分 F1：**

**Micro-F1：**
```
全局 TP = 4750 + 300 + 10 + 0 = 5060
全局 FP = 200 + 120 + 15 + 5 = 340
全局 FN = 250 + 200 + 40 + 5 = 495
Micro-P = 5060 / (5060 + 340) = 93.7%
Micro-R = 5060 / (5060 + 495) = 91.1%
Micro-F1 = 2 × 0.937 × 0.911 / (0.937 + 0.911) = **92.4%**
```

**Macro-F1：**
```
Macro-F1 = (0.955 + 0.652 + 0.267 + 0.000) / 4 = **46.9%**
```

**Weighted-F1：**
```
Weighted-F1 = (5000×0.955 + 500×0.652 + 50×0.267 + 5×0.000) / 5555
            = (4775 + 326 + 13.35 + 0) / 5555
            = 5114.35 / 5555 = **92.1%**
```

**三种均分 F1 对比总结：**

| 均分方式 | 最终结果 | 描述 | 谁占主导 | 业务含义 |
|---|---|---|---|---|
| Micro-F1 | **92.4%** | 整体分对多少 | 大类（类 0 占 90%） | 粗粒度业务指标 |
| Macro-F1 | **46.9%** | 每类平均表现 | **小类被平等对待** | 算法工程师的镜子 |
| Weighted-F1 | **92.1%** | 按样本量加权的平均 | 大类主导但考虑小类 | 业务汇报的首选 |

**关键洞察：Micro-F1 (92.4%) 和 Weighted-F1 (92.1%) 看起来都很好，但 Macro-F1 只有 46.9%**——这个差距揭示了模型在类 2 和类 3 上的严重问题。**永远不要只看一个数字就下结论。**

### 4.7 多分类的 OvO（One-vs-One）策略

与 OvR 不同，OvO 为每对类别训练一个二分类器（C(K,2) 个），然后用投票机制决定最终类别。

**OvO 的优势**：每个子分类器只用到两个类的数据，减少了数据不均衡的影响。

**OvO 的劣势**：训练成本为 O(K²)，当 K 很大时计算代价高。通常只用于 SVM 等难以处理多分类 Loss 的模型。

**在指标层面**：OvR 和 OvO 产生的最终预测是一样的（对于完全确定性的分类器），指标计算结果相同。区别在于训练过程，而非评估过程。

## 5. 指标与研发链路的深度映射

这一节将评价指标的选择和监控映射到你的实际研发流程中，让指标不再是"训练完看一下"的附属品，而是贯穿整个链路的决策依据。

### 5.1 Dataflow（数据准备）阶段

**目标**：在数据层面识别潜在问题，为后续所有阶段奠定基础

Dataflow 是整个链路的第一个漏斗。在这个阶段，你的每一个决策——如何清洗数据、如何处理缺失值、如何定义标签——都会直接影响后续所有指标的数值。很多指标问题，追根溯源都是 Dataflow 阶段埋下的。

**（1）类别分布的完整诊断**

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from collections import Counter

def diagnose_imbalance(df, label_col):
    """
    Dataflow 阶段的不均衡诊断函数。
    在真正开始训练之前，这一步是所有后续指标决策的基础。
    """
    label_counts = df[label_col].value_counts().sort_index()

    # 1. 基本统计
    n_classes = len(label_counts)
    total = len(df)
    max_ratio = label_counts.max() / label_counts.min()
    cv = label_counts.std() / label_counts.mean()  # 变异系数

    # 2. 不均衡比率分级
    if max_ratio < 3:
        imbalance_level = "均衡"
        recommended_metrics = ["Accuracy", "Micro-F1", "ROC-AUC"]
    elif max_ratio < 20:
        imbalance_level = "轻度不均衡"
        recommended_metrics = ["F1", "ROC-AUC", "Balanced Accuracy"]
    elif max_ratio < 100:
        imbalance_level = "中度不均衡"
        recommended_metrics = ["Weighted-F1", "Macro-F1", "ROC-AUC", "PR-AUC"]
    else:
        imbalance_level = "重度不均衡"
        recommended_metrics = ["PR-AUC", "Macro-F1", "Per-class Recall", "G-Mean", "MCC"]

    # 3. 每个类的样本量预警
    min_samples = label_counts.min()
    if min_samples < 50:
        print(f"⚠️ 警告：类别 {label_counts.idxmin()} 只有 {min_samples} 个样本")
        print(f"   宏均分时该类 F1=0 会导致 Macro-F1 下降 {1/n_classes:.2%}")

    # 4. 可视化
    fig, axes = plt.subplots(1, 2, figsize=(14, 5))

    # 柱状图：各类别样本数量
    axes[0].bar(range(n_classes), label_counts.values)
    axes[0].set_xlabel("类别")
    axes[0].set_ylabel("样本数量")
    axes[0].set_title(f"类别分布（不均衡比率: {max_ratio:.1f}:1）")
    axes[0].set_xticks(range(n_classes))

    # 对数柱状图：更清晰地看到小类
    axes[1].bar(range(n_classes), label_counts.values)
    axes[1].set_yscale('log')
    axes[1].set_xlabel("类别")
    axes[1].set_ylabel("样本数量（对数尺度）")
    axes[1].set_title("类别分布（对数尺度，突出小类）")
    axes[1].set_xticks(range(n_classes))

    plt.tight_layout()
    plt.savefig("class_distribution.png", dpi=150)
    plt.close()

    print(f"\n=== Dataflow 诊断报告 ===")
    print(f"总样本数: {total}")
    print(f"类别数: {n_classes}")
    print(f"不均衡比率: {max_ratio:.1f}:1")
    print(f"不均衡级别: {imbalance_level}")
    print(f"变异系数 (CV): {cv:.3f}")
    print(f"推荐监控指标: {', '.join(recommended_metrics)}")
    print(f"\n各类别样本数:")
    for cls, cnt in label_counts.items():
        pct = cnt / total * 100
        print(f"  类别 {cls}: {cnt:>6} ({pct:>5.2f}%)")

    return {
        "imbalance_level": imbalance_level,
        "max_ratio": max_ratio,
        "recommended_metrics": recommended_metrics,
        "min_samples": min_samples,
        "label_counts": label_counts
    }

# 使用示例
df = pd.read_csv("your_dataset.csv")
report = diagnose_imbalance(df, label_col="label")
```

**（2）Dataflow 阶段决定后续用哪些指标**

基于上面的诊断结果，你需要做出三个关键决策：

| 诊断结果 | 训练阶段监控策略 | 量化阶段关注重点 | 部署阈值策略 |
|---|---|---|---|
| 均衡（< 3:1） | Accuracy + Micro-F1 | 对比 FP32 vs INT8 Accuracy | 直接用 0.5 或 F1 最优阈值 |
| 轻度不均衡（3:1~20:1） | F1 + ROC-AUC + Weighted-F1 | 各类别 F1 是否有退化 | 按业务成本定阈值 |
| 中度不均衡（20:1~100:1） | Macro-F1 + PR-AUC + Per-class Recall | Per-class F1 逐类对比 | 优先 Recall，按 FPR 设阈值 |
| 重度不均衡（> 100:1） | PR-AUC + G-Mean + MCC + Per-class Recall | 极度关注少数类 Recall | 高召回策略，成本敏感阈值 |

**（3）标签质量检查对指标的影响**

在 Dataflow 阶段还需要检查：

```python
# 检查标注一致性问题
from sklearn.metrics import cohen_kappa_score

# 假设你有两份独立标注
y_labeler1 = df['label_v1']
y_labeler2 = df['label_v2']
kappa = cohen_kappa_score(y_labeler1, y_labeler2)

print(f"标注一致性 Kappa = {kappa:.3f}")
if kappa < 0.6:
    print("⚠️ 标注一致性不足，模型的 F1 上限被标注质量限制")
```

**标注不一致对指标的连锁影响**：如果标注者之间的 Kappa 只有 0.4，模型能达到的最好 F1 也不会超过 0.4（由标注上限决定）。这种情况下，指标低的原因不在模型，而在数据。

### 5.2 PyTorch（模型训练）阶段

**目标**：通过指标监控指导训练策略调整，让指标成为"训练过程的导航仪"

**（1）Loss 函数与指标的隐式对应关系**

Loss 函数的选择直接决定了模型在优化什么指标，理解这个对应关系才能知道"为什么 Loss 降了但业务指标没改善"：

| Loss 函数 | 隐式优化目标 | 显式监控指标 | 适用场景 |
|---|---|---|---|
| `nn.CrossEntropyLoss()` | 交叉熵 = Micro-Accuracy（近似） | Micro-F1 / Accuracy | 均衡多分类 |
| `nn.CrossEntropyLoss(weight=...)` | 加权交叉熵 = Weighted-Accuracy | Weighted-F1 + Macro-F1 | 不均衡多分类 |
| `nn.BCEWithLogitsLoss()` | 二分类交叉熵 | F1 + ROC-AUC + PR-AUC | 二分类 |
| `nn.BCEWithLogitsLoss(pos_weight=...)` | 代价敏感二分类 | Recall + F1 + Fβ | 不均衡二分类 |
| Focal Loss（`gamma > 0`） | 难分样本优先 = Macro-Recall 偏向 | Per-class Recall + Macro-F1 | 极度不均衡 |
| `nn.MSELoss()` | MSE = Brier Score（概率任务） | Brier Score + Calibration | 概率输出 |

**Focal Loss 的特殊价值**：当不均衡比率超过 100:1 时，标准 CE Loss 会被多数类的"easy negatives"主导——模型简单地学习"把所有样本预测为负类"就能使 Loss 很低。Focal Loss 通过对 easy examples 施加更低权重来解决这个问题：

$$
\text{FL}(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t)
$$

- `gamma = 0`：退化为标准 CrossEntropyLoss
- `gamma = 2`：实验中常用的设置，easy examples 的权重被平方衰减
- 效果：少数类的难分样本被赋予更高权重，Recall 显著提升

**（2）完整的训练监控框架**

```python
import torch
import torch.nn as nn
from torchmetrics import (
    Accuracy, F1Score, Precision, Recall,
    ROCAUC, AveragePrecision,
    CohenKappa, ConfusionMatrix
)
from torchmetrics.classification import (
    MulticlassF1Score, MulticlassPrecisionAtRecall,
    BinaryF1Score, BinaryROCABC, BinaryAveragePrecision
)
import numpy as np

class MetricsTracker:
    """
    训练过程的全方位指标追踪器。
    每个 epoch 结束后调用 compute_and_log()，输出完整诊断报告。
    """
    def __init__(self, num_classes, class_names=None, task='multiclass'):
        self.num_classes = num_classes
        self.class_names = class_names or [f"class_{i}" for i in range(num_classes)]
        self.task = task

        # === 微均分指标 ===
        self.metric_acc = Accuracy(task=task, num_classes=num_classes, average='micro')
        self.metric_f1_micro = F1Score(task=task, num_classes=num_classes, average='micro')
        self.metric_precision_micro = Precision(task=task, num_classes=num_classes, average='micro')
        self.metric_recall_micro = Recall(task=task, num_classes=num_classes, average='micro')

        # === 宏均分指标 ===
        self.metric_f1_macro = F1Score(task=task, num_classes=num_classes, average='macro')
        self.metric_precision_macro = Precision(task=task, num_classes=num_classes, average='macro')
        self.metric_recall_macro = Recall(task=task, num_classes=num_classes, average='macro')

        # === 加权均分指标 ===
        self.metric_f1_weighted = F1Score(task=task, num_classes=num_classes, average='weighted')

        # === Per-class 指标 ===
        self.metric_f1_per_class = F1Score(task=task, num_classes=num_classes, average=None)
        self.metric_recall_per_class = Recall(task=task, num_classes=num_classes, average=None)

        # === AUC 指标 ===
        self.metric_rocauc = ROCAUC(task=task, num_classes=num_classes)
        self.metric_auprc = AveragePrecision(task=task, num_classes=num_classes)

        # === 其他指标 ===
        self.metric_kappa = CohenKappa(task=task, num_classes=num_classes)

        self.all_metrics = [
            self.metric_acc, self.metric_f1_micro, self.metric_f1_macro,
            self.metric_f1_weighted, self.metric_f1_per_class,
            self.metric_recall_per_class, self.metric_rocauc,
            self.metric_auprc, self.metric_kappa
        ]

    def update(self, preds: torch.Tensor, targets: torch.Tensor):
        """每个 batch 后调用"""
        for m in self.all_metrics:
            m.update(preds, targets)

    def compute_and_log(self, epoch: int, phase: str = "train"):
        """每个 epoch 结束后调用，输出完整诊断报告"""
        results = {}

        print(f"\n{'='*60}")
        print(f"Epoch {epoch} [{phase.upper()}] 完整指标报告")
        print(f"{'='*60}")

        # 微均分
        acc = self.metric_acc.compute().item()
        f1_micro = self.metric_f1_micro.compute().item()
        print(f"  [微均分] Accuracy: {acc:.4f}  |  Micro-F1: {f1_micro:.4f}")

        # 宏均分
        f1_macro = self.metric_f1_macro.compute().item()
        prec_macro = self.metric_precision_macro.compute().item()
        rec_macro = self.metric_recall_macro.compute().item()
        print(f"  [宏均分] Macro-F1: {f1_macro:.4f}  |  Macro-Precision: {prec_macro:.4f}  |  Macro-Recall: {rec_macro:.4f}")

        # 加权均分
        f1_weighted = self.metric_f1_weighted.compute().item()
        print(f"  [加权均分] Weighted-F1: {f1_weighted:.4f}")

        # 宏微差距——这是最关键的诊断信号
        gap = f1_micro - f1_macro
        print(f"  [诊断信号] Micro-Macro Gap: {gap:.4f}", end="")
        if gap > 0.15:
            print(" ⚠️  差距过大，小类存在严重问题！")
        elif gap > 0.05:
            print(" ⚡  差距中等，建议检查 Per-class Recall")
        else:
            print(" ✓  差距正常")

        # Per-class Recall（最细粒度的诊断）
        recall_per_class = self.metric_recall_per_class.compute()
        print(f"\n  [Per-class Recall] 每个类的召回率：")
        worst_class_idx = -1
        worst_recall = 1.0
        for i, name in enumerate(self.class_names):
            r = recall_per_class[i].item()
            if r < worst_recall:
                worst_recall = r
                worst_class_idx = i
            status = "✓" if r > 0.8 else ("⚡" if r > 0.5 else "❌")
            print(f"    {status} {name:<20} Recall = {r:.4f}")
        print(f"  → 最短板类: {self.class_names[worst_class_idx]} (Recall={worst_recall:.4f})")

        # AUC
        try:
            rocauc = self.metric_rocauc.compute().item()
            print(f"  [AUC] ROC-AUC: {rocauc:.4f}", end="")
            if rocauc > 0.95:
                print(" ✓ 排序能力优秀")
            elif rocauc > 0.85:
                print(" ⚡ 排序能力良好")
            else:
                print(" ❌ 排序能力不足，建议检查数据质量")
        except:
            pass

        # Kappa
        kappa = self.metric_kappa.compute().item()
        print(f"  [一致性] Cohen's Kappa: {kappa:.4f}")

        # 存储结果
        results = {
            'accuracy': acc,
            'f1_micro': f1_micro,
            'f1_macro': f1_macro,
            'f1_weighted': f1_weighted,
            'gap': gap,
            'worst_class': self.class_names[worst_class_idx],
            'worst_recall': worst_recall
        }

        # 重置所有指标（下一个 epoch 重新开始）
        for m in self.all_metrics:
            m.reset()

        return results
```

**（3）训练监控中的关键决策信号**

训练过程中最常见的四个信号，每个都对应特定的调整策略：

| 观察到的现象 | 背后含义 | 建议行动 |
|---|---|---|
| **Micro-F1 涨，Macro-F1 不涨** | 模型在大类上变好，但小类没改善 | 加小类数据、用 Focal Loss、检查小类标注质量 |
| **Macro-F1 远低于 Micro-F1** | 小类被严重忽略 | 提高小类权重、检查数据增强是否覆盖小类 |
| **Loss 下降但 Macro-F1 震荡** | 梯度被大类主导，小类学习不稳定 | 使用类别平衡的采样器（WeightedRandomSampler） |
| **Per-class Recall 严重分化** | 部分类别是模型完全无法区分的 | 检查这些类是否本身就很相似，考虑合并或增加特征 |
| **F1 收敛但 Per-class F1 波动大** | 各类学习速度不一致 | 使用 Per-class 学习率调整（大类低学习率，小类高学习率） |

### 5.3 量化（Quantization）阶段

**目标**：确保量化后的模型在核心指标上没有严重退化，尤其是小类的 Per-class 指标

**量化不是在 FP32 Accuracy 基础上"还行"就可以的。** 一个量化模型可能在整体 Accuracy 上只下降了 0.3%，但在某个少数类上的 Recall 从 0.72 跌到了 0.31——这个 41% 的 Recall 下降，在欺诈检测场景中可能意味着每天多损失数十万元。

**（1）量化对比矩阵：完整的指标层面诊断**

```python
import torch
import numpy as np
from sklearn.metrics import (
    classification_report, confusion_matrix,
    f1_score, accuracy_score, roc_auc_score,
    precision_recall_curve, auc

def compare_model_metrics(model_fp32, model_quantized, dataloader, num_classes):
    """
    量化前后完整指标对比。
    核心原则：不只看 Accuracy，要按类别逐类对比。
    """
    model_fp32.eval()
    model_quantized.eval()

    all_preds_fp32, all_preds_int8 = [], []
    all_labels, all_probs_fp32, all_probs_int8 = [], [], []

    with torch.no_grad():
        for batch_x, batch_y in dataloader:
            # FP32 模型
            out_fp32 = model_fp32(batch_x)
            prob_fp32 = torch.softmax(out_fp32, dim=1)
            pred_fp32 = out_fp32.argmax(dim=1)

            # INT8 量化模型
            out_int8 = model_quantized(batch_x)
            prob_int8 = torch.softmax(out_int8, dim=1)
            pred_int8 = out_int8.argmax(dim=1)

            all_preds_fp32.append(pred_fp32.cpu().numpy())
            all_preds_int8.append(pred_int8.cpu().numpy())
            all_labels.append(batch_y.cpu().numpy())
            all_probs_fp32.append(prob_fp32.cpu().numpy())
            all_probs_int8.append(prob_int8.cpu().numpy())

    y_true = np.concatenate(all_labels)
    y_pred_fp32 = np.concatenate(all_preds_fp32)
    y_pred_int8 = np.concatenate(all_preds_int8)
    probs_fp32 = np.concatenate(all_probs_fp32)
    probs_int8 = np.concatenate(all_probs_int8)

    print("=" * 70)
    print("量化对比报告：FP32 vs INT8")
    print("=" * 70)

    # 1. 全局指标对比
    print("\n【全局指标对比】")
    print(f"{'指标':<20} {'FP32':>10} {'INT8':>10} {'变化':>10} {'状态':>8}")
    print("-" * 60)

    metrics_compare = [
        ("Accuracy", accuracy_score(y_true, y_pred_fp32), accuracy_score(y_true, y_pred_int8)),
        ("Micro-F1", f1_score(y_true, y_pred_fp32, average='micro', zero_division=0),
                      f1_score(y_true, y_pred_int8, average='micro', zero_division=0)),
        ("Macro-F1", f1_score(y_true, y_pred_fp32, average='macro', zero_division=0),
                      f1_score(y_true, y_pred_int8, average='macro', zero_division=0)),
        ("Weighted-F1", f1_score(y_true, y_pred_fp32, average='weighted', zero_division=0),
                       f1_score(y_true, y_pred_int8, average='weighted', zero_division=0)),
    ]

    for name, val_fp, val_int in metrics_compare:

        pct_delta = (delta / val_fp * 100) if val_fp > 0 else 0
        status = "✓" if abs(delta) < 0.01 else ("⚡" if abs(delta) < 0.03 else "❌")

    # 2. Per-class F1 逐类对比——这是量化诊断的核心
    print("\n【Per-class F1 逐类对比（量化诊断关键）】")
    f1_fp32 = f1_score(y_true, y_pred_fp32, average=None, zero_division=0)
    f1_int8 = f1_score(y_true, y_pred_int8, average=None, zero_division=0)

    worst_drop_class = -1
    worst_drop = 0.0

    for i in range(num_classes):

        if delta < worst_drop:

              f"变化={delta:+.4f} {status}")

              f"变化={auc_int8-auc_fp32:+.4f}")
    except ValueError:

    # 4. 决策：是否接受量化
    print("\n【量化接受判断】")
    macro_f1_drop = metrics_compare[2][2] - metrics_compare[2][1]
```

**（3）SmoothQuant 与 AWQ：更精细的量化策略**

对于大语言模型（LLM）等场景，标准 INT8 量化可能对小类指标影响极大，此时需要更精细的量化策略：

- **SmoothQuant**：对不同通道的权重分配不同的"量化难度"，减少激活值量化误差
- **AWQ（Activation-Aware Weight Quantization）**：根据激活值分布来决定权重缩放，优先保护对指标影响大的权重
- **GPTQ**：逐层量化，利用 Hessian 信息减少量化误差

这些方法的共同特点是：**它们都是为了让量化后的 Per-class Recall 和 Macro-F1 尽量少退化**，而不是只看整体 Accuracy。

### 5.4 vLLM（推理优化）阶段

**目标**：通过阈值调优和线上指标监控，确保推理服务在实际业务中达到目标

**（1）阈值调优：指标到业务的最后一公里**

训练模型时默认用 0.5 作为阈值，但业务场景不同，最优阈值也不同。阈值的选择需要结合业务成本：

```python
import numpy as np
from sklearn.metrics import precision_recall_curve, roc_curve

def find_cost_sensitive_threshold(
    y_true,
    y_scores,
    cost_fn=5.0,    # FN（漏检）代价
    cost_fp=1.0,    # FP（误报）代价
    return_details=False
):
    """
    基于业务代价找到最优决策阈值。

    原理：在每个阈值 t 下，计算总业务代价 = cost_fn * FN(t) + cost_fp * FP(t)
    选择使总代价最小的阈值
    """
    precisions, recalls, thresholds = precision_recall_curve(y_true, y_scores)

    # 添加首尾边界
    thresholds = np.concatenate([[0.0], thresholds, [1.0]])
    precisions = np.concatenate([[1.0], precisions, [0.0]])
    recalls = np.concatenate([[1.0], recalls, [0.0]])

    n_pos = np.sum(y_true == 1)
    n_neg = np.sum(y_true == 0)

    total_costs = []
    for t in thresholds:
        # 找到当前阈值下的 FP 和 FN
        # FP = 负类中被预测为正的数量 = (1 - Specificity) * n_neg
        # FN = 正类中被预测为负的数量 = (1 - Recall) * n_pos

        # 简化计算：直接用 precision-recall 曲线上的值
        fp_count = (1 - (precisions * n_pos) / (precisions * n_pos + fp_approx(y_scores, y_true, t)))
        # 更直接的方法：
        pred_pos = (y_scores >= t).astype(int)
        fp = np.sum((pred_pos == 1) & (y_true == 0))
        fn = np.sum((pred_pos == 0) & (y_true == 1))

        total_cost = cost_fn * fn + cost_fp * fp
        total_costs.append(total_cost)

    optimal_idx = np.argmin(total_costs)
    optimal_threshold = thresholds[optimal_idx]

    if return_details:
        return optimal_threshold, optimal_idx, thresholds, total_costs
    return optimal_threshold


def fp_approx(y_scores, y_true, threshold):
    """辅助函数"""
    pred = (y_scores >= threshold).astype(int)
    fp = np.sum((pred == 1) & (y_true == 0))
    fn = np.sum((pred == 0) & (y_true == 1))
    return fp


def find_optimal_threshold_with_roc(y_true, y_scores, target_fpr=0.05):
    """
    另一种常用策略：在控制 FPR 不超过目标值的前提下，最大化 Recall。

    典型场景：欺诈检测中，你希望 FPR（正常交易被误判）不超过 5%
    在这个约束下找到最高 Recall 的阈值
    """
    fpr, tpr, thresholds = roc_curve(y_true, y_scores)

    # 找到 FPR <= target_fpr 的最大 Recall
    valid_mask = fpr <= target_fpr
    if valid_mask.any():
        best_idx = np.argmax(tpr[valid_mask])
        optimal_threshold = thresholds[valid_mask][best_idx]
        best_tpr = tpr[valid_mask][best_idx]
        best_fpr = fpr[valid_mask][best_idx]
    else:
        # 如果所有阈值都不满足，找最接近的
        best_idx = np.argmin(np.abs(fpr - target_fpr))
        optimal_threshold = thresholds[best_idx]
        best_tpr = tpr[best_idx]
        best_fpr = fpr[best_idx]

    return optimal_threshold, best_tpr, best_fpr
```

## 6. 阈值与置信度：指标之外的决策层

### 6.1 阈值选择的三种范式

**范式一：F1 最优阈值**

找到使 F1 最大的阈值。适合"Precision 和 Recall 同样重要"的场景：

$$
t^* = \arg\max_t \; F1(t) = \arg\max_t \; \frac{2 \cdot P(t) \cdot R(t)}{P(t) + R(t)}
$$

```python
def find_f1_optimal_threshold(y_true, y_scores):
    precisions, recalls, thresholds = precision_recall_curve(y_true, y_scores)
    f1_scores = 2 * precisions * recalls / (precisions + recalls + 1e-10)
    best_idx = np.argmax(f1_scores)
    return thresholds[min(best_idx, len(thresholds)-1)], f1_scores[best_idx]
```

**范式二：成本敏感阈值**

根据业务代价 $C_{FN}$ 和 $C_{FP}$ 设定阈值：

$$
t^* = \arg\max_t \; (C_{FN} \cdot TP(t) - C_{FP} \cdot FP(t))
$$

等价于找一个使得以下不等式成立的阈值：

$$
P(\text{正类}|x) > \frac{C_{FP}}{C_{FN} + C_{FP}}
$$

**范式三：操作约束阈值**

先设定业务约束（如 FPR ≤ 5%），再在这个约束下最大化 Recall：

```python
# 欺诈检测场景：希望误报率不超过 5%，同时尽可能提高召回率
optimal_t, best_tpr, best_fpr = find_optimal_threshold_with_roc(
    y_true, y_scores, target_fpr=0.05
)
print(f"在 FPR ≤ 5% 下，最优阈值 = {optimal_t:.3f}, Recall = {best_tpr:.4f}")
```

### 6.2 置信度校准：概率的可靠性

模型输出的原始概率往往不是可靠的置信度度量。**校准（Calibration）** 研究的是"预测概率与真实频率的一致性"。

** Reliability Diagram（可靠性图）**：把预测概率分成 10 个区间（0-0.1, 0.1-0.2, ..., 0.9-1.0），在每个区间内计算实际正类比例，绘制折线图。如果曲线在对角线上，说明校准良好。

**Brier Score**：

$$
\text{Brier Score} = \frac{1}{N} \sum_{i=1}^{N} (p_i - y_i)^2
$$

Brier Score 衡量概率预测的质量，取值范围 \[0, 0.25\]（对于二分类），**越小越好**。它同时衡量了准确率（Resolution）和不确定性（Uncertainty），是比 AUC 更细粒度的概率质量指标。

**Temperature Scaling（温度缩放）**：校准最简单有效的方法

```python
import torch
import torch.nn as nn
from sklearn.metrics import brier_score_loss

class TemperatureScaler(nn.Module):
    """Platt Scaling 的变体：用一个温度参数 T 缩放 logits"""
    def __init__(self):
        super().__init__()
        self.temperature = nn.Parameter(torch.ones(1))

    def forward(self, logits):
        return logits / self.temperature

def calibrate_temperature(model, val_logits, val_labels):
    """
    用验证集学习最优温度 T，然后用 T 对测试集 logits 进行校准。
    原理：最小化 NLL（负对数似然）
    """
    scaler = TemperatureScaler()
    optimizer = torch.optim.LBFGS([scaler.temperature], lr=0.01, max_iter=50)

    logits_tensor = torch.tensor(val_logits, dtype=torch.float32)
    labels_tensor = torch.tensor(val_labels, dtype=torch.float32)

    def eval():
        optimizer.zero_grad()
        loss = nn.CrossEntropyLoss()(scaler(logits_tensor), labels_tensor)
        loss.backward()
        return loss

    optimizer.step(eval)

    T = scaler.temperature.item()
    print(f"最优温度 T = {T:.4f}")

    # 校准后的概率
    calibrated_probs = torch.softmax(logits_tensor / T, dim=1)[:, 1].numpy()
    brier = brier_score_loss(val_labels, calibrated_probs)
    print(f"校准后 Brier Score = {brier:.4f}")

    return T, calibrated_probs
```

### 6.3 量化对校准的影响

量化会显著破坏模型的校准性。一个 INT8 模型的预测概率可能比 FP32 模型离散得多，某些区间的概率值完全无法达到。这就是为什么在量化后：

1. **不要直接使用原始概率阈值**（如 0.5）
2. 在校准集上重新学习最优阈值
3. 优先使用 Temperature Scaling 恢复校准

## 7. 实用场景分析与决策指南

### 7.1 场景一：欺诈检测系统

**场景描述**：信用卡交易欺诈检测，0.5% 欺诈率（1:200 不均衡）

**关键指标选择**：

| 研发阶段 | 核心指标 | 理由 |
|---|---|---|
| Dataflow | 类别分布、欺诈率时序变化 | 欺诈模式随时间漂移 |
| PyTorch | Recall@FPR=1% + PR-AUC + Macro-F1 | 业务关心高召回下的误报控制 |
| 量化 | Per-class Recall + PR-AUC 对比 | 量化后 Recall 退化可能是灾难性的 |
| vLLM | Recall@5%FPR + 业务代价最优阈值 | 阈值根据实际欺诈损失调整 |

**业务阈值策略**：欺诈检测的漏检代价（被盗刷金额）通常是误报代价（人工复核成本）的 50-200 倍，所以阈值应该偏向 Recall。典型配置：控制 FPR ≤ 2%，然后找最大 Recall。

### 7.2 场景二：多标签医学影像诊断

**场景描述**：一张 X 光片可能同时包含肺炎、肺结核、肿瘤等多标签，10 个疾病类别，其中某些罕见病占比 < 0.1%

**关键指标选择**：

- **不能用 Accuracy**：每个标签的二分类 Accuracy 都会被"无病"主导
- **必须用 Per-label Recall**：某种罕见病 Recall = 0.1 意味着 90% 的病人被漏诊
- **Macro-F1 per label**：每个标签同等重要
- **PR-AUC**：适合极端不均衡的 per-label 评估

**训练策略与指标的联动**：

```python
# 多标签分类的指标注册
from torchmetrics.classification import MultilabelF1Score, MultilabelAveragePrecision

num_labels = 10
threshold = 0.5

# 每标签的 F1（宏均分 = 每个标签权重相同）
f1_macro = MultilabelF1Score(num_labels=num_labels, average='macro', threshold=threshold)

# 每标签的 F1（微均分 = 所有标签聚合）
f1_micro = MultilabelF1Score(num_labels=num_labels, average='micro', threshold=threshold)

# 每标签的平均精度（类似 PR-AUC）
auprc = MultilabelAveragePrecision(num_labels=num_labels)
```

### 7.3 场景三：推荐系统中的点击率预估

**场景描述**：二分类 CTR 预估，数据通常 5%-10% 点击率

**关键指标选择**：

- **LogLoss / Brier Score**：概率预测质量，比 Accuracy 更敏感
- **AUC**：排序质量的核心指标（推荐系统实际优化的是相对排序而非绝对标签）
- **Calibration**：如果业务使用概率阈值（如"只推送概率 > 0.15 的内容"），校准后的概率至关重要
- **不选 F1**：推荐系统的业务目标是"最大化总点击数"，不是"平衡 Precision 和 Recall"

**推荐系统的特殊指标**：
- **NDCG@K**：推荐列表中前 K 个结果的相关性度量（Learning to Rank）
- **AUC 提升的意义**：AUC 从 0.75 提升到 0.77 意味着"随机选一对样本（点击 vs 未点击），77% 的概率模型把点击的排在前面"

### 7.4 场景四：工业质检（缺陷检测）

**场景描述**：流水线上产品缺陷检测，缺陷率 2%-5%，漏检一个次品流入市场代价极高

**关键指标选择**：

| 受众 | 核心指标 | 原因 |
|---|---|---|
| 算法工程师 | Recall + Macro-F1 | 每个缺陷类型都必须被检测 |
| 产线工人 | 漏检率（= 1 - Recall） | 关心"这个批次漏了多少个" |
| 质量部门 | Specificity（通过率） | 关心"正常产品被误判多少" |
| 管理层 | F1 + 每班次缺陷数 | 关心生产效率与质量的平衡 |

## 8. 常见误区与避坑指南

### 8.1 指标选择层面的误区

**误区一：只看 Accuracy 就做决策**

这是最常见、代价最大的误区。在不均衡数据中，Accuracy 是一个具有欺骗性的高数字。**任何汇报 Accuracy 的场合，都应该同时要求 Macro-F1 和 Per-class Recall。**

**误区二：混淆"指标"和"目标"**

很多团队在论文中声称"我们的模型 F1 达到了 0.92"，但实际上他们用 0.5 阈值在验证集上调了很久。这个 0.92 是在验证集上搜索最优阈值后的人为结果，在测试集上可能只有 0.75。

**正确做法**：始终在**留出的测试集**（非验证集）上评估最终指标，验证集只用于调阈值。

**误区三：用上采样后的数据评估模型性能**

如果你对少数类做了 SMOTE 过采样，然后在同一批数据上评估 F1，得到的 F1 是虚高的——因为你用生成的数据测试了模型在生成数据上的拟合能力，而不是真实泛化能力。

**正确做法**：过采样/数据增强**只在训练时**使用，验证集和测试集必须保持原始分布。

### 8.2 研发流程层面的误区

**误区四：量化阶段只看 Accuracy 下降**

INT8 量化后 Accuracy 下降 0.5% 可能看起来没问题，但如果这个下降完全集中在某个少数类（Recall 从 0.72 掉到 0.31），实际业务影响可能是灾难性的。

**正确做法**：量化前后必须做完整的 Per-class F1 对比，设定各类别 F1 退化的容忍阈值。

**误区五：Loss 下降就认为模型在变好**

在加权 CrossEntropyLoss 下，少数类的梯度被放大，Loss 可能在快速下降，但这可能只是模型学会了"把一切都预测为少数类"（导致 FN 减少，Loss 下降，但 Recall 实际上在恶化）。**Loss 下降而 Recall 下降的情况叫做" Accuracy Paradox"（准确率悖论）。**

**正确做法**：同时监控 Loss 和 Recall/F1，不要只看 Loss。

**误区六：直接使用 0.5 阈值部署**

0.5 只是人类习惯的默认值，没有任何业务意义。在欺诈检测中 0.5 可能导致 40% 的欺诈被漏检，在垃圾邮件过滤中可能导致 20% 的正常邮件被误删。

**正确做法**：在验证集上通过业务成本分析确定最优阈值，然后在测试集上确认这个阈值在未见数据上同样有效。

### 8.3 多分类场景的误区

**误区七：宏 F1 和微 F1 混用导致策略矛盾**

如果训练时用加权 Loss（隐式优化 Weighted-F1），但评估时只看 Macro-F1，可能会出现"Loss 在下降但 Macro-F1 不涨"的困惑——因为加权 Loss 对小类的关注程度可能仍然不够。**确认你的优化目标和评估指标是一致的。**

**误区八：用 Micro-F1 来衡量多分类问题中各类别的均衡性**

Micro-F1 ≈ Accuracy，永远反映大类的表现。如果你想评估"每个类别是否都被照顾到"，必须看 Macro-F1 和 Per-class Recall，而不能只看 Micro-F1。

```
你是算法工程师，正在训练一个分类模型
│
├─ 数据集类别分布是否均衡？
│   │
│   ├─ 【均衡】（各类样本量差异 < 3:1）
│   │   └─ 优先：Accuracy + Micro-F1 + ROC-AUC
│   │
│   └─ 【不均衡】（各类样本量差异 ≥ 3:1）
│       │
│       ├─ 不均衡程度？
│       │   │
│       │   ├─ 【轻度 3:1 ~ 20:1】
│       │   │   └─ F1 + ROC-AUC + Balanced Accuracy
│       │   │   + 阈值调优（业务成本分析）
│       │   │
│       │   ├─ 【中度 20:1 ~ 100:1】
│       │   │   └─ PR-AUC + F1 + G-Mean + MCC
│       │   │   + Per-class Recall 逐类诊断
│       │   │
│       │   └─ 【重度 > 100:1】
│       │       └─ PR-AUC + G-Mean + MCC + Per-class Recall
│       │       + Focal Loss / 加权 Loss / 采样策略
│       │
│       └─ 是否极度关注少数类召回率？
│           └─ 是 → 以 Recall 和 Per-class Recall 为核心
│
├─ 是二分类还是多分类？
│   │
│   ├─ 【二分类】
│   │   └─ 见上方不均衡决策树
│   │
│   └─ 【多分类】
│       │
│       ├─ 各类别同等重要？（医疗、工业检测、安全）
│       │   └─ 核心：Macro-F1 + Per-class Recall
│       │       （小类 F1=0 会显著拉低宏 F1）
│       │
│       ├─ 大类更重要？（通用分类、推荐系统）
│       │   └─ 核心：Weighted-F1 + Micro-F1
│       │       （汇报给业务方的常用指标）
│       │
│       └─ 想全面了解？（作为开发者做深度诊断）
│           └─ 核心：Macro + Micro + Weighted + Per-class 全套
│
└─ 当前处于研发链路的哪个阶段？
    │
    ├─ 【Dataflow】
    │   └─ 画分布图 → 算不均衡比率 → 确定监控指标集
    │       + 检查标注一致性（Kappa）
    │       + 决定采样/Loss 策略
    │
    ├─ 【PyTorch】
    │   └─ 按指标集注册 torchmetrics → 每 epoch 记录
    │       + Micro-Macro Gap 诊断（最关键信号）
    │       + Per-class Recall 逐类追踪
    │       + Loss + F1 联合监控
    │
    ├─ 【Quantization】
    │   └─ 对比 FP32 vs 量化后的同指标集 → Per-class 诊断
    │       + 量化前后的 Macro-F1 差值 < 容忍阈值
    │       + 量化后 Per-class Recall 退化 < 容忍阈值
    │       + 必要时启用 QAT
    │
    └─ 【vLLM】
        └─ 结合业务目标选阈值 → 线上监控 Per-class + AUC 漂移
            + 成本敏感阈值 vs 操作约束阈值
            + 置信度校准（Temperature Scaling）
            + 定期用新数据重新评估 Per-class Recall
```

| 指标 | 公式 | 范围 | 不均衡适用性 | 多分类支持 | 计算代价 |
|---|---|---|---|---|---|
| **Accuracy** | (TP+TN)/(TP+TN+FP+FN) | [0,1] | ❌ 误导性高 | Micro ✓ | 极低 |
| **Balanced Accuracy** | (Recall+Specificity)/2 | [0,1] | ✅ 消除分布影响 | OvR ✓ | 极低 |
| **Precision** | TP/(TP+FP) | [0,1] | ⚠️ 需配合 Recall | Micro ✓ | 极低 |
| **Recall (TPR)** | TP/(TP+FN) | [0,1] | ✅ 核心指标 | Micro ✓ | 极低 |
| **Specificity (TNR)** | TN/(TN+FP) | [0,1] | ✅ 配合 Recall | Micro ✓ | 极低 |
| **F1-Score** | 2·P·R/(P+R) | [0,1] | ✅ 相对可靠 | Micro/Macro/Weighted ✓ | 极低 |
| **Fβ-Score** | (1+β²)·P·R/(β²P+R) | [0,1] | ✅ 可调 β | Micro/Macro/Weighted ✓ | 极低 |
| **ROC-AUC** | ∫TPR dFPR | [0,1] | ✅ 首选 | ✅ OvR | 中 |
| **PR-AUC (AP)** | ∫P dR | [0,1] | ✅ 极端不均衡首选 | ⚠️ OvR | 中 |
| **G-Mean** | √(Recall × Specificity) | [0,1] | ✅ 极度不均衡 | ⚠️ | 低 |
| **MCC** | (TP·TN-FP·FN)/√(...) | [-1,1] | ✅ 最均衡 | ⚠️ | 低 |
| **Cohen's Kappa** | (p_o - p_e)/(1-p_e) | [-1,1] | ✅ 消除随机影响 | ⚠️ | 低 |
| **Brier Score** | (p-y)² 均值 | [0,0.25] | ✅ 概率质量 | ✅ | 低 |
| **LR+** | TPR/FPR | [0,+∞) | ✅ 诊断能力强 | ⚠️ | 低 |
| **DOR** | TP·TN/(FP·FN) | [0,+∞) | ✅ 综合诊断 | ⚠️ | 低 |

> **最终建议**：作为 AI 开发者，在研发链路中建立完整的指标体系比选对单一指标更重要。建议在 Dataflow 阶段确定指标集（基于不均衡诊断）→ PyTorch 训练中持续监控（Micro-Macro Gap 是核心诊断信号）→ 量化前后做对比验证（Per-class F1 是关键）→ vLLM 部署时设定业务阈值（成本敏感或操作约束）。这个流程走通之后，指标选择本身会变得自然而清晰。
>
> **最重要的三个数字**：
> 1. **Micro-Macro Gap**：Gap 越大 → 小类问题越严重
> 2. **Per-class Recall 最低值**：模型最短板在哪里
> 3. **量化前后 Per-class Recall 的最大退化**：量化是否打破了某个关键类别的召回能力
