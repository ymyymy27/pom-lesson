# 第 01 节：导航基础

## 本节目标

- 掌握 Navigator 的 push / pop 与传参
- 理解"页面即路由栈"的心智模型
- 学会返回结果（类似 Promise resolve）

## 一、页面栈模型

Flutter 的导航是**栈**：每 push 一页，压一层；pop 一页，弹一层。

```text
栈顶 → 任务详情页
       TaskListPage
       HomePage（BottomNav）
```

对应 Web：浏览器历史栈 + 前进后退；对应 React Router：`navigate()` / `navigate(-1)`。

## 二、push 与 pop

```dart
// 跳转
Navigator.of(context).push(
  MaterialPageRoute(
    builder: (_) => TaskDetailPage(taskId: task.id),
  ),
);

// 返回
Navigator.of(context).pop();
```

注意：`context` 要在 Navigator 之下（MaterialApp 内）。`Navigator.of(context)` 向上找最近的 Navigator。

## 三、传参与回传

```dart
// 打开编辑页，等待结果
final result = await Navigator.of(context).push<String>(
  MaterialPageRoute(builder: (_) => const EditTaskPage()),
);

if (result != null) {
  debugPrint('编辑结果：$result');
}

// 编辑页保存后返回数据
Navigator.of(context).pop('已保存');
```

泛型 `<String>` 声明返回类型，类似 `await` 一个返回 Promise 的函数。

## 四、命名路由（1.0 时代写法）

```dart
MaterialApp(
  routes: {
    '/': (_) => const HomePage(),
    '/tasks': (_) => const TaskListPage(),
    '/tasks/new': (_) => const NewTaskPage(),
  },
)

// 跳转
Navigator.of(context).pushNamed('/tasks/new');

// 带参数
Navigator.of(context).pushNamed('/tasks/detail', arguments: taskId);

// 读取参数
final taskId = ModalRoute.of(context)!.settings.arguments as String;
```

命名路由方便但**类型不安全**（arguments 是 dynamic），大型项目不推荐。后续 go_router 会替代它。

## 五、常用导航操作

```dart
// 替换当前页（登录后不希望返回登录页）
Navigator.of(context).pushReplacement(
  MaterialPageRoute(builder: (_) => const HomePage()),
);

// 清空栈后进入（登出）
Navigator.of(context).pushAndRemoveUntil(
  MaterialPageRoute(builder: (_) => const LoginPage()),
  (route) => false,          // 全部移除
);

// 返回指定结果并移除多页
Navigator.of(context).popUntil((route) => route.isFirst);
```

## 常见坑

- 在 `build` 里调用 `Navigator.pop` 会报错，要放到回调/事件里
- `pushReplacement` 后旧页面 dispose，不要再操作它的 State
- 深层嵌套 Navigator（底部导航内嵌）时 `Navigator.of(context)` 可能拿到内层，需要指定 `rootNavigator: true`

## 动手练习

1. 任务列表 → 详情页：传 `taskId`，详情页返回后刷新列表
2. 新建页保存后 `pop('已保存')`，列表页读取并提示
3. 登录成功用 `pushAndRemoveUntil` 清空返回栈
