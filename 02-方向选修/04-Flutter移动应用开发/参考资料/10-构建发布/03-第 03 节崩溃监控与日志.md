# 第 03 节：崩溃监控与日志

## 本节目标

- 接入 Sentry 崩溃监控
- 建立分级日志规范
- 制定线上问题响应流程

## 一、为什么需要崩溃监控

线上问题你永远无法靠"用户截图"复现。崩溃监控自动上报：堆栈、设备、系统、操作路径，让 bug 变成可查询的工单。

## 二、接入 Sentry

```powershell
flutter pub add sentry_flutter
```

```dart
import 'package:sentry_flutter/sentry_flutter.dart';

Future<void> main() async {
  await SentryFlutter.init(
    (options) {
      options.dsn = 'https://你的DSN@sentry.io/项目号';
      options.environment = const bool.fromEnvironment('dart.vm.product')
          ? 'production'
          : 'development';
      options.tracesSampleRate = 1.0;      // 性能采样率
    },
    appRunner: () => runApp(const ProviderScope(child: TaskFlowApp())),
  );
}
```

主动上报：

```dart
try {
  await repo.createTask(task);
} catch (e, st) {
  Sentry.captureException(e, stackTrace: st);
}

// 带上下文
Sentry.captureMessage('同步失败，离线队列堆积', level: SentryLevel.warning);
```

用户上下文（登录后设置）：

```dart
Sentry.configureScope((scope) {
  scope.setUser(SentryUser(id: '${user.id}', email: user.email));
});
```

## 三、日志分级规范

```dart
class Log {
  static void debug(String tag, String msg) =>
      debugPrint('[$tag] $msg');                       // 开发
  static void warn(String tag, String msg) {
    debugPrint('⚠️ [$tag] $msg');
    // 可选：Sentry 警告
  }
  static void error(String tag, String msg, [Object? e, StackTrace? st]) {
    debugPrint('❌ [$tag] $msg');
    if (e != null) Sentry.captureException(e, stackTrace: st);
  }
}
```

规则：

- 不打印 Token、密码、手机号
- 日志带 tag（模块），方便过滤
- 错误日志必须带堆栈
- 敏感字段脱敏后上报

## 四、发布前检查

```markdown
- [ ] DSN 是生产项目，且 environment 区分环境
- [ ] 错误日志有用户上下文
- [ ] 隐私合规：上报数据脱敏
- [ ] 告警通道配置（邮件/钉钉/Slack）
- [ ] 测试账号可在 Sentry 里识别（tag）
```

## 五、线上问题响应流程

```text
Sentry 告警 → 按严重级评估
  ├─ 崩溃率高 → 暂停灰度/回滚版本
  ├─ 单点崩溃 → 拉取堆栈 + 用户上下文 → 定位模块
  └─ 低风险 → 进入迭代修复
修复 → 发版 → 观察 Sentry 趋势是否归零
```
