# 第 04 节：CI/CD 与发布流水线

## 本节目标

- 用 GitHub Actions 自动化构建 APK
- 了解 Fastlane / Codemagic 的发布能力

## 一、CI 到 CD：从测试到发布

Stage 08 的 CI 只做 analyze + test；本节点发布流水线：

```text
推送 tag v1.2.3
  → analyze + test
  → 构建 AAB / APK
  → 签名
  → 上传分发（GitHub Release / 应用商店）
  → 通知
```

## 二、GitHub Actions：构建并发布 APK

```yaml
name: Build Release

on:
  push:
    tags: ['v*']                    # 打 tag 触发

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          channel: stable
          cache: true

      - run: flutter pub get
      - run: flutter test
      - run: flutter build appbundle --release

      # 解密签名（密钥放 GitHub Secrets 的 base64）
      - name: 解密密钥
        env:
          KEYSTORE_B64: ${{ secrets.KEYSTORE_B64 }}
          KEY_PROPERTIES: ${{ secrets.KEY_PROPERTIES }}
        run: |
          echo "$KEYSTORE_B64" | base64 -d > android/app/taskflow-upload.jks
          echo "$KEY_PROPERTIES" > android/key.properties

      - uses: actions/upload-artifact@v4
        with:
          name: release-aab
          path: build/app/outputs/bundle/release/*.aab
```

安全要点：

- 密钥只放 GitHub Secrets，绝不入库
- 每次构建用**全新的一次性配置**，构建机不留密钥

## 三、Fastlane：应用商店自动化

Fastlane 是"上架自动化"工具（Ruby），可提交 Google Play / App Store：

```ruby
# fastlane/Fastfile
platform :android do
  lane :beta do
    gradle(task: 'bundleRelease')
    supply(                # 上传到 Google Play 内测
      track: 'internal',
      aab_path: 'build/app/outputs/bundle/release/app-release.aab',
    )
  end
end
```

## 五、热更新方案对比

| 方案 | 原理 | 优点 | 缺点/限制 |
|------|------|------|-----------|
| 应用商店发版 | 整包更新 | 稳定合规 | 审核周期长 |
| Shorebird / OTA 方案 | 代码补丁 | 秒级修复 | iOS 政策风险；Dart 改动有限制 |
| 远程配置（后端开关） | 运行时配置 | 无需发版 | 只能改行为，不能改代码 |
| 服务端渲染 / 动态化 | 模板下发 | 灵活 | 复杂度高，仅部分业务 |

**建议**：线上小问题优先"后端开关 + 远程配置"；代码级修复走正常发版；热更新方案在合规允许时再评估。

## 六、版本发布流程落地

```markdown
1. main 分支合并 → CI 自动测试
2. 人工打 tag v1.2.3 → 发布流水线构建
3. 构建产物自动上传（Release/商店）
4. 内部群分发 → 冒烟
5. 商店审核 → 生产发布 → 监控观察 24h
```
