# Flutter起步工程

提供Dart对象、内存任务列表、输入校验与Widget测试。先安装学校统一的Flutter SDK，执行 `flutter --version`、`flutter doctor` 确认工具与目标平台可用。

本次CI使用Flutter 3.47.6。该版本在中文工程路径下运行分析器出现协议解析错误；若遇到`FormatException`或分析器退出，把个人工程复制到有写入权限的英文路径后再执行以下命令。仓库中的课程目录继续使用中文。

从仓库根目录在PowerShell中运行：

```powershell
Set-Location "02-方向选修/04-Flutter移动应用开发/起步工程"
flutter pub get
flutter analyze
flutter test
flutter run -d chrome
```

本工程包含Web入口。新增Android或Windows平台时，在个人项目副本中执行 `flutter create --platforms=android,windows .` 生成平台文件，再按平台要求配置工具。

预期：页面能添加任务、切换完成状态、删除任务；空名称显示反馈。内存版本重启清空数据。本地保存与真实API接入是后续独立任务。

## 起步任务

复制 [main.dart](lib/main.dart) 到个人项目，先实现TaskStore.add，再完成列表渲染。参考实现即当前完整工程；[测试](test/task_test.dart)给出了空输入、稳定编号和完整交互的行为契约。

独立变式：加入未完成筛选；再将Task序列化为JSON并按存储课持久化。验收要包含实际SDK版本、运行命令、界面截图或演示、测试结果。

本机尚无Flutter SDK，仓库提供源码和自动验证任务；实际工具结果更新到教学管理的运行记录，不能仅凭源码存在宣称已完成平台验证。

维护者可从仓库根目录执行兼容验证脚本：

```powershell
python "工具脚本/验证Flutter起步工程.py"
```

脚本只验证临时英文副本，依次安装依赖、分析、测试和构建Web，完成后清理临时副本。系统临时路径含中文时，用`--work-root`指定一个可写的英文目录。实际运行与个人练习仍在自己的项目副本中完成。
