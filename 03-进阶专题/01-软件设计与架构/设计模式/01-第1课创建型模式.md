# 第1课：创建型模式

创建型模式关注**对象的创建机制**，将对象的创建与使用分离，使系统独立于对象的创建方式。

---

## 1. 单例模式（Singleton）

### 动机
确保一个类只有一个实例，并提供全局访问点。

### 适用场景
- 配置管理器
- 数据库连接池
- 日志记录器

### Python 实现

```python
class Singleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

# 更 Pythonic：模块级单例或装饰器
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class Config:
    def __init__(self):
        self.settings = {}
```

### 注意事项

| 优点 | 缺点 |
|------|------|
| 控制实例数量 | 全局状态，难测试 |
| 节省资源 | 违反 SRP |
| 延迟初始化 | 多线程需加锁 |

**现代替代：** 依赖注入容器管理生命周期，而非手写单例。

---

## 2. 工厂方法（Factory Method）

### 动机
定义创建对象的接口，由子类决定实例化哪个类。

### 结构

```
Creator (abstract)
  + factory_method() → Product
  + operation()        使用 factory_method()

ConcreteCreator
  + factory_method() → ConcreteProduct
```

### Python 实现

```python
from abc import ABC, abstractmethod

class Document(ABC):
    @abstractmethod
    def render(self) -> str: ...

class PDFDocument(Document):
    def render(self):
        return "<PDF content>"

class WordDocument(Document):
    def render(self):
        return "<Word content>"

class DocumentCreator(ABC):
    @abstractmethod
    def create_document(self) -> Document: ...

    def export(self) -> str:
        doc = self.create_document()
        return doc.render()

class PDFCreator(DocumentCreator):
    def create_document(self):
        return PDFDocument()

class WordCreator(DocumentCreator):
    def create_document(self):
        return WordDocument()
```

### 简单工厂 vs 工厂方法

```python
# 简单工厂 — 一个工厂类根据参数创建
class DocumentFactory:
    @staticmethod
    def create(doc_type: str) -> Document:
        creators = {"pdf": PDFDocument, "word": WordDocument}
        return creators[doc_type]()

# 工厂方法 — 每个产品对应一个 Creator 子类
# 扩展时新增子类，不修改已有代码（OCP）
```

**选型：** 产品类型固定且少 → 简单工厂；产品族会扩展 → 工厂方法。

---

## 3. 抽象工厂（Abstract Factory）

### 动机
创建**一族相关或依赖的对象**，无需指定具体类。

### 类比
家具工厂：现代风格工厂生产现代椅+现代桌；古典风格工厂生产古典椅+古典桌。不能混用。

### Python 实现

```python
class Button(ABC):
    @abstractmethod
    def render(self): ...

class DarkButton(Button):
    def render(self):
        return "[Dark Button]"

class LightButton(Button):
    def render(self):
        return "[Light Button]"

class Checkbox(ABC):
    @abstractmethod
    def render(self): ...

class DarkCheckbox(Checkbox):
    def render(self):
        return "[Dark Checkbox]"

class LightCheckbox(Checkbox):
    def render(self):
        return "[Light Checkbox]"

class UIFactory(ABC):
    @abstractmethod
    def create_button(self) -> Button: ...
    @abstractmethod
    def create_checkbox(self) -> Checkbox: ...

class DarkThemeFactory(UIFactory):
    def create_button(self):
        return DarkButton()
    def create_checkbox(self):
        return DarkCheckbox()

class LightThemeFactory(UIFactory):
    def create_button(self):
        return LightButton()
    def create_checkbox(self):
        return LightCheckbox()

# 使用 — 整个 UI 风格一致
def build_ui(factory: UIFactory):
    btn = factory.create_button()
    cb = factory.create_checkbox()
    return btn.render(), cb.render()
```

### vs 工厂方法

| | 工厂方法 | 抽象工厂 |
|---|---------|---------|
| 创建 | 一种产品 | 一族产品 |
| 扩展 | 新增 Creator 子类 | 新增 Factory 子类（整族） |
| 复杂度 | 较低 | 较高 |

---

## 4. 建造者模式（Builder）

### 动机
分步骤构建复杂对象，同样的构建过程可以创建不同的表示。

### 类比
点汉堡：选面包 → 选肉 → 选配料 → 组装。同样的流程，不同组合得到不同汉堡。

### Python 实现

```python
class Pizza:
    def __init__(self):
        self.size = "medium"
        self.crust = "thin"
        self.toppings = []

    def __str__(self):
        return f"{self.size} {self.crust} pizza with {', '.join(self.toppings)}"

class PizzaBuilder:
    def __init__(self):
        self._pizza = Pizza()

    def size(self, size: str):
        self._pizza.size = size
        return self

    def crust(self, crust: str):
        self._pizza.crust = crust
        return self

    def add_topping(self, topping: str):
        self._pizza.toppings.append(topping)
        return self

    def build(self) -> Pizza:
        return self._pizza

# 链式调用
pizza = (PizzaBuilder()
    .size("large")
    .crust("thick")
    .add_topping("pepperoni")
    .add_topping("cheese")
    .build())
```

### Director（可选）

```python
class PizzaDirector:
    def __init__(self, builder: PizzaBuilder):
        self.builder = builder

    def make_margherita(self):
        return (self.builder
            .size("medium")
            .crust("thin")
            .add_topping("tomato")
            .add_topping("mozzarella")
            .build())
```

### vs 构造函数

| 构造函数 | 建造者 |
|---------|--------|
| 参数少时简洁 | 参数多且可选时用建造者 |
| 必填参数明确 | 步骤清晰、可读性好 |
| | 支持不同构建流程 |

**Python 提示：** `@dataclass` + `field(default=...)` 可替代简单场景；复杂可选组合仍适合 Builder。

## 5. 原型模式（Prototype）

### 动机
通过复制现有对象来创建新对象，而非 `new`。

### 适用场景
- 创建成本高（深拷贝数据库对象）
- 运行时才知道具体类型
- 避免 subclassing 工厂

### Python 实现

```python
import copy

class Prototype:
    def clone(self):
        return copy.deepcopy(self)

class GameCharacter(Prototype):
    def __init__(self, name, level, equipment):
        self.name = name
        self.level = level
        self.equipment = equipment  # 列表，需深拷贝

# 从模板克隆
template = GameCharacter("Warrior", 1, ["sword", "shield"])
player1 = template.clone()
player1.name = "Player1"
player1.equipment.append("helmet")  # 不影响 template
```

### 浅拷贝 vs 深拷贝

```python
import copy

original = {"items": [1, 2, 3]}

shallow = copy.copy(original)
shallow["items"].append(4)
# original["items"] 也变了 → [1, 2, 3, 4]

deep = copy.deepcopy(original)
deep["items"].append(5)
# original 不变
```

## 6. 创建型模式对比

```
需要几个实例？
  └─ 一个 → 单例（谨慎使用）

创建哪种对象？
  └─ 一种，类型运行时决定 → 工厂方法 / 简单工厂
  └─ 一族相关产品 → 抽象工厂

对象构建复杂？
  └─ 多步骤、多可选参数 → 建造者

从现有对象复制？
  └─ 原型
```

# 深入篇：创建型的底层逻辑

> 前面是每个模式的"是什么"；这一篇讲"为什么不能直接 new"、
> "每个模式的机关与代价"和"它们之间的血缘关系"。

## 0. 创建为什么是个问题？

`new` 是面向对象里最强的耦合：写 `new PDFDocument()` 的地方，
就**同时决定了"用哪个类"和"怎么构造"**。当这两件事会变时，
直接 new 就变成修改点。创建型五个模式，本质是五种"把 new 藏起来"的方式：

| 方式 | 藏的是什么 |
|---|---|
| 单例 | "只能有一个"这个约束 |
| 工厂方法 | "造哪种"这个决定 |
| 抽象工厂 | "一整族配套"这个决定 |
| 建造者 | "怎么一步步拼"这个过程 |
| 原型 | "从零造"这个成本 |

---

## 1. 单例：被误解最多的模式

### 机关

```python
def __new__(cls):
    if cls._instance is None:
        cls._instance = super().__new__(cls)
    return cls._instance
```

拦截"造对象"的入口：第一个实例存起来，之后谁来都还它。

### 变化点与代价

- 隔离的变化：**实例数量**（业务上必须唯一：配置、连接池）；
- 代价：全局状态难测试、隐藏耦合、多线程要加锁；
- 反模式形态：为了"方便全局访问"而单例——唯一性应该是业务需求，不是偷懒手段。

### 现代替代

依赖注入容器管理生命周期、模块级对象（Python `import` 一次天然共享）。
**看到"全局唯一"先问：这个唯一性是业务约束，还是我图方便？**

---

## 2. 工厂方法：模板方法在创建场景的特例

### 机关

```python
class Creator(ABC):
    @abstractmethod
    def create_product(self): ...   # 工厂方法：只声明
    def operate(self):              # 骨架：只认抽象
        product = self.create_product()
        return product.use()
```

### 深层洞察

- `operate()` 是**模板方法**，`create_product()` 是可变步骤——
  工厂方法模式本质上就是模板方法模式在"创建"上的应用；
- 隔离的变化：**创建哪个产品**；加产品 = 加 Creator 子类，旧代码不改（OCP）；
- 和简单工厂的区别：简单工厂"一个函数集中拍板"（适合产品少且固定）；
  工厂方法"拍板权下放给子类"（适合产品会扩展）。

---

## 3. 抽象工厂：一族产品的"配套契约"

### 机关

一个工厂接口声明"族里有哪些产品"，每个族一个工厂子类：

```python
class UIFactory(ABC):
    def create_button(self) -> Button: ...
    def create_checkbox(self) -> Checkbox: ...

class DarkThemeFactory(UIFactory): ...
class LightThemeFactory(UIFactory): ...
```

### 深层洞察

- 它解决的不只是"创建"，更是**一致性**：从同一个工厂拿出来的产品天然成套，
  不会"暗色按钮配浅色输入框"；
- 实现上就是"一组工厂方法装进一个族对象"——你拆开它，全是工厂方法；
- 选型方向：**加新族便宜（加一个 Factory 子类），加新产品贵（改接口 + 所有族）**。
  所以适用条件是：产品种类稳定、族会变多；
- 与六边形架构的关系：一个抽象工厂 = 一个供应商族的适配器集合。

---

## 4. 建造者：把"流程"从"对象"里拆出来

### 机关

```python
class EmailBuilder:
    def body(self, text): ...; return self    # 每步返回 self → 链式
    def build(self): ...                      # 交付前统一校验
```

### 深层洞察

- 隔离的变化：**构造流程**（哪些步骤、什么顺序、什么校验）；
- 三个角色：Builder（步骤）、Director（配方，可选）、Client（点菜）；
- Python 里建造者常"退化成"函数或 `@dataclass` + 默认值——
  参数少时直接构造，别为模式而模式；
- 与工厂的区别：工厂管"造哪种"，建造者管"怎么一步步造"。

---

## 5. 原型：复制规则由对象自己定

### 机关

```python
def clone(self):
    return copy.deepcopy(self)   # 默认规则：全部复制
```

### 深层洞察

- `deepcopy` 是"无脑复印机"（机制），`clone()` 是"复印规章制度"（模式）；
- 定制 clone 能决定：什么共享（只读配置）、什么重置（新 ID、清空历史）、
  什么深拷贝（可变状态）；
- 浅拷贝 vs 深拷贝：浅拷贝新外壳旧内层（改内层连累原件），
  深拷贝整棵树都是新的；
- 与备忘录的区别：原型复制是为了**创建新对象**，备忘录保存是为了**恢复旧状态**。

---

## 6. 创建型选型的完整思维链

```
先问：创建这件事真的会变吗？（Rule of Three）
  ├─ 不会 → 直接 new / 构造函数
  └─ 会 ↓
      要几份？→ 一份 → 单例（先问是否业务约束）
      要哪种？→ 一种 → 工厂方法（会扩展）或简单工厂（固定且少）
                → 一族 → 抽象工厂
      怎么造？→ 多步骤/多可选 → 建造者（+Director）
      有模板？→ 复制现成 → 原型
```
