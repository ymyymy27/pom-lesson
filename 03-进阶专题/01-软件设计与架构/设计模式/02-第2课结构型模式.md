# 第2课：结构型模式

结构型模式关注**类和对象的组合**，形成更大的结构，同时保持灵活和高效。

---

## 1. 适配器模式（Adapter）

### 动机
将一个类的接口转换成客户端期望的另一个接口。

### 类比
电源转接头：中国插头 → 转接头 → 美国插座。

### 类适配器 vs 对象适配器

```python
# 已有第三方库 — 接口不兼容
class LegacyPayment:
    def make_payment(self, dollars: float):
        return f"Paid ${dollars}"

# 目标接口
class PaymentGateway(ABC):
    @abstractmethod
    def pay(self, amount_cents: int) -> str: ...

# 对象适配器（推荐，组合优于继承）
class PaymentAdapter(PaymentGateway):
    def __init__(self, legacy: LegacyPayment):
        self.legacy = legacy

    def pay(self, amount_cents: int) -> str:
        dollars = amount_cents / 100
        return self.legacy.make_payment(dollars)
```

**适用：** 集成第三方 SDK、遗留系统改造、统一多种 API。

---

## 2. 桥接模式（Bridge）

### 动机
将抽象与实现分离，使它们可以独立变化。

### vs 继承爆炸

```
不用桥接：                     用桥接：
RedCircle                    Shape ──▷ Circle, Square
BlueCircle                        └──▷ Color: Red, Blue
RedSquare
BlueSquare                   Shape(color).draw()
... 2×2=4 个类                2+2=4 个类，但可任意组合
```

```python
class Color(ABC):
    @abstractmethod
    def fill(self) -> str: ...

class Red(Color):
    def fill(self):
        return "red"

class Shape(ABC):
    def __init__(self, color: Color):
        self.color = color

    @abstractmethod
    def draw(self) -> str: ...

class Circle(Shape):
    def draw(self):
        return f"Circle filled with {self.color.fill()}"
```

**适用：** 两个维度独立变化（形状×颜色、设备×消息类型、UI×平台）。

---

## 3. 组合模式（Composite）

### 动机
将对象组合成树形结构，以表示「部分-整体」层次，客户端统一对待单个对象和组合对象。

### 类比
文件系统：文件和文件夹都支持 `getSize()`，文件夹的大小 = 子项之和。

```python
class FileSystemComponent(ABC):
    @abstractmethod
    def get_size(self) -> int: ...

class File(FileSystemComponent):
    def __init__(self, name, size):
        self.name = name
        self.size = size

    def get_size(self):
        return self.size

class Directory(FileSystemComponent):
    def __init__(self, name):
        self.name = name
        self.children: list[FileSystemComponent] = []

    def add(self, component: FileSystemComponent):
        self.children.append(component)

    def get_size(self):
        return sum(c.get_size() for c in self.children)

# 统一接口
root = Directory("root")
root.add(File("readme.txt", 1024))
docs = Directory("docs")
docs.add(File("guide.md", 2048))
root.add(docs)
print(root.get_size())  # 3072
```

**适用：** 菜单树、组织架构、UI 组件树、表达式 AST。

---

## 4. 装饰器模式（Decorator）

### 动机
动态地给对象添加职责，比继承更灵活。

### Python 中的装饰器

Python 的 `@decorator` 语法正是装饰器模式的语言级支持：

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@log_calls
def greet(name):
    return f"Hello, {name}"
```

### 类装饰器模式

```python
class Coffee(ABC):
    @abstractmethod
    def cost(self) -> float: ...
    @abstractmethod
    def description(self) -> str: ...

class SimpleCoffee(Coffee):
    def cost(self):
        return 5.0
    def description(self):
        return "Simple coffee"

class CoffeeDecorator(Coffee):
    def __init__(self, coffee: Coffee):
        self._coffee = coffee

    def cost(self):
        return self._coffee.cost()
    def description(self):
        return self._coffee.description()

class Milk(CoffeeDecorator):
    def cost(self):
        return self._coffee.cost() + 1.5
    def description(self):
        return self._coffee.description() + ", milk"

class Sugar(CoffeeDecorator):
    def cost(self):
        return self._coffee.cost() + 0.5
    def description(self):
        return self._coffee.description() + ", sugar"

# 任意组合
coffee = Sugar(Milk(SimpleCoffee()))
print(coffee.description())  # Simple coffee, milk, sugar
print(coffee.cost())         # 7.0
```

**适用：** 中间件链、I/O 流包装（Python 的 `BufferedReader`）、权限/日志/缓存叠加。

### vs 继承

| 继承 | 装饰器 |
|------|--------|
| 编译时确定 | 运行时组合 |
| 组合爆炸 | 灵活叠加 |
| 静态 | 动态 |

## 5. 外观模式（Facade）

### 动机
为子系统提供统一的高层接口，隐藏复杂性。

### 类比
酒店前台 —— 你不需要知道 housekeeping、kitchen、maintenance 怎么协作，只跟前台说需求。

```python
class CPU:
    def freeze(self): ...
    def jump(self, addr): ...
    def execute(self): ...

class Memory:
    def load(self, addr, data): ...

class HardDrive:
    def read(self, lba, size): ...

# 外观 — 简化启动流程
class ComputerFacade:
    def __init__(self):
        self.cpu = CPU()
        self.memory = Memory()
        self.hard_drive = HardDrive()

    def start(self):
        self.cpu.freeze()
        boot_data = self.hard_drive.read(0, 1024)
        self.memory.load(0, boot_data)
        self.cpu.jump(0)
        self.cpu.execute()
```

**适用：** API Gateway、SDK 封装、遗留系统统一入口。

**注意：** 外观不阻止客户端直接访问子系统，只是提供便捷路径。

## 6. 享元模式（Flyweight）

### 动机
运用共享技术有效支持大量细粒度对象，减少内存占用。

### 核心思想
分离**内部状态**（可共享）和**外部状态**（每次不同）。

```python
class TreeType:  # 享元 — 共享的数据
    def __init__(self, name, color, texture):
        self.name = name
        self.color = color
        self.texture = texture  # 假设很大

class TreeFactory:
    _types: dict[tuple, TreeType] = {}

    @classmethod
    def get_tree_type(cls, name, color, texture) -> TreeType:
        key = (name, color, texture)
        if key not in cls._types:
            cls._types[key] = TreeType(name, color, texture)
        return cls._types[key]

class Tree:  # 外部状态：位置
    def __init__(self, x, y, tree_type: TreeType):
        self.x = x
        self.y = y
        self.type = tree_type  # 引用共享对象

# 10000 棵树可能只有几种 TreeType
forest = [Tree(x, y, TreeFactory.get_tree_type("Oak", "green", "oak.png"))
          for x, y in coordinates]
```

**适用：** 文本编辑器字符格式、游戏粒子/地图块、连接池中的连接元数据。

**Python 提示：** 小整数缓存、`str.intern()`、元组的不可哈希性等也是享元思想。

## 7. 代理模式（Proxy）

### 动机
为对象提供代理，以控制对它的访问。

### 四种常见代理

| 类型 | 作用 | 示例 |
|------|------|------|
| 虚拟代理 | 延迟加载 | 大图片占位符 |
| 保护代理 | 权限控制 | 仅 admin 可删除 |
| 远程代理 | 本地代表远程对象 | RPC stub |
| 缓存代理 | 缓存结果 | 重复查询走缓存 |

```python
class Image(ABC):
    @abstractmethod
    def display(self): ...

class RealImage(Image):
    def __init__(self, filename):
        self.filename = filename
        self._load_from_disk()

    def _load_from_disk(self):
        print(f"Loading {self.filename} from disk...")

    def display(self):
        print(f"Displaying {self.filename}")

class ImageProxy(Image):
    def __init__(self, filename):
        self.filename = filename
        self._real = None

    def display(self):
        if self._real is None:
            self._real = RealImage(self.filename)  # 延迟加载
        self._real.display()
```

**Python 提示：** `@property`、`__getattr__`、描述符也可实现类似效果。

## 8. 结构型模式对比

```
接口不匹配？ → 适配器
两个维度独立变化？ → 桥接
树形结构统一处理？ → 组合
动态叠加功能？ → 装饰器
简化复杂子系统？ → 外观
大量相似小对象？ → 享元
控制对象访问？ → 代理
```

# 深入篇：结构型的底层逻辑

> 结构型管"对象怎么组合"。这一篇讲每个模式的**机关**、
> **隔离的变化**、**代价**，以及怎么区分那些"长着同一张脸"的模式。

## 0. 结构型的六种"组合手术"

结构型不是七个无关技巧，而是六种组合问题的答案：

| 组合问题 | 模式 |
|---|---|
| 接口对不上 → 转接 | 适配器 |
| 两轴正交 → 解耦 | 桥接 |
| 部分-整体 → 统一 | 组合 |
| 增强 → 叠加 | 装饰器 |
| 复杂 → 简化 | 外观 |
| 重复 → 共享 | 享元 |
| 访问 → 控制 | 代理 |

---

## 1. 适配器：翻译官

### 机关

```python
class Adapter(Target):                 # 实现"业务要的接口"
    def __init__(self, third): self._third = third
    def request(self):
        return self._third.specific_request()   # 内部翻译
```

### 深层洞察

- 适配器**不改双方**，只加一层翻译；目标接口由业务方定义；
- 翻译工作通常有三类：单位换算、格式转换、字段映射；
- 用**组合**（持有第三方）优于继承（继承会把 SDK 方法全暴露）；
- 和六边形架构的关系：端口 = 目标接口，适配器 = 外部世界的翻译层；
- **别预造**：等真的出现第二个不兼容接口（Rule of Three）再抽象。

---

## 2. 桥接：两个家族的"组合桥"

### 机关

```python
class Shape(ABC):
    def __init__(self, renderer): self._renderer = renderer   # 桥
```

### 深层洞察

- 继承组合会爆炸（n×m 个类），桥接用组合让两个维度**各自扩展、任意搭配**；
- 隔离的变化：**两个正交维度的扩展**——加一个实现（颜色），所有抽象子类自动可用；
- 和策略的区别：策略只有一个维度在变；桥接要求**两个维度都要变且都会扩展**；
- 和六边形架构的关系："抽象握着实现引用"就是"核心握着端口引用"的模式级表达。

---

## 3. 组合：树形结构的统一接口

### 机关

```python
class Branch(Node):
    def size(self):
        return sum(c.size() for c in self._children)   # 递归
```

### 深层洞察

- 叶子是终点（自己干活），容器是递归点（汇总子项）；
- 隔离的变化：**树的形状**（增删节点，客户端无感）；
- 和装饰器都是"持有子对象"，但组合是**一对多 + 递归聚合**，
  装饰器是**一对一 + 增强**；
- 和解释器的关系：解释器 = 组合的树 + 每个节点自带 `interpret()`。

---

## 4. 装饰器：洋葱

### 机关

```python
class Decorator(Component):
    def __init__(self, c): self._c = c
    def op(self): return self._c.op()      # 转发（加料在子类的前后）
```

### 深层洞察

- 隔离的变化：**功能叠加的方式与顺序**——加功能 = 新写一个装饰器，组件零改动；
- 和继承的区别：继承在编译期固定、会组合爆炸；装饰器运行期组合、粒度更细；
- 和代理的区别：装饰器**必转发**（增强），代理**可能不转发**（控制）；
- Python 的 `@` 语法是装饰器模式在函数上的语言级实现——
  注意离函数最近的那个先包（自下而上）；
- 洋葱别太厚：层数多时调试栈很深，考虑 AOP 框架。

---

## 5. 外观：前台

### 机关

```python
class Facade:
    def __init__(self): self.a = A(); self.b = B()
    def run(self):                      # 对外一个方法，内部编排
        self.a.do(); self.b.do()
```

### 深层洞察

- 外观**不封锁**子系统——它只是便捷路径，需要精细控制时仍可直接访问；
- 隔离的变化：**子系统的内部实现与编排**；
- 和适配器的区别：适配器**改**接口（翻译），外观**加**入口（编排）；
- 最大的坑：外观变"上帝对象"，把子系统的复杂度全吸进去——
  那是转移复杂度，不是消除。

---

## 6. 享元：共享池

### 机关

```python
class Registry:
    _pool = {}
    @classmethod
    def get(cls, key):
        if key not in cls._pool:
            cls._pool[key] = Flyweight(key)
        return cls._pool[key]           # 有就复用
```

### 深层洞察

- 拆分规则：**内部状态**（不变、重复）抽出来共享；**外部状态**（每次不同）留在客户端；
- 共享的前提是内部状态**不可变**——改一个 = 改一万个；
- 和单例的区别：单例全局一个，享元**按 key 多个**（池 vs 独苗）；
- 现代视角：内存不是主要理由了，**一致性**和**加载成本**才是
  （共享配置不漂移、大资源只加载一次）；
- `lru_cache`、连接池、embedding 缓存都是享元思想。

---

## 7. 代理：替身

### 机关

```python
class Proxy(Subject):
    def __init__(self): self._real = None
    def request(self):
        if self._real is None: self._real = Real()   # 延迟创建
        return self._real.request()
```

### 深层洞察

- 四种替身：虚拟（延迟）、保护（权限）、缓存（复用）、远程（本地代表远方）；
- 透明性：客户端不知道自己在跟真身还是替身说话——这是目的，不是缺陷；
- 和装饰器结构几乎一样：**意图决定模式**——加功能是装饰器，
  替真实对象做访问决定是代理；
- 现实里：nginx 反向代理、OpenAI SDK 客户端、`weakref.proxy` 全是它。

---

## 8. 三组双胞胎 + 一张"形状谱系"

| 组合 | 口诀 |
|---|---|
| 适配器 vs 外观 | 改造接口（翻译） vs 新增入口（编排） |
| 装饰器 vs 代理 | 加功能（必转发） vs 控访问（可能不转发） |
| 享元 vs 单例 | 按 key 多个共享 vs 全局一个 |

**为什么它们长这么像？** 适配器、桥接、装饰器、代理都是
"接口 + 持有引用 + 转发/翻译"的形态。区别不在形状，在**意图**：

```
接口对不上 → 适配器
两个维度 → 桥接
增强 → 装饰器
控制 → 代理
```
