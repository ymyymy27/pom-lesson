# 第1课：限界上下文与上下文地图

## 1. 深入理解限界上下文

### 边界内的规则

限界上下文不仅是「模块名」，而是包含：

- **统一的术语**（通用语言）
- **一致的业务规则**
- **独立的生命周期**
- **明确的对外接口**

```
┌─────────────────────────────────────┐
│         订单上下文 Order             │
│                                     │
│  术语：Order, LineItem, OrderStatus │
│  规则：已支付订单不可改商品           │
│  状态机：Draft→Paid→Shipped→Done    │
│                                     │
│  对外：PlaceOrder, CancelOrder API  │
│         OrderCreated 事件           │
└─────────────────────────────────────┘
```

### 划分过细 vs 过粗

| 问题 | 症状 | 解决 |
|------|------|------|
| 过粗 | 一个「电商模块」500 个类 | 按子域拆分 |
| 过细 | 「OrderLineItemPrice 上下文」 | 合并到 Order |
| 刚好 | 一个团队 2 周内能讲清边界 | ✓ |

**经验法则：** 一个限界上下文 ≈ 一个微服务（未来）≈ 一个团队负责（现在）。

## 2. 事件风暴（Event Storming）

### 是什么
跨职能工作坊，用**橙色便利贴（领域事件）**梳理业务流程，自然浮现上下文边界。

### 流程（4 小时版）

```
Phase 1: 发散（1h）
  贴出所有领域事件：「OrderPlaced」「PaymentReceived」「ItemShipped」...
  按时间线排列

Phase 2: 命令与角色（1h）
  每个事件前加：谁（角色）执行什么命令（蓝色贴）导致事件

Phase 3: 聚合识别（1h）
  用黄色贴圈出「一起变化的数据」→ 候选聚合

Phase 4: 上下文边界（1h）
  用胶带在墙上划分区域 → 限界上下文
  标注上下文间关系
```

### 产出物

- 完整业务流程时间线
- 限界上下文列表
- 上下文地图初稿
- 通用语言词汇表


### 关系选型指南

| 场景 | 推荐关系 |
|------|---------|
| 两个团队平等协作 | Partnership |
| 上游稳定，下游可提需求 | Customer-Supplier |
| 下游必须适配上游（第三方） | Conformist + ACL |
| 上游提供公开 API | Open Host Service |
| 共享少量类型定义 | Shared Kernel（谨慎，易耦合） |

## 4. 防腐层（Anti-Corruption Layer）

### 问题
集成外部系统时，外部模型会「污染」你的领域模型。

```
外部物流 API 返回：
{
  "shipment_id": "xxx",
  "pkg_wgt_kg": 2.5,
  "dest_addr_line1": "..."
}

你的领域模型：
Shipment(shipment_id, weight, destination_address)
```

### 防腐层结构

```
┌──────────────┐     ┌─────────────┐     ┌──────────────┐
│  你的领域层   │ ←── │  防腐层 ACL  │ ←── │  外部 API    │
│  Shipment    │     │  翻译/适配    │     │  原始 JSON   │
└──────────────┘     └─────────────┘     └──────────────┘
```

```python
# 防腐层示例
class LogisticsACL:
    """将外部物流 API 翻译为领域 Shipment"""

    def __init__(self, external_client):
        self._client = external_client

    def get_shipment(self, tracking_id: str) -> Shipment:
        raw = self._client.track(tracking_id)
        return Shipment(
            id=raw["shipment_id"],
            weight=Weight(raw["pkg_wgt_kg"], unit="kg"),
            destination=Address(
                line1=raw["dest_addr_line1"],
                city=raw["dest_city"],
            ),
        )
```

**原则：** 外部变化只改 ACL，领域层不受影响。

## 5. 共享内核（Shared Kernel）— 谨慎使用

两个上下文共享一小部分代码/模型。

```
Shared Kernel: UserId, Email 值对象
     ↑                    ↑
Identity 上下文      Project 上下文
```

**风险：** 共享部分变更需两边协调 → 耦合  
**替代：** 与其共享代码，不如各自定义 + ID 关联

## 6. 上下文集成模式

| 模式 | 耦合 | 一致性 | 场景 |
|------|------|--------|------|
| 共享数据库 | 极高 | 强 | ❌ 反模式 |
| 同步 API 调用 | 高 | 强 | 需即时反馈 |
| 异步事件 | 低 | 最终 | 大多数跨上下文 |
| 复制读模型 | 低 | 最终 | CQRS 读侧 |

**推荐默认：** 上下文间用 **Domain Event + 消息队列**，避免同步链式调用。

```
Order 上下文                    Inventory 上下文
    │                                │
    │ OrderCreated 事件               │
    └───────────────────────────────▷│ ReserveStock 命令
                                     │ StockReserved 事件
```

## 7. 从单体到上下文的代码组织

### 模块化单体目录结构

```
taskflow/
├── contexts/
│   ├── identity/
│   │   ├── domain/       # 实体、值对象、聚合
│   │   ├── application/  # 用例、应用服务
│   │   ├── infrastructure/  # Repository 实现、DB
│   │   └── api/          # HTTP 接口
│   ├── project/
│   │   ├── domain/
│   │   ├── application/
│   │   ├── infrastructure/
│   │   └── api/
│   └── notification/
│       └── ...
├── shared/               # 真正跨上下文共享（极少）
│   └── kernel/
│       └── user_id.py
└── main.py
```

**规则：**
- 上下文之间**不直接 import domain 层**
- 跨上下文只通过 **API / Event / ACL**
- 每个上下文内部可独立测试

### 练习 2：设计防腐层

外部支付网关返回 `{ "txn_id", "amt_cents", "stat" }`，设计 ACL 将其翻译为你的 `Payment` 领域对象。

<details>
<summary>参考答案（练习 2）</summary>

```python
@dataclass
class Payment:
    transaction_id: str
    amount: Money
    status: PaymentStatus  # enum: Pending, Completed, Failed

class PaymentGatewayACL:
    def to_domain(self, raw: dict) -> Payment:
        status_map = {
            "stat_1": PaymentStatus.PENDING,
            "stat_2": PaymentStatus.COMPLETED,
            "stat_3": PaymentStatus.FAILED,
        }
        return Payment(
            transaction_id=raw["txn_id"],
            amount=Money(raw["amt_cents"] / 100, "CNY"),
            status=status_map[raw["stat"]],
        )
```
