# 第4课：缓存模式与常见问题

## 1. 为什么需要缓存？

```
无缓存：  请求 → 应用 → PostgreSQL（10–50ms+）
有缓存：  请求 → 应用 → Redis（0.1–1ms）→ 命中直接返回
```

适合缓存的数据：**读多写少**、**可容忍短暂不一致**、**查询成本高**。

---

## 2. 四种缓存模式

| 模式 | 读 | 写 | 适用 |
|------|----|----|------|
| **Cache Aside** | 先缓存后 DB | 先 DB 后删缓存 | 通用（最常用） |
| Read Through | 缓存层加载 | — | 读多，缓存中间件 |
| Write Through | — | 同时写缓存和 DB | 强一致 |
| Write Behind | — | 先缓存，异步写 DB | 写多读少 |

### 2.1 Cache Aside（推荐）

```python
def get_article(article_id: int) -> dict | None:
    key = f"article:{article_id}"
    data = cache.get(key)
    if data is not None:
        return data

    data = db.fetch_article(article_id)   # 模拟 DB
    if data is None:
        cache.set(key, None, ttl=60)      # 空值缓存，防穿透
        return None

    cache.set(key, data, ttl=300)
    return data

def update_article(article_id: int, payload: dict) -> None:
    db.update_article(article_id, payload)
    cache.delete(f"article:{article_id}")   # 删缓存，而非更新
```

**更新时删缓存而非写缓存的原因：** 避免并发下旧值覆盖新值。

## 3. 三大经典问题

### 3.1 缓存穿透

**现象：** 查询不存在的数据，缓存和 DB 都没有，每次打到 DB。

**对策：**

```python
# 1. 缓存空值（短 TTL）
cache.set(key, None, ttl=60)

# 2. 布隆过滤器（大量恶意 ID 时）
# 3. 接口层参数校验
```

### 3.2 缓存击穿

**现象：** 热点 Key 过期瞬间，大量请求同时查 DB。

**对策：**

```python
import uuid

def get_with_mutex(key, fetch, ttl=300):
    data = cache.get(key)
    if data is not None:
        return data

    lock_key = f"lock:{key}"
    token = str(uuid.uuid4())
    if cache.redis.set(lock_key, token, nx=True, ex=10):
        try:
            data = fetch()
            cache.set(key, data, ttl=ttl)
            return data
        finally:
            if cache.redis.get(lock_key) == token:
                cache.redis.delete(lock_key)
    else:
        import time
        time.sleep(0.05)
        return get_with_mutex(key, fetch, ttl)
```

### 3.3 缓存雪崩

**现象：** 大量 Key 同时过期，或 Redis 整体不可用，DB 压力骤增。

**对策：**

- TTL 加随机抖动：`ttl = 300 + random.randint(0, 60)`
- Redis 高可用（Sentinel / Cluster）
- 限流 + 降级

## 4. Key 设计规范

```
{app}:{module}:{entity}:{id}[:{field}]

myapp:cache:article:42
myapp:cache:article:list:page:1:size:20
myapp:stats:user:7:daily
```

| 原则 | 说明 |
|------|------|
| 统一前缀 | 多项目共用实例时防冲突 |
| 见名知意 | 运维 SCAN 时可识别 |
| 控制长度 | 键名也占内存 |
| 避免超大 Key | 单 Key 值不超过 MB 级 |

---

## 5. TTL 怎么定？

| 数据类型 | 建议 TTL |
|----------|----------|
| 热点详情 | 5–30 分钟 |
| 列表分页 | 1–5 分钟 |
| 空值占位 | 30–120 秒 |
| 验证码 | 5 分钟 |
| Session | 24 小时（滑动续期） |
| 统计数据 | 10 分钟 + 异步刷新 |

---

## 6. 什么不该缓存？

- 强一致金融余额（除非有严格失效策略）
- 超大对象（压缩或只缓存 ID 列表）
- 极低频访问数据
- 用户私有敏感数据（需加密 + 短 TTL + 权限校验）
