# 性能工程全景

## 1. 性能思维

### 一句话解释

**不要猜瓶颈在哪——测量、分析、优化、再测量。**

### 优化层次（自上而下）

```
1. 架构层：缓存、CDN、读写分离、异步 → 收益最大
2. 算法层：O(n²) → O(n log n)         → 收益大
3. 代码层：减少 IO、批量操作、连接池    → 收益中
4. 语言层：PyPy、C 扩展               → 收益小（最后手段）

❌ 不要跳过 1 直接做 4
❌ 不要优化不是瓶颈的部分（Amdahl 定律）
```

### Amdahl 定律

```
加速比 = 1 / ((1 - P) + P/S)

P = 可优化部分占比
S = 该部分的加速倍数

示例：90% 时间在 DB 查询，DB 优化 10 倍
  加速比 = 1 / (0.1 + 0.9/10) = 5x（不是 10x）

→ 先优化占比最大的部分
```

## 2. 延迟的数量级

```
心里有数，避免不合理的期望：

  L1 缓存引用     ~1 ns
  内存引用        ~100 ns
  SSD 随机读      ~100 μs    （比内存慢 1000 倍）
  同机房网络 RTT  ~0.5 ms
  跨洲网络 RTT    ~100 ms
  磁盘顺序读 1MB  ~20 ms

  → 一次 DB 查询 ≈ 1-10ms
  → 一次 Redis 查询 ≈ 0.1-1ms
  → 一次 HTTP 调用 ≈ 1-100ms
```

### 延迟分布

```
不要只看平均值，看分布：

  p50（中位数）：50% 的请求
  p95：95% 的请求
  p99：99% 的请求（用户体验的关键）
  p999：99.9% 的请求（长尾）

  平均 50ms 但 p99 2000ms → 1% 用户体验很差
  SLO 通常基于 p99
```

## 3. 性能优化 Checklist

```
测量：
  □ 有性能基准（Baseline）吗？
  □ 有 APM/Profiler 吗？
  □ 知道 p50/p95/p99 延迟吗？

架构：
  □ 读多写少场景有缓存吗？
  □ 慢操作异步化了吗？
  □ 静态资源走 CDN 了吗？

数据库：
  □ 慢查询日志开了吗？
  □ 关键查询有索引吗？
  □ N+1 查询消除了吗？

应用：
  □ 连接池配置合理吗？
  □ 大数据量用分页/流式了吗？
  □ 不必要的序列化/反序列化？
```
