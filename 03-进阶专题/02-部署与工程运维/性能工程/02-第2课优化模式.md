# 第2课：优化模式

## 1. 缓存策略

```
┌─────────┐  Hit   ┌───────┐  Miss  ┌──────┐
│  Client  │──────→│ Cache │──────→│  DB  │
└─────────┘       └───────┘       └──────┘

层级：
  L1：进程内缓存（LRU，μs 级）
  L2：Redis（ms 级，跨进程）
  L3：CDN（静态资源，边缘节点）

Cache-Aside（最常用）：
  读：Cache → Miss → DB → 写 Cache
  写：DB → 删 Cache

关键决策：
  TTL 设多少？（数据可接受多旧）
  缓存什么？（热点数据，不是全部）
  缓存粒度？（整个对象 vs 部分字段）
```

## 2. 异步与并行

```python
# ❌ 同步：串行等 3 个 API
user = fetch_user(id)        # 100ms
orders = fetch_orders(id)    # 200ms
recommendations = fetch_reco(id)  # 150ms
# 总计：450ms

# ✅ 异步：并行
import asyncio

async def get_dashboard(user_id):
    user, orders, reco = await asyncio.gather(
        fetch_user_async(user_id),
        fetch_orders_async(user_id),
        fetch_reco_async(user_id),
    )
    return {"user": user, "orders": orders, "recommendations": reco}
# 总计：~200ms（最慢的那个）
```

### 适用判断

```
适合异步：
  IO 密集型（等 DB、等 API、等文件）
  多个独立的外部调用

不适合异步：
  CPU 密集型（计算、加密）→ 用 multiprocessing
  简单 CRUD（异步开销 > 收益）
```

## 3. 数据库优化

### 索引设计

```sql
-- 单列索引
CREATE INDEX idx_tasks_status ON tasks(status);

-- 复合索引（最左前缀原则）
CREATE INDEX idx_tasks_project_status ON tasks(project_id, status, created_at DESC);

-- 查询能用到：
--   WHERE project_id = ? AND status = ?
--   WHERE project_id = ? AND status = ? ORDER BY created_at DESC
-- 用不到：
--   WHERE status = ? （没用到最左列 project_id）

-- 覆盖索引（Index-Only Scan）
CREATE INDEX idx_tasks_cover ON tasks(project_id, status) INCLUDE (title, assignee_id);
```

### 连接池

```python
# SQLAlchemy 连接池配置
engine = create_engine(
    DATABASE_URL,
    pool_size=20,         # 常驻连接数
    max_overflow=10,      # 超出 pool_size 允许的临时连接
    pool_timeout=30,      # 等待连接的超时
    pool_recycle=3600,    # 连接回收时间（防 DB 断开）
    pool_pre_ping=True,   # 使用前检测连接是否有效
)
```

### 批量操作

```python
# ❌ 逐条插入
for item in items:
    db.insert(item)  # N 次 round-trip

# ✅ 批量插入
db.bulk_insert(items)  # 1 次 round-trip

# ✅ COPY（PostgreSQL 最快）
cursor.copy_from(file, 'tasks', sep=',')
```
