# 第3课：负载测试

## 1. 负载测试类型

| 类型 | 目的 | 方法 |
|------|------|------|
| 基准测试 | 建立性能基线 | 固定并发，测量延迟/吞吐 |
| 负载测试 | 验证目标负载下表现 | 模拟预期 QPS |
| 压力测试 | 找到系统极限 | 逐步增加负载直到崩溃 |
| 浸泡测试 | 发现内存泄漏 | 恒定负载运行数小时 |
| 峰值测试 | 验证突发流量 | 短时间 10x 负载 |

## 2. 工具

### Locust（Python，推荐）

```python
from locust import HttpUser, task, between

class TaskFlowUser(HttpUser):
    wait_time = between(1, 3)

    def on_start(self):
        response = self.client.post("/api/v1/auth/login", json={
            "email": "test@example.com",
            "password": "password123"
        })
        self.token = response.json()["data"]["token"]

    @task(3)
    def list_tasks(self):
        self.client.get("/api/v1/tasks",
            headers={"Authorization": f"Bearer {self.token}"})

    @task(1)
    def create_task(self):
        self.client.post("/api/v1/tasks",
            json={"title": "Load test task"},
            headers={"Authorization": f"Bearer {self.token}"})
```

### k6（JavaScript）

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },  //  ramp up
    { duration: '5m', target: 100 },  //  steady
    { duration: '2m', target: 0 },    //  ramp down
  ],
  thresholds: {
    http_req_duration: ['p(99)<500'],  // p99 < 500ms
    http_req_failed: ['rate<0.01'],    // 错误率 < 1%
  },
};

export default function () {
  const res = http.get('http://localhost:8000/api/v1/tasks');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}
```

## 3. 压测流程

```
1. 确定目标
   SLO：p99 < 500ms，错误率 < 0.1%，1000 QPS

2. 准备环境
   Staging 环境（与生产配置一致）
   测试数据（足够量级）
   监控就绪（Grafana Dashboard）

3. 建立基准
   1 用户 → 10 用户 → 50 用户
   记录每个并发级别的 p50/p95/p99/错误率

4. 逐步加压
   100 → 200 → 500 → 1000 → 2000
   找到性能拐点（延迟急剧上升的点）

5. 分析瓶颈
   CPU 100%？→ 代码优化或加实例
   DB 连接满？→ 连接池或读写分离
   内存增长？→ 内存泄漏
   网络带宽？→ CDN 或压缩

6. 优化 → 重新压测 → 对比
```

## 4. 性能报告模板

```markdown
# 性能测试报告：TaskFlow API

## 目标
- p99 延迟 < 500ms
- 错误率 < 0.1%
- 支持 1000 QPS

## 环境
- 2 × 4C8G App Server
- PostgreSQL 16 (4C16G)
- Redis 7 (2C4G)

## 结果
| 并发用户 | QPS | p50 | p95 | p99 | 错误率 |
|---------|-----|-----|-----|-----|--------|
| 50      | 200 | 45ms| 80ms| 120ms| 0%    |
| 100     | 450 | 90ms| 180ms| 350ms| 0%   |
| 200     | 800 | 200ms| 450ms| 800ms| 0.1% |
| 500     | 1200| 500ms| 1200ms| 2500ms| 2% |

## 瓶颈
200 并发以上 p99 超标，瓶颈在 DB 连接池（max 20）

## 建议
1. 连接池扩大到 50
2. 任务列表加 Redis 缓存
3. 预期优化后 1000 QPS p99 < 400ms
```
