# 第 01 课：信息检索与搜索引擎基础

## 1. 核心问题

搜索引擎到底在解决什么问题？答案不是"找到包含关键词的文档"，
而是**从大量文档中找出与用户信息需求最相关的少量文档**。

## 2. 信息检索（IR）是什么

信息检索（Information Retrieval, IR）是研究"如何根据查询从文档集合中
找到相关信息"的学科。搜索引擎是 IR 最经典的产品形态。

四个基本要素：

| 要素 | 说明 | 例子 |
|------|------|------|
| 文档 Document | 被检索的最小单位 | 一篇网页、一个 PDF、一条 FAQ |
| 语料 Corpus | 全部文档的集合 | 公司全部 wiki 页面 |
| 查询 Query | 用户的信息需求表达 | "报销超过5000怎么处理" |
| 相关性 Relevance | 文档满足查询需求的程度 | 这篇文档有没有答案 |

## 3. 搜索与相关概念的区别

### 3.1 搜索 vs 推荐

- 搜索：用户**主动**表达需求（查询），系统找相关文档
- 推荐：用户**被动**接收，系统根据画像预测兴趣

搜索要求"可解释、可追溯"，推荐更关注"惊喜度"。

### 3.2 搜索 vs RAG

- 搜索：返回**文档列表**（用户自己看）
- RAG：搜索只是中间步骤，最终返回**模型生成的答案**

但 RAG 的检索部分几乎就是搜索引擎：
倒排索引、BM25、混合检索、重排——全部直接复用。

```
搜索：    Query → 检索 → 排序 → 文档列表
RAG：     Query → 检索 → 排序 → Top-K 文档 → Prompt → LLM 答案
                        ↑ 这一整段就是"搜索引擎"
```

## 4. 搜索的生命周期

```
┌────────── 离线（索引侧）──────────┐
│ 采集/导入 → 解析 → 文本处理 → 建立索引 │
└──────────────────────────────────┘
             │
┌────────── 在线（查询侧）──────────┐
│ Query → 分析 → 检索 → 排序 → 摘要 → 返回 │
└──────────────────────────────────┘
```

离线侧处理"文档"，在线侧处理"查询"，两侧都要做同样的**文本分析**，
否则查询词和文档词永远对不上（这是新人最容易踩的坑）。

## 5. 相关性的两个基本度量

### 5.1 查准率（Precision）

返回的结果里，有多少是相关的：

```text
Precision = 返回且相关 / 返回总数
```

### 5.2 查全率（Recall）

所有相关文档里，找回了多少：

```text
Recall = 返回且相关 / 全部相关文档数
```

两者天然矛盾：放宽条件 → 召回变多但精度下降；收紧 → 反过来。
搜索引擎的目标是在两者之间找平衡，并让**高相关的排前面**。

### 5.3 例子

语料有 100 篇文档，其中 10 篇与"报销"相关。系统返回 20 篇，其中 6 篇相关：

```text
Precision = 6/20 = 30%
Recall    = 6/10 = 60%
```

如果只返回 5 篇且全部相关：

```text
Precision = 100%，Recall = 50%
```

## 6. 搜索质量的三个层次

```
第一层：能不能搜到（检索/召回）——有没有把相关文档捞进来
第二层：排得对不对（排序）——相关的排前面
第三层：体验好不好（摘要/高亮/纠错）——用户愿不愿意点
```

大部分搜索问题出在第二层：相关文档都召回了，但排到了第 30 名。
这就是为什么排序（Ranking）是整个搜索系统的灵魂。

## 7. 搜索引擎的分类

| 类型 | 特点 | 例子 |
|------|------|------|
| 通用搜索 | 海量网页、链接分析 | Google、Bing |
| 站内搜索 | 单站内容、结构简单 | 博客搜索、文档站 |
| 垂直搜索 | 特定领域、强结构化 | 电商搜索、代码搜索 |
| 企业搜索 | 权限、多源、合规 | Elasticsearch 企业应用 |
| 语义搜索 | 向量 + 混合 | RAG 检索、问答 |

本课程以"站内/企业搜索 + 语义搜索"为主线，兼顾通用搜索的经典算法。
