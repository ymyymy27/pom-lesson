# 第 06 课：搜索引擎架构

## 1. 核心问题

单机小搜索引擎的流程很简单；支撑千万文档、低延迟、高可用的搜索系统，
架构上要解决什么？这一课给出一张完整的架构图。

## 2. 整体架构

```
┌────────────── 离线/准实时（索引侧）──────────────┐
│ 数据源 → 采集/同步 → 解析 → 文本分析 → 建立索引 → 索引存储 │
└────────────────────────────────────────────────┘
                      │ 发布
┌────────────── 在线（查询侧）────────────────────┐
│ Query → 分析 → 召回 → 排序 → 摘要/高亮 → 结果   │
│              ↑        ↑                        │
│           查询缓存   排序模型（BM25/向量/LTR）    │
└────────────────────────────────────────────────┘
```

## 3. 索引侧架构

### 3.1 数据接入

- 全量导入：首次/定期全量重建
- 增量同步：数据库 binlog、消息队列、定时抓取
- 文档去重：内容哈希，避免重复索引

### 3.2 解析与处理

不同格式转成统一文档模型：

```text
HTML/PDF/Word/Markdown → 纯文本 + 元数据（标题、作者、时间、URL）
```

### 3.3 索引构建

- 文本分析（第 2 课）
- 写入倒排索引（第 3 课）
- 可选：向量索引（第 5 课）
- 分段 + 合并（第 3 课）

### 3.4 索引发布

索引重建不能停服，用**双缓冲/版本切换**：

```
新索引构建完成 → 原子切换 → 旧索引下线
```

## 4. 查询侧架构

### 4.1 查询分析

```
原始查询
  → 归一化/分词
  → 纠错（"pthon" → "python"）
  → 改写/扩展（同义词）
  → 意图识别（可选：是搜文档还是搜商品？）
```

### 4.2 召回（Recall）

多路召回并行：

- 布尔/倒排召回（精确词）
- BM25 召回（词面相关）
- 向量召回（语义相关）
- 标签/过滤召回（类目、时间、权限）

### 4.3 排序（Rank）

```
粗排：BM25 + 向量融合（几百条 → 几十条）
精排：LTR / Cross-Encoder（几十条 → 十条）
重排：多样性、时效、商业规则
```

### 4.4 结果展示

- 摘要生成（命中词附近取片段）
- 关键词高亮
- 分页/游标（深分页很贵，用游标）

## 5. 缓存

| 缓存 | 缓存什么 | 命中效果 |
|------|---------|---------|
| 查询缓存 | 相同查询的分析结果 | 省分析成本 |
| 结果缓存 | 热门查询的完整结果 | 大幅降延迟 |
| 词项缓存 | 词项的倒排列表 | 省磁盘 IO |

注意：结果缓存要处理**新鲜度**（新文档发布后缓存失效策略）。

## 6. 分布式

数据量单机放不下时，做分片（Sharding）：

```text
分片策略：
  - 按文档 ID 哈希：写入均匀，查询要广播到所有分片
  - 按类目分片：查询路由到特定分片
  - 副本（Replica）：一份数据多副本，扛读流量
```

经典架构（Elasticsearch 就是这种）：

```
协调节点（接收查询、合并结果）
  → 数据节点1（分片A主+副本）
  → 数据节点2（分片B主+副本）
  → 汇总 Top-K（各分片取 Top-K，合并后再排序）
```

**各分片取 Top-K 再合并**是分布式搜索的关键：
全局 Top-K 必然在各分片 Top-K 之中（K 相同或更大）。

## 7. 高可用

- 副本故障转移
- 索引版本回滚
- 查询熔断（后端超时降级）
- 降级方案：精排挂了 → 用粗排结果；向量挂了 → 只用 BM25

## 8. 典型参数与量级

| 组件 | 量级参考 |
|------|---------|
| 倒排索引 | 原始文本的 30%~50%（含压缩） |
| 向量索引 | 每向量 768 维 float ≈ 3KB（HNSW 更高） |
| 查询延迟 | 粗排 P99 < 100ms，精排 < 300ms |
| 分片大小 | 每分片几十 GB 为宜 |
