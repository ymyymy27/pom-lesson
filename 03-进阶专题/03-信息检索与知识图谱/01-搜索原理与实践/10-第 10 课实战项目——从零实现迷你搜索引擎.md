# 第 10 课：实战项目——从零实现迷你搜索引擎

## 1. 项目目标

用纯 Python（不依赖第三方搜索引擎）实现一个可用的搜索引擎：

1. 中文分词（词典最大匹配 + 字符 bigram 兜底）
2. 倒排索引（词频、位置）
3. BM25 排序
4. 向量检索 + RRF 混合（可选 Ollama）
5. 评估：MRR / NDCG@K / Recall@K

## 2. 数据

`practice/data/corpus.txt`：12 篇中文短文（公司制度 + 技术文档），
每篇带 ID 和标题。

`practice/data/queries.tsv`：5 条带标注的查询（qrels），
格式：`查询词<TAB>相关文档ID（逗号分隔）`

## 3. 项目结构

```
practice/
├── data/
│   ├── corpus.txt        # 文档语料
│   └── queries.tsv       # 查询 + 相关标注
├── common.py             # 分词、加载、BM25 实现
├── 01_inverted_index.py  # 倒排索引构建与布尔查询
├── 02_bm25_search.py     # BM25 搜索 + 摘要
├── 03_hybrid_search.py   # BM25 + 向量 + RRF
├── 04_evaluate.py        # MRR/NDCG/Recall 评估
└── requirements.txt
```

## 4. 分步实施

### Step 1：分词器（common.py）

- 词典正向最大匹配
- 未登录词兜底：字符 bigram
- 停用词过滤（最小化，避免误伤）
- **文档和查询共用同一套分析管道**

### Step 2：倒排索引（01）

- term → [(doc_id, tf, positions)]
- 布尔 AND 查询
- 短语查询（位置连续）

### Step 3：BM25（02）

- 实现完整 BM25（k1、b、avgdl）
- 查询打分 → Top-K → 摘要（命中词附近片段）

### Step 4：混合检索（03）

- BM25 一路
- Embedding 一路（Ollama `qwen3-embedding:4b`，
  不可用则用 bigram 向量兜底）
- RRF 融合，对比单路效果

### Step 5：评估（04）

- 读 queries.tsv 标注
- 计算 MRR、NDCG@3、Recall@5
- 对比 BM25 vs 混合

## 5. 验收标准

- [ ] "报销超过5000怎么处理" 能搜到报销制度文档
- [ ] "远程办公政策" 能搜到远程办公文档
- [ ] "年假" 和 "休假" 至少一路能召回同一篇文档
- [ ] 混合检索 NDCG@3 不差于纯 BM25
- [ ] 布尔查询 AND 结果正确
- [ ] 所有脚本无第三方搜索依赖可运行

## 6. 扩展方向

1. **换真实产品**：把同样的数据导入 Elasticsearch，
   对比 mapping 配置和搜索结果
2. **加同义词**：维护同义词表，看召回变化
3. **加精排**：Cross-Encoder 对 Top-20 重排
4. **接 RAG**：把本项目的检索结果喂给 LLM，
   就是你自己从零搭的 RAG 检索层
5. **加新鲜度**：时间字段参与排序

## 7. 最终自测

1. 倒排索引为什么快？布尔查询怎么工作？
2. BM25 的 k1、b 各控制什么？怎么调？
3. 向量检索解决什么问题？RRF 为什么不用分数归一化？
4. 怎么设计一个 50 条查询的评估集？用什么指标？
5. 如果线上"搜不到"，你的排查顺序是什么？
