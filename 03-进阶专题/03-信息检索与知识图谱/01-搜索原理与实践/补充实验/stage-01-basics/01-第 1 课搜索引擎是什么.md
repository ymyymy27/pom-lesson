# 第 1 课：搜索引擎是什么？

## 一句话解释

搜索引擎是一套「在海量文档中，根据用户的查询，快速找出最相关结果」的系统。

## 类比：图书馆检索员

你走进图书馆，想找「讲数据库索引的书」。你不会从第一排书开始一本本翻（那是全表扫描），而是去查目录卡片：卡片按主题组织，很快告诉你哪几个书架、哪几本书提到「数据库索引」。然后你根据出版时间、内容简介等挑最合适的。

- 书 = 文档（网页、商品、工单……）
- 目录卡片 = 倒排索引
- 你挑书的标准 = 相关性排序

## 一次搜索的完整旅程

```mermaid
flowchart LR
    A[用户输入查询] --> B[查询分析\n分词/纠错/同义词]
    B --> C[查倒排索引\n找出候选文档]
    C --> D[相关性打分\nBM25 等]
    D --> E[结果展示\n高亮/分页]
    E --> F[用户反馈\n点击/评价]
    F --> G[调优排序与索引]
```

分两条线理解：

1. 离线索引线：收集文档 → 分词 → 构建倒排索引（可以提前慢慢做）
2. 在线查询线：收到查询 → 分析 → 查索引 → 打分 → 返回（必须毫秒级）

## 为什么不用数据库的 LIKE？

| 对比项 | LIKE '%词%' | 搜索引擎 |
|--------|-------------|----------|
| 速度 | 扫描每一行 | 查索引，快 |
| 相关性 | 只会包含/不包含 | 能排序、加权 |
| 拼写/同义词 | 不支持 | 支持 |
| 中文分词 | 按字符匹配 | 按语义切词 |

数据库索引适合「精确查询」（id = 123），搜索引擎适合「模糊、多词、按相关度排序」的查询。两者配合使用，而不是互相替代。

## 动手：运行你的第一个搜索程序

文件：`practice/01_inverted_index.py`

```bash
cd 03-进阶专题/03-信息检索与知识图谱/01-搜索原理与实践/补充实验/practice
python 01_inverted_index.py
```

你会看到：

1. 倒排索引的示例——每个词出现在哪些文档；
2. 两次查询的 BM25 相关性分数——即使同一篇文档，不同查询的分数不同；
3. 布尔 AND 的结果——哪些文档同时包含所有查询词。

这个程序只有两个核心部分：`build_index`（建索引）和 `bm25`（打分）。
