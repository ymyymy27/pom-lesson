# 知识图谱术语与语法参考

> 本文档梳理知识图谱工程中的核心概念、两种主流数据模型、查询语言与工具选型。建议配合 `01-第1课知识图谱基础 — 概念与应用场景.md` 一起阅读。

---

## 1. 核心术语

| 术语 | 英文 | 含义 |
|------|------|------|
| 知识图谱 | Knowledge Graph (KG) | 用图结构组织实体及其关系的知识库 |
| 实体 | Entity / Node | 现实世界中的对象，如人、公司、产品 |
| 关系 | Relation / Edge | 实体之间的语义连接，如「就职于」「属于」 |
| 属性 | Property / Attribute | 实体或关系的键值描述，如 `name: "张三"` |
| 三元组 | Triple | `(主语, 谓语, 宾语)`，如 `(张三, 就职于, 阿里巴巴)` |
| 本体 | Ontology | 概念层：定义有哪些类型、关系及其约束 |
| Schema | Schema | 工程层：Node Label、Relation Type、属性字段的实际定义 |
| 实体链接 | Entity Linking | 将文本中的 mention 对齐到图谱中已有实体 |
| 实体对齐 | Entity Alignment | 合并不同来源的同一实体（消歧 / 融合） |
| 知识融合 | Knowledge Fusion | 多源数据合并、冲突消解、置信度加权 |

## 2. 两种主流数据模型

```
属性图 (Property Graph)          RDF 三元组模型
─────────────────────────        ─────────────────────────
(张三:Person)                    <张三> rdf:type <Person>
  │ name: "张三"                   <张三> <name> "张三"
  │ age: 30                        <张三> <worksAt> <阿里巴巴>
  └─[:WORKS_AT {since:2020}]─→     <阿里巴巴> rdf:type <Company>
       (阿里巴巴:Company)
  name: "阿里巴巴"
```

| 维度 | 属性图 (Neo4j, NebulaGraph) | RDF (Apache Jena, GraphDB) |
|------|----------------------------|----------------------------|
| 查询语言 | Cypher, nGQL | SPARQL |
| 关系能否带属性 | ✅ 可以 | ⚠️ 需 reification 或 named graph |
| 工程生态 | AI/RAG 集成丰富 | 语义 Web、标准本体强 |
| 典型场景 | 企业知识库、推荐、Graph RAG | 学术本体、政府开放数据 |
| 本课程默认 | **Neo4j 属性图** | 第 2 课对比了解即可 |

## 4. Cypher 语法速查（Neo4j）

### 4.1 创建

```cypher
// 节点 + 关系
CREATE (p:Person {id: 'p1', name: '张三'})
CREATE (c:Company {id: 'c1', name: '阿里巴巴'})
CREATE (p)-[:WORKS_AT {since: 2020}]->(c)
```

### 4.2 查询

```cypher
// 模式匹配
MATCH (p:Person {name: '张三'})-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name, p.age

// 可变长度路径（多跳）
MATCH (p:Person {name: '张三'})-[:REPORTS_TO*1..3]->(boss:Person)
RETURN boss.name

// 聚合
MATCH (c:Company)<-[:WORKS_AT]-(p:Person)
RETURN c.name, count(p) AS headcount
ORDER BY headcount DESC
```

### 4.3 更新与删除

```cypher
MATCH (p:Person {id: 'p1'})
SET p.title = '高级工程师', p.updated_at = datetime()

MATCH (p:Person {id: 'p1'})-[r:WORKS_AT]->()
DELETE r

// 删除节点需先删关系
MATCH (p:Person {id: 'p1'}) DETACH DELETE p
```

### 4.4 索引与约束

```cypher
CREATE CONSTRAINT person_id IF NOT EXISTS
FOR (p:Person) REQUIRE p.id IS UNIQUE;

CREATE INDEX person_name IF NOT EXISTS
FOR (p:Person) ON (p.name);
```

## 5. Python neo4j 驱动速查

```python
from neo4j import GraphDatabase

driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "changeme"))

def run_query(query: str, **params):
    with driver.session() as session:
        result = session.run(query, **params)
        return [record.data() for record in result]

# 参数化查询（防注入）
rows = run_query(
    "MATCH (p:Person {name: $name}) RETURN p",
    name="张三",
)
```

## 6. 技术选型速查

| 环节 | 推荐（本课程） | 替代方案 |
|------|----------------|----------|
| 图数据库 | Neo4j Community | NebulaGraph、Amazon Neptune |
| 抽取（原型） | LLM + Instructor/JSON Schema | spaCy NER + 规则 |
| 抽取（生产） | 专用 NER 模型 + LLM 复核 | OpenIE、UIE |
| 流水线调度 | Celery / Airflow | Prefect、Dagster |
| 向量混合 | ChromaDB + Neo4j | Milvus + Neo4j |
| 可视化 | Neo4j Browser、Bloom | G6、Cytoscape.js |
| Schema 管理 | Git 版控 YAML/JSON | Protégé（RDF 本体） |

## 7. 与关系型数据库的对比

| 特性 | PostgreSQL | 知识图谱 (Neo4j) |
|------|------------|------------------|
| 核心抽象 | 表 + 行 | 节点 + 关系 |
| 多跳关联查询 | JOIN 多层，性能下降 | 原生图遍历，路径高效 |
| Schema 灵活度 | 固定表结构 | Label/Relation 可扩展 |
| 事务 | 完整 ACID | Neo4j 支持 ACID（Enterprise 集群更强） |
| 适用 | 业务主数据、报表 | 关系推理、知识检索、推荐 |

**结论：** 图谱通常**不替代**业务主库，而是从主库、文档等**同步构建**，服务于检索与推理场景。
