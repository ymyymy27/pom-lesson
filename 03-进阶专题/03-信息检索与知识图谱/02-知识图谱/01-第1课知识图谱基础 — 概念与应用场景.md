# 第1课：知识图谱基础 — 概念与应用场景

## 1. 知识图谱是什么？

### 一句话解释

**知识图谱 = 用「节点 + 关系」组织事实的结构化知识库**，让机器能表达「张三就职于阿里巴巴，阿里巴巴位于杭州」这类关联，并支持多跳推理。

### 类比理解

| 日常概念 | 知识图谱概念 |
|---------|-------------|
| 人物关系网 | 实体 + 社交关系 |
| 公司组织架构图 | Person → Department → Company |
| 维基百科内链 | 实体链接 + 跨文档关系 |
| Excel 多表关联 | 图上的路径遍历（无需多层 JOIN） |

### 知识图谱 vs 向量数据库

| 维度 | 向量库 | 知识图谱 |
|------|--------|----------|
| 存储单元 | 文本 chunk + embedding | 实体 + 关系 + 属性 |
| 擅长 | 语义相似检索 | 精确关系、多跳推理 |
| 模糊匹配 | ✅ 强 | 需实体链接辅助 |
| 可解释性 | 较低（黑盒相似度） | 较高（路径可追溯） |
| 维护成本 | 低 | 需 Schema + 抽取流水线 |

**2026 生产趋势：** 向量库与知识图谱**并存**，Hybrid 检索成为 RAG 标配（详见 [`stage-08-rag/06-graph-rag.md`](<../../../02-方向选修/02-AI应用/参考资料/04-RAG/06-Graph RAG向量检索 + 知识图谱.md>)）。

## 2. 知识图谱的六大应用场景

```
┌────────────────────────────────────────────────────────┐
│              知识图谱典型应用                            │
├────────────────────────────────────────────────────────┤
│ 1. 智能问答    — 多跳关系查询（「张三上司的部门项目」）  │
│ 2. 搜索增强    — 实体卡片、关联推荐、Query 理解         │
│ 3. 推荐系统    — 用户-物品-标签 图传播                  │
│ 4. 风控反欺诈  — 账户-设备-交易 异常子图检测            │
│ 5. 研发效能    — 代码-服务-依赖 影响分析                │
│ 6. 企业知识库  — 文档实体化 + Graph RAG                 │
└────────────────────────────────────────────────────────┘
```

### 场景决策：你需要知识图谱吗？

```
你的核心问题是「找语义相似的文本」？
  ├─ 是 → 向量 RAG 通常足够
  └─ 否 → 继续

问题涉及 2 跳以上的实体关系？
  ├─ 是 → 知识图谱价值高
  └─ 否 → 关系型 DB + 缓存可能够用

实体和关系能否稳定定义（Schema 可维护）？
  ├─ 是 → 适合建图谱
  └─ 否 → 先整理业务概念，再考虑图谱

数据是否持续更新、需增量同步？
  ├─ 是 → 必须规划工程化流水线（本课第 6 课）
  └─ 否 → 可一次性构建 MVP
```

   ↓

## 4. 一个最小可运行示例（概念）

假设我们要构建「公司内部人员-项目」知识图谱：

```
(张三:Person {name:"张三"})
    │
    ├──[:MEMBER_OF]──→ (研发一部:Department)
    │                        │
    │                        └──[:BELONGS_TO]──→ (技术中心:Org)
    │
    └──[:WORKS_ON {role:"后端"}]──→ (订单系统:Project)
                                           │
                                           └──[:OWNED_BY]──→ (李四:Person)
```

对应 Cypher（第 5 课详讲）：

```cypher
CREATE (p:Person {name: '张三'})
CREATE (d:Department {name: '研发一部'})
CREATE (proj:Project {name: '订单系统'})
CREATE (p)-[:MEMBER_OF]->(d)
CREATE (p)-[:WORKS_ON {role: '后端'}]->(proj)
```

查询：「张三参与的项目有哪些？」

```cypher
MATCH (p:Person {name: '张三'})-[:WORKS_ON]->(proj:Project)
RETURN proj.name
```

## 5. 常见失败模式（工程视角）

| 失败模式 | 表现 | 预防 |
|---------|------|------|
| Schema 膨胀 | 上百种 Label，无人维护 | 第 2 课：分层 Schema + 版本管理 |
| 抽取即垃圾 | 错误实体大量入库 | 第 4、7 课：置信度阈值 + 人工复核 |
| 一次性工程 | 上线后无法增量更新 | 第 6 课：流水线 + 幂等写入 |
| 图谱孤岛 | 建了没人用 | 第 8、9 课：API + RAG 集成 |
| 性能瓶颈 | 多跳查询超时 | 第 5 课：索引 + 查询深度限制 |
