## 1. 抽取任务定义

```
输入：文本 chunk + Schema 定义
输出：
{
  "entities": [
    {"id": "e1", "label": "Person", "name": "张三", "confidence": 0.95}
  ],
  "relations": [
    {"type": "WORKS_AT", "from": "e1", "to": "e2", "confidence": 0.88}
  ]
}
```

### 抽取质量维度

| 维度 | 说明 | 目标 |
|------|------|------|
| 准确率 (Precision) | 抽出来的对不对 | > 90%（核心关系） |
| 召回率 (Recall) | 该抽的是否都抽到 | 视场景 70–95% |
| 一致性 | 同实体多次 mention 是否统一 | 依赖实体链接 |
| 覆盖率 | Schema 中 Relation 的填充比例 | 监控仪表盘 |

---

## 2. 三种抽取路径对比

| 路径 | 工具/方法 | 优点 | 缺点 | 适用阶段 |
|------|-----------|------|------|----------|
| 规则 + 词典 | 正则、关键词、模板 | 快、可控、零成本 | 泛化差 | 结构化句式、固定格式 |
| NLP 管道 | spaCy NER、UIE | 速度中等、可离线 | 需训练数据 | 中等规模、领域固定 |
| LLM 抽取 | GPT-4 / 本地模型 + JSON Schema | 泛化强、快速原型 | 成本、幻觉、延迟 | 原型、复杂句式、低频关系 |

**生产推荐：** **规则兜底 + NLP/LLM 主抽 + 人工复核** 三层架构。

## 3. LLM 结构化抽取（快速原型）

### 3.1 Prompt + JSON Schema

```python
import json
from openai import OpenAI

EXTRACT_SYSTEM = """你是知识图谱抽取助手。严格按 Schema 输出 JSON。
只抽取文本中明确提到的实体和关系，不要推测。
实体 label 只能是：Person, Company, Department, Project。
关系 type 只能是：WORKS_AT, MEMBER_OF, WORKS_ON, REPORTS_TO。"""

EXTRACT_USER = """文本：
{text}

输出格式：
{{"entities": [{{"label": str, "name": str, "temp_id": str}}],
  "relations": [{{"type": str, "from_temp_id": str, "to_temp_id": str}}]}}"""

def extract_with_llm(text: str, client: OpenAI, model: str = "gpt-4o-mini") -> dict:
    resp = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": EXTRACT_SYSTEM},
            {"role": "user", "content": EXTRACT_USER.format(text=text)},
        ],
        response_format={"type": "json_object"},
        temperature=0,
    )
    return json.loads(resp.choices[0].message.content)
```

### 3.2 降低幻觉的技巧

| 技巧 | 说明 |
|------|------|
| `temperature=0` | 减少随机性 |
| JSON Schema / Instructor | 强制输出结构 |
| 引用溯源 | 要求返回 `source_span` 原文片段 |
| 置信度自评 | LLM 输出 confidence，低于阈值不入库 |
| 小 chunk | 单 chunk 控制在 500–1500 字 |

```python
# 带溯源的抽取字段
{"name": "张三", "source_span": "张三于2020年加入研发一部", "confidence": 0.92}
```

## 4. spaCy NER 管道（离线方案）

```python
import spacy

nlp = spacy.load("zh_core_web_sm")  # 或 en_core_web_sm

def extract_entities_spacy(text: str) -> list[dict]:
    doc = nlp(text)
    return [
        {"name": ent.text, "label": ent.label_, "start": ent.start_char, "end": ent.end_char}
        for ent in doc.ents
    ]
```

**局限：** 通用 NER 的 Label（PER/ORG）与业务 Schema（Person/Project）不一致，需**映射表**：

```python
SPACY_TO_SCHEMA = {
    "PERSON": "Person",
    "ORG": "Company",
}
```

关系抽取可叠加**模式规则**：

```python
RELATION_PATTERNS = [
    (r"(.+?)就职于(.+?)", "WORKS_AT"),
    (r"(.+?)负责(.+?)项目", "WORKS_ON"),
]
```

## 5. 实体链接与对齐

### 5.1 问题

```
文本 mention     图谱已有实体
────────────     ──────────────
"小张"      →    Person {name: "张三", id: "p001"} ?
"阿里"      →    Company {name: "阿里巴巴"} ?
"张三"      →    两个同名 Person 选哪个？
```

### 5.2 链接策略（按优先级）

```
1. 精确 ID 匹配（结构化数据已有 id）
2. 唯一属性匹配（email、工号）
3. 模糊名匹配 + 上下文消歧（部门、同事共现）
4. Embedding 相似度（实体名 + 描述向量）
5. 人工复核队列（置信度 < 阈值）
```

```python
def link_entity(mention: str, label: str, context: dict, graph) -> str | None:
    # 唯一 email 匹配
    if email := context.get("email"):
        hit = graph.run(
            "MATCH (p:Person {email: $email}) RETURN p.id AS id",
            email=email,
        ).single()
        if hit:
            return hit["id"]

    # 同名消歧：同部门优先
    candidates = graph.run(
        """
        MATCH (p:Person {name: $name})-[:MEMBER_OF]->(d:Department {name: $dept})
        RETURN p.id AS id LIMIT 1
        """,
        name=mention, dept=context.get("department"),
    ).single()
    return candidates["id"] if candidates else None
```

### 5.3 实体融合（多源同一实体）

```
hr_db:     Person {id: hr_001, name: "张三", email: "zhang@co.com"}
doc_extract: Person {id: ext_99, name: "张三", title: "高级工程师"}

融合后：
  Person {id: "p001", name: "张三", email: "...", title: "...", sources: ["hr_db","doc_extract"]}
```

使用 `MERGE` + 属性优先级规则（HR 数据优先于文档抽取）。

## 6. 抽取结果写入 Staging

```python
def write_staging(session, entities, relations):
    session.run("""
        UNWIND $entities AS e
        MERGE (n:Staging {temp_id: e.temp_id})
        SET n += e, n.status = 'pending_review'
    """, entities=entities)

    session.run("""
        UNWIND $relations AS r
        MATCH (a:Staging {temp_id: r.from_temp_id})
        MATCH (b:Staging {temp_id: r.to_temp_id})
        MERGE (a)-[rel:STAGING_REL {type: r.type}]->(b)
        SET rel.confidence = r.confidence
    """, relations=relations)
```

## 7. 评估与迭代

### 7.1 黄金测试集

```
tests/golden/
├── sample_001.txt      # 输入文本
├── sample_001.expected.json  # 期望实体关系
└── ...
```

```python
def evaluate_extraction(predicted, expected):
    pred_triples = {(r["type"], r["from"], r["to"]) for r in predicted["relations"]}
    exp_triples = {(r["type"], r["from"], r["to"]) for r in expected["relations"]}
    precision = len(pred_triples & exp_triples) / len(pred_triples) if pred_triples else 0
    recall = len(pred_triples & exp_triples) / len(exp_triples) if exp_triples else 0
    return {"precision": precision, "recall": recall}
```

### 7.2 CI 门禁

抽取模型或 Prompt 变更后，黄金集 Precision/Recall 不得低于基线 -2%。
