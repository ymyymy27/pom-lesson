本课将知识图谱从「本地 Docker」推进到**可运维的生产系统**，覆盖部署拓扑、备份、监控与团队规范。

## 1. 部署架构选型

### 1.1 小规模（< 100 万节点）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Graph API  │────→│   Neo4j     │     │  Redis      │
│  (FastAPI)  │     │  Community  │     │  (缓存)     │
└─────────────┘     └─────────────┘     └─────────────┘
       │
┌─────────────┐
│  Pipeline   │───→ Neo4j (batch MERGE)
│  Worker     │
└─────────────┘
```

Docker Compose 即可（见 `practice/docker-compose.yml`）。

### 1.2 中大规模（100 万 – 1000 万节点）

```
                    ┌── Neo4j Core 1 ──┐
Graph API × N ─────→├── Neo4j Core 2 ──┤  Causal Cluster (Enterprise)
                    └── Neo4j Read Replica ──→ 只读查询
Pipeline ──────────→ Core (write)
Kafka ─────────────→ 增量事件
```

| 组件 | 小规模 | 中大规模 |
|------|--------|----------|
| Neo4j | Community 单实例 | Enterprise 集群 + Read Replica |
| 向量库 | ChromaDB 嵌入式 | Milvus / Qdrant 集群 |
| 流水线 | Cron + Python | Airflow + K8s Job |
| 缓存 | 本地 Redis | Redis Cluster |

### 1.3 云托管选项

| 服务 | 说明 |
|------|------|
| Neo4j AuraDB | 全托管，免运维 |
| Amazon Neptune | AWS 生态 |
| 自建 K8s | 成本可控、运维复杂 |

## 2. 环境隔离

```
优先级（从高到低）：

1. 不同环境 → 不同 Neo4j 实例 / Aura 实例
   dev / staging / prod 绝不共用

2. 同一实例内 → 不同 database（Neo4j 4.0+）
   kg_dev / kg_staging / kg_prod

3. 连接配置 → 环境变量，禁止硬编码
   NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD, NEO4J_DATABASE
```

`.env.example`：

```bash
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=changeme
NEO4J_DATABASE=kg_dev
REDIS_URL=redis://localhost:6379/0
KG_ENV=development
```

## 3. 备份与恢复

### 3.1 Neo4j 备份

```bash
# Enterprise: neo4j-admin backup
# Community: 停库后备份 data 目录 volume

docker compose stop neo4j
tar -czf neo4j-backup-$(date +%Y%m%d).tar.gz ./neo4j/data
docker compose start neo4j
```

### 3.2 恢复演练

**每月一次**恢复演练到 staging，验证备份可用。

### 3.3 Schema + 数据双备份

| 内容 | 方式 | 频率 |
|------|------|------|
| 图数据 | neo4j-admin / volume snapshot | 每日 |
| Schema YAML | Git | 每次变更 |
| 流水线水位线 | PostgreSQL meta 表 | 实时 |

## 4. 监控与告警

### 4.1 Neo4j 关键指标

| 指标 | 告警阈值 | 说明 |
|------|----------|------|
| `dbms.transaction.total` | 异常飙升 | 写入压力 |
| 堆内存使用率 | > 85% | OOM 风险 |
| 查询延迟 P95 | > 2s | 需优化 Cypher/索引 |
| 磁盘使用 | > 80% | 扩容 |
| 集群 leader 切换 | 频繁 | 网络/节点问题 |

### 4.2 应用层指标

```python
# Prometheus 示例
kg_api_requests_total.labels(endpoint="/v1/persons", status="200").inc()
kg_query_duration_seconds.labels(query="subgraph").observe(elapsed)
kg_pipeline_last_success_timestamp.set(time.time())
```

### 4.3 健康检查

```python
@app.get("/health")
def health():
    try:
        with driver.session() as s:
            s.run("RETURN 1").single()
        return {"status": "ok", "neo4j": "connected"}
    except Exception as e:
        return JSONResponse({"status": "degraded", "error": str(e)}, status_code=503)
```

## 5. 性能与容量规划

### 5.1 内存估算（经验）

```
图数据内存 ≈ 节点数 × 平均属性大小 × 1.5（索引开销）
关系内存 ≈ 关系数 × 平均属性 × 1.2

例：100 万 Person + 500 万 WORKS_ON
    → 规划 8–16 GB heap（视属性复杂度）
```

### 5.2 查询 SLA

| 查询类型 | 目标 P95 |
|----------|-----------|
| 单实体详情 | < 100 ms |
| 一度邻居 | < 200 ms |
| 2–3 跳子图 | < 1 s |
| 全图分析 | 离线批处理 |

## 6. 安全 checklist

```
□ prod Bolt 仅内网 / TLS
□ 密码轮换（90 天）
□ Graph API 认证（JWT / API Key）
□ Pipeline 写账号 vs API 读账号分离
□ Cypher 注入防护（参数化）
□ NL2Cypher 禁止写操作
□ 敏感属性脱敏（PII）
□ 审计日志保留 ≥ 90 天
```

## 8. 故障 playbook

| 现象 | 排查 | 处理 |
|------|------|------|
| API 503 | `/health`、Neo4j 日志 | 重启 /  failover |
| 查询超时 | `PROFILE` 慢查询 | 加索引、降 depth |
| 数据不一致 | 对比源端 ID 集 | 重跑 pipeline |
| 抽取质量骤降 | 黄金集 eval | 回滚 Prompt/模型 |
| 磁盘满 | 日志 + 事务日志 | 清理 + 扩容 |
