# 第1课：Neo4j 基础 — 核心概念与安装

## 1. Neo4j 是什么？

### 一句话解释

**Neo4j 就是「专门存关系的原生图数据库」** —— 用节点和边组织数据，多跳关联查询高效，常用于知识图谱、推荐、风控和社交网络。

### 类比理解

| 日常概念 | Neo4j 概念 |
|---------|-----------|
| 人物 | **Node**（节点） |
| 人物之间的关系（同事、汇报） | **Relationship**（有向边） |
| 人物的姓名、年龄 | **Property**（属性） |
| 人物 / 公司 / 项目等分类 | **Label**（标签） |

### Neo4j vs PostgreSQL

| 特性 | PostgreSQL | Neo4j |
|------|-----------|-------|
| 核心抽象 | 表 + 行 | 节点 + 关系 |
| 多跳关联 | 多层 JOIN，性能下降 | 原生图遍历 |
| 查询语言 | SQL | Cypher |
| Schema | 固定表结构 | Label/Relation 可扩展 |
| 事务 | 完整 ACID | ACID（Community 单实例） |
| 适用 | 业务主数据、报表 | 关系推理、路径查询、知识检索 |

**结论：** Neo4j 通常**不替代**关系库，而是与之配合——PostgreSQL 存权威业务数据，Neo4j 存**关系密集**或**需要图遍历**的数据。

## 3. 属性图模型

```
        (张三:Person)
         │ name: "张三"
         │ title: "工程师"
         │
         │ [:MEMBER_OF]
         ↓
    (研发一部:Department)
         │ name: "研发一部"
         │
         │ [:BELONGS_TO]
         ↓
    (示例科技:Company)
         name: "示例科技"
```

| 元素 | 说明 | 示例 |
|------|------|------|
| **Node** | 实体，可有多个 Label | `:Person:Employee` |
| **Relationship** | 有方向的连接，有类型 | `-[:WORKS_ON {role:'后端'}]->` |
| **Property** | 节点或关系上的键值 | `name: '张三'` |

关系**必须有类型**且**有方向**；反向查询时用 `<-` 或无方向 `-`。

## 4. 安装 Neo4j（Docker 方式，推荐）

```bash
cd 03-进阶专题/03-信息检索与知识图谱/04-Neo4j/practice
docker compose up -d
```

**验证连接：**

```powershell
# 方式 1：cypher-shell（推荐）
docker exec learn-neo4j cypher-shell -u neo4j -p changeme "RETURN 1 AS ok"

# 方式 2：浏览器
# 打开 http://localhost:7474
# 连接 URI: neo4j://localhost:7687
# 用户名: neo4j  密码: changeme
```

> Windows 无需本机安装 Neo4j，全部在 Docker 容器内运行。  
> 容器名 `learn-neo4j`；Bolt 端口 `7687`，Browser 端口 `7474`。

停止：`docker compose down`（加 `-v` 清空数据卷）

## 5. 第一次操作

在 Browser 或 cypher-shell 中执行：

```cypher
// 创建节点和关系
CREATE (p:Person {name: 'Alice'})
CREATE (c:Company {name: 'Acme Corp'})
CREATE (p)-[:WORKS_AT {since: 2024}]->(c);

// 查询
MATCH (p:Person)-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name, p.name + ' works at ' + c.name AS sentence;

// 清理（练习后可选）
MATCH (n) DETACH DELETE n;
```

**可视化：** Browser 结果区切换到 Graph 视图，可拖拽节点查看结构。

## 6. 核心概念

- **Label**：节点分类，类似「表名」但可多个；查询时 Label 过滤走索引
- **Relationship Type**：关系名，全大写+下划线是惯例（`WORKS_AT`）
- **Property**：键值对；复杂对象建议 JSON 字符串或拆节点
- **Bolt 协议**：应用连接用 `bolt://localhost:7687`，非 HTTP
- **Database**：Neo4j 4.0+ 单实例可有多库 → 详见 [第8课](08-第8课逻辑数据库与环境隔离.md)
- **Cypher**：声明式查询语言 → 详见 [第3课](<03-第3课Cypher 增删改查.md>)
