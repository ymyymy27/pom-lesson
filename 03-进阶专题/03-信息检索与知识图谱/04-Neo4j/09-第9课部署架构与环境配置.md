## 1. 部署形态对比

| 形态 | 适用 | 优点 | 缺点 |
|------|------|------|------|
| **Docker 单容器** | 本地/CI/小规模 | 简单、与课程一致 | 需自管备份与高可用 |
| **Docker Compose** | 小团队 dev/staging | 一键 APOC、卷持久化 | 单机 |
| **Neo4j AuraDB** | 生产/免运维 | 托管、自动备份 | 成本、网络延迟 |
| **K8s + Helm** | 大规模自建 | 弹性、可观测 | 运维复杂 |
| **Neo4j Enterprise 集群** | 大型生产 | 因果集群、读写分离 | 许可证 |

## 2. Docker Compose 生产向调整

本课程 `practice/docker-compose.yml` 是基础版；生产需补充：

```yaml
services:
  neo4j:
    image: neo4j:5.26-community
    restart: unless-stopped
    ports:
      - "7474:7474"
      - "7687:7687"
    environment:
      NEO4J_AUTH: neo4j/${NEO4J_PASSWORD}
      NEO4J_server_memory_heap_initial__size: 512m
      NEO4J_server_memory_heap_max__size: 2G
      NEO4J_server_memory_pagecache_size: 1G
      NEO4J_dbms_security_procedures_unrestricted: apoc.*
    volumes:
      - neo4j_data:/data
      - neo4j_logs:/logs
      - ./import:/import
    healthcheck:
      test: ["CMD", "cypher-shell", "-u", "neo4j", "-p", "${NEO4J_PASSWORD}", "RETURN 1"]
      interval: 30s
      timeout: 10s
      retries: 3
```

| 配置项 | 说明 |
|--------|------|
| `heap_max` | JVM 堆，复杂查询/大事务 |
| `pagecache` | 图数据缓存，建议 ≈ 数据集可缓存部分 |
| `restart` | 异常自动拉起 |
| `/import` | LOAD CSV 目录 |

## 3. 内存规划（经验值）

```
总 RAM
├── 50% — OS page cache（Neo4j 依赖 OS 缓存）
├── heap_max — 查询执行、事务状态
└── pagecache — Neo4j 显式页缓存（配置项）
```

**起步参考（小型图谱 < 100 万节点）：**

- heap: 512m – 2G
- pagecache: 512m – 2G

监控后再调；过大 heap 会导致 GC 停顿。

## 4. 安全

| 项 | 开发 | 生产 |
|----|------|------|
| 默认密码 | 可固定 `changeme` | 强密码 + 轮换 |
| Bolt 暴露 | localhost | 内网 / VPN / TLS |
| Browser 7474 | 可开放 | 禁止公网或加反向代理认证 |
| 备份文件 | 本地 | 加密存储 |
| APOC | 限制 `unrestricted` | 白名单过程 |

```yaml
# 启用 Bolt TLS（示意）
NEO4J_server_bolt_tls__level: REQUIRED
```

Aura 默认 TLS；自建需配置证书。

## 5. Neo4j Aura（云托管）

1. [console.neo4j.io](https://console.neo4j.io) 创建 Free/Professional 实例
2. 获取 `neo4j+s://xxx.databases.neo4j.io` 连接串
3. 应用环境变量：

```bash
NEO4J_URI=neo4j+s://xxxx.databases.neo4j.io
NEO4J_USER=neo4j
NEO4J_PASSWORD=<aura-generated>
```

`neo4j+s` 表示加密 Bolt；驱动无需改代码。

## 6. 备份概览

| 方式 | 命令/工具 | 场景 |
|------|-----------|------|
| **在线 dump** | `neo4j-admin database dump` | 定期全量 |
| **load** | `neo4j-admin database load` | 还原 |
| **Aura** | 控制台自动快照 | 托管环境 |
| **卷快照** | 云盘 snapshot | 需停写或配合 dump |

```bash
docker exec learn-neo4j neo4j-admin database dump neo4j --to-path=/backups
```

**注意：** Community 备份需在维护窗口或使用 dump；详细运维见第 10 课。

## 7. 多环境配置矩阵

| 环境 | 实例 | Database | 备份 |
|------|------|----------|------|
| local | Docker | `neo4j` | 无 |
| dev | 共享 Docker | `org_dev` |  weekly dump |
| staging | 独立 VM | `neo4j` | daily dump |
| prod | Aura / Enterprise | `neo4j` | 自动 + 异地 |

应用只通过环境变量切换，代码无硬编码 URI。

## 8. 动手练习

1. 调整 compose 中 `heap_max` / `pagecache`，`docker compose up -d` 后 `docker logs` 确认启动
2. 注册 Aura Free，用 cypher-shell 或 Python 连接一次（可选）
3. 执行一次 `neo4j-admin database dump`（容器内），列出备份文件
