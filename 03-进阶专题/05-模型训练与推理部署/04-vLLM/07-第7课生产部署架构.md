## 1. 生产架构全景

```
                    ┌─────────────┐
  客户端 ──────────→│  API 网关    │  认证、限流、路由
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ vLLM #1  │ │ vLLM #2  │ │ vLLM #3  │  模型副本 / 多模型
        └──────────┘ └──────────┘ └──────────┘
              │            │            │
              └────────────┼────────────┘
                           ▼
                    ┌─────────────┐
                    │ Prometheus  │  指标 + 告警
                    └─────────────┘
```

典型组件：
- **网关层**：Nginx / Kong / 自研 FastAPI（stage-11）
- **推理层**：vLLM OpenAI Server
- **观测层**：Prometheus + Grafana
- **模型存储**：HuggingFace Cache / S3 / PVC

## 2. Docker 生产配置

```yaml
# practice/docker-compose.yml
services:
  vllm:
    image: vllm/vllm-openai:latest
    restart: unless-stopped
    ports:
      - "8000:8000"
    volumes:
      - hf_cache:/root/.cache/huggingface
    environment:
      - HF_HOME=/root/.cache/huggingface
      - VLLM_LOGGING_LEVEL=INFO
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    command: >
      --model Qwen/Qwen2.5-7B-Instruct
      --dtype auto
      --max-model-len 4096
      --gpu-memory-utilization 0.9
      --max-num-seqs 128
      --enable-prefix-caching
      --served-model-name qwen-7b
      --api-key ${VLLM_API_KEY:-changeme}

volumes:
  hf_cache:
```

### 生产 Checklist

```
□ restart: unless-stopped
□ healthcheck 指向 /health
□ 模型 cache 持久化 volume
□ api-key 从环境变量注入，不写死在 compose
□ gpu-memory-utilization ≤ 0.95
□ 日志级别 INFO（排查时改 DEBUG）
```

## 3. Kubernetes 部署要点

```yaml
# 简化示例（需 NVIDIA GPU Operator）
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-qwen-7b
spec:
  replicas: 2
  template:
    spec:
      containers:
        - name: vllm
          image: vllm/vllm-openai:latest
          resources:
            limits:
              nvidia.com/gpu: "1"
          args:
            - --model
            - Qwen/Qwen2.5-7B-Instruct
            - --port
            - "8000"
            - --served-model-name
            - qwen-7b
          ports:
            - containerPort: 8000
          readinessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 120  # 模型加载慢
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 180
            periodSeconds: 30
```

**K8s 注意：**
- `initialDelaySeconds` 要足够长（大模型加载 1–5 分钟）
- 每 Pod 1 GPU 最常见；多 GPU 用 TP 在同一 Pod 内
- HPA 基于自定义指标（队列深度、GPU 利用率）而非 CPU

## 4. 分离式 Prefill / Decode

高并发下 Prefill（算力密集）与 Decode（带宽密集）资源需求不同：

```
         ┌──────────────┐         ┌──────────────┐
请求 ───→│ Prefill 节点  │ ──KV──→ │ Decode 节点   │ ──→ 输出
         │ (算力型 GPU)  │  transfer│ (带宽型 GPU)  │
         └──────────────┘         └──────────────┘
              × N                      × M
         独立扩缩容                独立扩缩容
```

vLLM 支持 Disaggregated Prefill（实验/生产特性随版本更新）：

- Prefill 节点：处理长 prompt，快速算 KV
- Decode 节点：专注 token 生成，高 batch 并发
- 通过 KV transfer（如 NCCL / RDMA）传递 cache

**何时考虑：** TTFT 与 TPOT 无法在同一配置下同时优化，且 QPS > 100。

## 5. 多模型与路由

```
场景：chat 用 7B，embedding 用 small 模型

方案 A：两个 vLLM 实例，不同端口
  :8000 → chat
  :8001 → embed
  网关按 path 路由

方案 B：vLLM 多模型（同一进程，共享 GPU）
  --model model_a --model model_b
  （显存需够，适合小模型组合）
```

## 6. 高可用与滚动更新

```
多副本 + 负载均衡：
  - 至少 2 个 vLLM 实例（不同节点）
  - 网关健康检查剔除故障实例
  - 滚动更新：先起新 Pod → readiness 通过 → 摘旧 Pod

模型版本切换：
  - 蓝绿：新模型新 Deployment，切换网关权重
  - 金丝雀：5% 流量到新模型，对比质量指标
```

## 7. 安全要点

| 项 | 做法 |
|----|------|
| API 认证 | `--api-key` + 网关二次校验 |
| 网络隔离 | vLLM 不暴露公网，仅内网 |
| 输入限制 | 网关限制 max prompt length |
| 模型来源 | 仅信任 HF 官方 / 自建权重 |
| 日志 | 不记录完整 prompt（PII） |
