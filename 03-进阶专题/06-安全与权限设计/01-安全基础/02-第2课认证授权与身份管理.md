# 第2课：认证、授权与身份管理

## 1. 认证 vs 授权

```
认证（Authentication）：你是谁？ → 登录
授权（Authorization）：你能做什么？ → 权限检查

流程：
  用户登录 → 认证成功 → 获得 Token
  访问资源 → 携带 Token → 验证身份 → 检查权限 → 允许/拒绝
```

---

## 2. 认证方案

### Session vs Token

| 维度 | Session | JWT Token |
|------|---------|-----------|
| 存储 | 服务端（Redis/DB） | 客户端（Cookie/Header） |
| 扩展 | 需要共享 Session Store | 无状态，易扩展 |
| 撤销 | 立即（删 Session） | 困难（需黑名单/短过期） |
| 适用 | 传统 Web | SPA / 移动端 / 微服务 |

### JWT 结构

```
Header.Payload.Signature

Header:  {"alg": "HS256", "typ": "JWT"}
Payload: {"sub": "user_42", "role": "admin", "exp": 1690000000}
Signature: HMAC-SHA256(header + payload, secret)

⚠️ Payload 是 Base64 编码，不是加密！不要放敏感信息
```

### OAuth2 流程（第三方登录）

```
用户 → App：「用 Google 登录」
App → Google：重定向到授权页
用户 → Google：同意授权
Google → App：Authorization Code
App → Google：用 Code 换 Access Token（后端）
App → Google：用 Token 获取用户信息
App：创建/关联本地用户，签发自己的 JWT
```

## 3. 授权模型

### RBAC（Role-Based Access Control）

```
User → Role → Permission → Resource

示例：
  Alice → Admin → [create, read, update, delete] → All Projects
  Bob  → Member → [read, update] → Assigned Projects
  Carol → Viewer → [read] → Assigned Projects
```

```python
from functools import wraps

def require_permission(permission: str):
    def decorator(func):
        @wraps(func)
        def wrapper(request, *args, **kwargs):
            if not request.user.has_permission(permission):
                raise PermissionDenied(permission)
            return func(request, *args, **kwargs)
        return wrapper
    return decorator

@require_permission("task.delete")
def delete_task(request, task_id):
    ...
```

### ABAC（Attribute-Based）

```
更细粒度：基于用户属性、资源属性、环境条件

规则示例：
  IF user.department == resource.department
  AND user.level >= "manager"
  AND time.hour BETWEEN 9 AND 18
  THEN allow "approve_expense"
```

## 4. API 安全

```
1. HTTPS everywhere（TLS 1.3）
2. API Key / Token 认证
3. Rate Limiting（防暴力破解）
4. CORS 配置（只允许信任的域名）
5. 输入验证（Pydantic / JSON Schema）
6. 响应不包含敏感信息
```

### CORS 配置

```python
# FastAPI
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],  # 不要用 "*"
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
)
```

## 5. 零信任（Zero Trust）

```
传统：内网 = 安全，外网 = 危险（城堡模型）
零信任：Never trust, always verify

原则：
  1. 每次请求都验证身份
  2. 最小权限访问
  3. 假设网络已被攻破
  4. 微分段（Micro-segmentation）
  5. 持续验证（Continuous Verification）

实践：
  - 服务间 mTLS（双向 TLS 认证）
  - 每个 API 调用都带 Service Token
  - 网络策略：Service A 只能访问 Service B 的 8080 端口
```

## 7. IDOR 与资源级授权

**IDOR（Insecure Direct Object Reference）** 是最常见越权漏洞。

```
❌ 只检查「用户已登录」
❌ 只检查「用户是 Member 角色」
✅ 检查「用户是否有权访问这个具体 Task」

GET /tasks/task_123
→ task.project_id → user 是否该 project 成员？
```

### TaskFlow 权限矩阵

| 操作 | Owner | Admin | Member | Viewer |
|------|-------|-------|--------|--------|
| 查看任务 | ✅ | ✅ | ✅ | ✅ |
| 创建任务 | ✅ | ✅ | ✅ | ❌ |
| 编辑他人任务 | ✅ | ✅ | ❌ | ❌ |
| 删除任务 | ✅ | ✅ | 自己的 | ❌ |
| 邀请成员 | ✅ | ✅ | ❌ | ❌ |
| 删除项目 | ✅ | ❌ | ❌ | ❌ |

## 8. 多租户隔离

```
数据隔离：每个 query 带 project_id 过滤；PostgreSQL RLS
逻辑隔离：middleware 从 JWT 提取 user → 查 membership → 注入 context

❌ SELECT * FROM tasks WHERE id = ?
✅ SELECT * FROM tasks WHERE id = ? AND project_id IN (user_projects)
```
