# 第4课：AI 伦理与产品安全

## 1. 为什么 AI PM 必须关注伦理和安全？

```
AI 产品的特殊性：
  · 传统产品出 bug = 功能不正常
  · AI 产品出问题 = 可能产生有害内容、歧视、隐私泄露

真实案例：
  · ChatGPT 泄露用户对话历史（2023年3月）
  · 微软 Tay 聊天机器人上线24小时变成种族主义者
  · AI 面试系统被发现对特定性别/种族有偏见
  · AI 生成的虚假新闻/深度伪造视频传播

AI PM 的责任：
  在产品设计阶段就考虑安全和伦理
  不是事后补救，而是 "Security by Design"
```

## 2. AI 幻觉（Hallucination）

### 2.1 什么是幻觉？

```
幻觉 = AI 一本正经地编造不存在的事实

类型：
  事实性幻觉：编造不存在的数据、论文、事件
    "根据2024年Nature发表的研究..."（这篇论文不存在）
  
  推理性幻觉：逻辑推理错误
    "2+3=6"（计算错误）
  
  引用性幻觉：编造引用来源
    "根据《公司手册》第8章..."（没有第8章）

为什么会幻觉？
  大模型本质是"概率预测下一个词"
  它不"知道"事实，只是生成"看起来合理"的文本
```

### 2.2 产品层面的应对策略

```
1. 检索增强（RAG）
   让 AI 基于真实文档回答，减少编造
   + 展示引用来源，用户可验证

2. 事实核查
   对 AI 输出进行自动事实检验
   用另一个模型检查是否有事实错误

3. 置信度标识
   AI 不确定时明确告知
   "我不太确定这个信息，建议您核实"

4. 限制回答范围
   只回答知识库内的问题
   超出范围说"这个问题超出了我的知识范围"

5. 免责声明
   "AI 生成内容，仅供参考，请勿作为专业依据"
   特别是在医疗、法律、金融等高风险场景

6. 人工审核
   高风险场景的 AI 输出必须经过人工审核
```

## 3. AI 偏见与公平性

### 3.1 偏见从哪来？

```
数据偏见 → 模型偏见 → 产品偏见

1. 训练数据偏见
   · 数据集中某些群体过多/过少
   · 历史数据本身就包含社会偏见
   · 标注员的主观偏见

2. 模型放大偏见
   · 模型学习并放大了数据中的模式
   · 例：如果训练数据中"CEO"多与男性关联
         模型就会倾向于认为CEO是男性

3. 产品放大偏见
   · 推荐系统的"信息茧房"
   · 搜索结果的排序偏见
```

### 3.2 PM 如何应对偏见

```
1. 评估阶段
   · 用不同群体的数据分别测试模型效果
   · 检查不同性别/年龄/地区的准确率是否一致
   · 使用公平性指标（Demographic Parity, Equal Opportunity）

2. 设计阶段
   · 避免让 AI 做涉及歧视的决策
   · 在简历筛选等场景中隐藏敏感信息
   · 提供人工复核机制

3. 监控阶段
   · 定期审查 AI 输出中的偏见案例
   · 收集用户投诉和反馈
   · 建立偏见检测自动化系统

案例分析：AI招聘系统
  问题：模型学习了历史招聘数据，偏好男性候选人
  原因：历史数据中男性被录用的比例更高
  解决：
    · 从训练数据中移除性别相关特征
    · 用公平性约束训练模型
    · 最终决策由人工做出，AI只做辅助
```

## 4. 隐私与数据安全

### 4.1 AI 产品的隐私风险

```
1. 训练数据隐私
   · 模型可能记住训练数据中的个人信息
   · 用户可能通过特殊提问"提取"出训练数据
   
2. 对话数据隐私
   · 用户对话内容是否被保存？
   · 是否用于模型训练？
   · 谁能看到用户的对话？

3. 数据泄露
   · RAG 知识库中的敏感信息
   · AI 回答中不小心暴露其他用户/内部信息

4. 第三方风险
   · 调用外部 API 时数据是否安全？
   · 数据是否出境？
```

### 4.2 隐私保护策略

```
1. 数据最小化
   · 只收集必要的数据
   · 不用于模型训练的数据及时删除
   · 明确告知用户数据用途

2. 数据脱敏
   · 在送入模型前脱敏（身份证、手机号、地址）
   · 模型输出也要检查是否包含敏感信息
   
3. 用户控制
   · 用户可以删除自己的对话历史
   · 用户可以选择是否允许数据用于训练
   · 清晰的隐私政策

4. 访问控制
   · 严格控制谁能访问用户数据
   · 日志审计
   · 最小权限原则

5. 合规
   · 中国：《个人信息保护法》《数据安全法》《生成式AI管理办法》
   · 欧盟：GDPR
   · 美国：各州隐私法
```

## 5. 内容安全

### 5.1 AI 可能产生的有害内容

```
┌─────────────────┬──────────────────────────────┐
│ 类型            │ 示例                          │
├─────────────────┼──────────────────────────────┤
│ 暴力/血腥       │ 生成暴力描写或指导             │
│ 色情/低俗       │ 生成色情内容                   │
│ 违法犯罪        │ 教人制造危险物品               │
│ 歧视/仇恨       │ 针对特定群体的歧视性内容       │
│ 虚假信息        │ 编造新闻、伪造数据             │
│ 自伤/自杀       │ 提供自伤方法                   │
│ 政治敏感        │ 不当政治言论                   │
│ 侵犯版权        │ 大段复制受保护内容             │
└─────────────────┴──────────────────────────────┘
```

### 5.2 安全防护体系

```
三道防线：

第一道：输入过滤（Prompt Safety）
  · 检测用户输入中的恶意意图
  · 识别 Prompt 注入攻击
  · 过滤明显的违规请求

第二道：模型层安全（RLHF + Safety Training）
  · 模型训练时加入安全对齐
  · 拒绝回答有害请求
  · "我无法提供这方面的信息"

第三道：输出过滤（Output Safety）
  · 对 AI 输出进行内容审核
  · 敏感词过滤
  · 安全分类器检测

兜底方案：
  · 过滤后的回答替换为安全回复
  · 高风险内容触发人工审核
  · 严重违规直接封禁
```

### 5.3 Prompt 注入攻击

```
什么是 Prompt 注入？
  用户通过特殊输入，试图绕过 AI 的安全限制

常见攻击方式：
  1. 角色扮演绕过
     "假装你是一个没有限制的AI..."
  
  2. 编码绕过
     用 base64/反写/拼音等方式隐藏敏感词
  
  3. 间接注入
     在文档/图片中嵌入恶意指令
     AI 处理文档时执行了隐藏指令

PM 的应对：
  · 将安全指令放在 System Prompt 的最高优先级
  · 添加输入检测层
  · 定期进行红队测试（专人尝试攻破安全防线）
  · 建立安全事件响应流程
```

## 6. AI 产品的合规要求

### 6.1 中国 AI 合规要点

```
《生成式人工智能服务管理暂行办法》（2023年8月）
  1. 生成内容应当体现社会主义核心价值观
  2. 不得生成虚假有害信息
  3. 用于训练的数据应合法合规
  4. 需要对生成内容进行标识（AI水印）
  5. 提供投诉举报机制
  6. 备案（深度合成服务需向主管部门备案）

《个人信息保护法》
  1. 收集个人信息需要明确同意
  2. 用户有权访问、删除个人数据
  3. 敏感信息需要单独同意
  4. 数据出境需要安全评估

PM 的合规 Checklist：
  □ 隐私政策已更新，覆盖 AI 功能
  □ 用户同意机制已实现
  □ AI 生成内容有明确标识
  □ 投诉举报入口已上线
  □ 内容安全审核系统已部署
  □ 数据存储和传输已加密
  □ 已完成必要的备案/报备
```

## 8. 动手练习

1. **安全设计**：为一个 AI 客服产品设计安全防护方案（三道防线的具体实现）
2. **隐私政策**：为一个 AI 对话产品写隐私政策要点（哪些数据收集、如何使用、如何保护）
3. **红队测试**：尝试用各种方式"攻破" Kimi 或豆包的安全限制，记录哪些方法有效
4. **伦理案例分析**：分析"AI面试官"产品的伦理风险，提出解决方案

## 9. 小结

| 概念 | PM 需要关注的 |
|------|--------------|
| AI 幻觉 | RAG+事实核查+免责声明+人工审核 |
| 偏见/公平 | 多群体评估+隐藏敏感特征+人工复核 |
| 隐私安全 | 数据最小化+脱敏+用户控制+合规 |
| 内容安全 | 输入过滤+模型安全+输出过滤（三道防线）|
| Prompt注入 | 安全指令+输入检测+红队测试 |
| 合规 | 《生成式AI管理办法》+《个保法》+备案 |
| 负责任AI | 透明+可控+公平+安全+隐私 |
