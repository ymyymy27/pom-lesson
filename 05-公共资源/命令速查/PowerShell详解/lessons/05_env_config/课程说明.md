## 5.1 环境变量基础

### 什么是环境变量？

**环境变量**是操作系统和应用程序用来存储配置信息的"全局变量"。它们在系统启动时被加载，所有程序都可以访问。

```
环境变量的工作原理：

操作系统加载时：
  PATH=C:\Windows; C:\Windows\System32; ...
  USERPROFILE=C:\Users\<用户名>
  TEMP=C:\Users\<用户名>\AppData\Local\Temp
  ...

程序启动时：
  程序 A → 读取 PATH → 知道在哪里找可执行文件
  程序 B → 读取 USERPROFILE → 知道用户的主目录在哪里
  程序 C → 读取 TEMP → 知道临时文件应该放哪里
```

### 查看所有环境变量

```powershell
# 查看所有环境变量
Get-ChildItem Env:

# 统计数量
Get-ChildItem Env: | Measure-Object

# 格式化为表格
Get-ChildItem Env: | Format-Table Name, Value -AutoSize
```

### 访问单个环境变量

```powershell
# 使用 $env: 前缀访问
$env:PATH
$env:USERPROFILE
$env:TEMP
$env:USERNAME

# 访问不存在的变量返回空字符串
$env:NONEXISTENT  # ""

# 检查变量是否存在
Test-Path Env:\PATH
```

## 5.3 PATH 环境变量详解

### PATH 的作用

PATH 是最重要的环境变量之一，它告诉系统**在哪里找到可执行文件**。

```
当你输入 python 时，系统搜索 PATH：
  1. 查找 C:\Windows\ → 没有 python.exe
  2. 查找 C:\Windows\System32\ → 没有 python.exe
  3. 查找 C:\Program Files\Python311\ → 找到了！使用它
  4. 停止搜索（第一个匹配的生效）
```

### 查看 PATH

```powershell
# 查看 PATH（分行列出）
$env:PATH -split ";"

# 格式化显示
$env:PATH -split ";" | ForEach-Object { Write-Output "  $_" }

# 统计 PATH 中的路径数量
($env:PATH -split ";").Count
```

### 添加到 PATH

```powershell
# 临时添加到 PATH（仅当前会话有效）
$env:PATH += ";C:\MyTools\bin"

# 永久添加到用户级 PATH
[Environment]::SetEnvironmentVariable(
    "PATH",
    [Environment]::GetEnvironmentVariable("PATH", "User") + ";C:\MyTools\bin",
    "User"
)

# 永久添加到系统级 PATH（需要管理员权限）
[Environment]::SetEnvironmentVariable(
    "PATH",
    [Environment]::GetEnvironmentVariable("PATH", "Machine") + ";C:\MyTools\bin",
    "Machine"
)
```

### 从 PATH 中移除

```powershell
# 临时移除
$env:PATH = ($env:PATH -split ";" | Where-Object { $_ -ne "C:\MyTools\bin" }) -join ";"

# 永久移除（需要管理员权限）
$currentPath = [Environment]::GetEnvironmentVariable("PATH", "Machine")
$newPath = ($currentPath -split ";" | Where-Object { $_ -ne "C:\MyTools\bin" }) -join ";"
[Environment]::SetEnvironmentVariable("PATH", $newPath, "Machine")
```

### PATH 的最佳实践

```
推荐做法：
1. 用户级 PATH：用于个人工具（如 Git 用户目录下的 bin）
2. 系统级 PATH：用于系统级工具（尽量少用）
3. 不要在 PATH 中放太多路径（影响搜索性能）
4. 重要路径放在前面（搜索优先级高）
```

## 5.4 环境变量的作用域

### 三种作用域

| 作用域 | 级别 | 持续时间 | 权限 |
|-------|------|---------|------|
| `Process` | 当前进程 | 当前会话 | 当前用户 |
| `User` | 当前用户 | 永久 | 当前用户 |
| `Machine` | 所有用户 | 永久 | 管理员 |

### 查看不同作用域

```powershell
# 查看进程级变量（当前会话）
[Environment]::GetEnvironmentVariables("Process")

# 查看用户级变量（永久）
[Environment]::GetEnvironmentVariables("User")

# 查看系统级变量（永久）
[Environment]::GetEnvironmentVariables("Machine")
```

### 设置不同作用域

```powershell
# 设置进程级（临时，仅当前会话）
$env:TEST = "process-level"

# 设置用户级（永久）
[Environment]::SetEnvironmentVariable("TEST", "user-level", "User")

# 设置系统级（永久，需要管理员权限）
[Environment]::SetEnvironmentVariable("TEST", "machine-level", "Machine")
```

### 修改立即生效

```powershell
# 修改用户级或系统级环境变量后
# 新开的 PowerShell 窗口会立即看到
# 但当前窗口需要手动刷新或重新启动

# 手动刷新（针对当前窗口）
# 方法 1: 重新读取
$env:PATH = [Environment]::GetEnvironmentVariable("PATH", "Machine") + ";" + [Environment]::GetEnvironmentVariable("PATH", "User")

# 方法 2: 完全重新加载
. $PROFILE
```

## 5.5 PowerShell Profile（配置文件）

### 什么是 Profile？

Profile 是在 PowerShell 启动时**自动执行的脚本**，用于配置你的个性化环境。

### 查看 Profile 信息

```powershell
# 查看当前有效的所有 Profile 文件
$PROFILE | Get-Member -MemberType NoteProperty

# 输出示例：
# AllUsersAllHosts       : C:\Program Files\PowerShell\7\profile.ps1
# AllUsersCurrentHost    : C:\Program Files\PowerShell\7\Microsoft.PowerShell_profile.ps1
# CurrentUserAllHosts    : C:\Users\<用户名>\Documents\PowerShell\profile.ps1
# CurrentUserCurrentHost : C:\Users\<用户名>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1

# 查看当前使用的 Profile 路径
$PROFILE.CurrentUserCurrentHost

# 检查 Profile 是否存在
Test-Path $PROFILE
```

### 创建 Profile

```powershell
# 获取 Profile 所在目录
$profileDir = Split-Path -Parent $PROFILE

# 如果目录不存在，创建它
if (-not (Test-Path $profileDir)) {
    New-Item -ItemType Directory -Path $profileDir -Force
}

# 创建 Profile 文件
New-Item -ItemType File -Path $PROFILE -Force

# 编辑 Profile
notepad $PROFILE
```

### Profile 常用配置

```powershell
# ========== PowerShell Profile 示例 ==========

# 1. 设置提示符（自定义 PS1 提示符）
function prompt {
    $location = Get-Location
    $user = $env:USERNAME
    "[$user] $location > "
}

# 2. 设置别名
Set-Alias -Name ll -Value Get-ChildItem
Set-Alias -Name grep -Value Select-String

# 3. 添加到 PATH
$env:PATH += ";$env:USERPROFILE\Documents\MyScripts"

# 4. 导入模块
Import-Module posh-git  # Git 提示符增强
Import-Module oh-my-posh  # 主题支持

# 5. 设置默认参数
$PSDefaultParameterValues = @{
    "Get-Process:ComputerName" = "localhost"
}

# 6. 自定义颜色
$host.PrivateData.ErrorForegroundColor = "Red"
$host.PrivateData.WarningForegroundColor = "Yellow"

# 7. 启动时显示欢迎信息
Write-Host "`n========================================" -ForegroundColor Cyan
Write-Host "  PowerShell 7.4.0 已启动" -ForegroundColor Green
Write-Host "  当前目录: $(Get-Location)" -ForegroundColor Yellow
Write-Host "========================================`n" -ForegroundColor Cyan
```

### Profile 加载顺序

```
PowerShell 启动时，按以下顺序加载 Profile：

1. AllUsersAllHosts        → C:\Program Files\PowerShell\7\profile.ps1
   （所有用户，所有主机）

2. AllUsersCurrentHost     → C:\Program Files\PowerShell\7\Microsoft.PowerShell_profile.ps1
   （所有用户，当前 PowerShell 主机）

3. CurrentUserAllHosts     → C:\Users\<用户>\Documents\PowerShell\profile.ps1
   （当前用户，所有主机）

4. CurrentUserCurrentHost → C:\Users\<用户>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1
   （当前用户，当前 PowerShell 主机）← 最常用！
```

## 5.6 自定义函数与别名

### 定义函数

```powershell
# 在 Profile 中添加函数
function which {
    param([string]$cmd)
    Get-Command $cmd -ErrorAction SilentlyContinue |
        Select-Object -ExpandProperty Source
}

# 使用函数
which python

# 快速进入项目目录
function cdp {
    Set-Location C:\code\Projects
}

# 快速创建并进入目录
function mkcd {
    param([string]$dir)
    New-Item -ItemType Directory -Path $dir -Force
    Set-Location $dir
}
```

### 定义别名

```powershell
# 创建别名
Set-Alias -Name gs -Value Get-Process
Set-Alias -Name gh -Value Get-Help

# 查看所有自定义别名
Get-Alias | Where-Object { $_.Description }

# 导出别名
Get-Alias | Export-Clixml $env:USERPROFILE\Documents\my-aliases.xml

# 导入别名
Import-Clixml $env:USERPROFILE\Documents\my-aliases.xml | ForEach-Object {
    Set-Alias -Name $_.Name -Value $_.Value
}
```

## 5.8 配置文件的版本控制

### 问题

Profile 中积累了大量自定义配置，如何在不同机器间同步？

### 解决方案

```powershell
# 1. 在 OneDrive/Dropbox/Git 中存放 Profile
$profileLink = "$env:USERPROFILE\Documents\PowerShell\profile.ps1"
$profileGit = "C:\Git\my-profile\profile.ps1"

# 创建符号链接（Windows）
New-Item -ItemType SymbolicLink -Path $profileLink -Target $profileGit -Force

# 2. 使用 Git 管理配置
# 在 GitHub 上创建仓库存储所有配置文件
git clone https://github.com/yourname/dotfiles.git C:\dotfiles

# 3. 创建安装脚本
@"
# dotfiles 安装脚本
`$dotfilesDir = 'C:\dotfiles'
`$profileDir = Split-Path -Parent `$PROFILE

# 链接配置文件
Copy-Item `"`$dotfilesDir\profile.ps1`" `"`$profileDir`" -Force
Copy-Item `"`$dotfilesDir\Microsoft.PowerShell_profile.ps1`" `"`$profileDir`" -Force

Write-Host '配置文件已安装！'
"@ | Out-File -FilePath C:\dotfiles\install.ps1
```

## 5.10 常见问题

### Q1: 修改 PATH 后不生效

**原因**：PATH 是进程级环境变量，修改后只对新开的窗口生效。

**解决**：
```powershell
# 关闭所有 PowerShell 窗口，重新打开

# 或在当前窗口手动刷新
$env:PATH = [Environment]::GetEnvironmentVariable("PATH", "Machine") + ";" + [Environment]::GetEnvironmentVariable("PATH", "User")
```

### Q2: Profile 不执行

**检查**：
```powershell
# 1. 确认 Profile 存在
Test-Path $PROFILE

# 2. 检查执行策略
Get-ExecutionPolicy

# 3. 如果是 Restricted，运行：
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### Q3: 环境变量值太长

**解决**：使用 `[Environment]::SetEnvironmentVariable()` 方法，避免 PATH 字符串过长导致的错误。
