## 8.1 Git 基础概念

### 版本控制是什么？

**版本控制系统（VCS）** 记录文件的变更历史，允许你在任意时间点查看、恢复或比较不同版本。

```
没有版本控制：
  文档_v1.doc
  文档_v2.doc
  文档_v2_最终版.doc  ← 混乱！
  文档_v2_最终版_真的.doc
  文档_v3_老王改的.doc

有 Git：
  每次修改都是一个"提交（commit）"
  可以查看任意提交的变更
  可以回到任意历史版本
  可以比较任意两个版本的差异
  可以创建分支并行开发
```

### Git 核心概念

```
工作区（Working Directory）：
  你正在编辑的文件目录
  ↓ git add
暂存区（Staging Area / Index）：
  准备提交的文件快照
  ↓ git commit
本地仓库（Local Repository）：
  .git 目录中存储的完整历史
  ↓ git push
远程仓库（Remote Repository）：
  GitHub, GitLab, Gitee 等服务器上的仓库
```

### 三个区域的关系

```
┌─────────────┐
│  Working    │  你正在编辑的文件
│  Directory  │  (被 Git 跟踪的文件)
└──────┬──────┘
       │ git add
       ↓
┌─────────────┐
│   Staging   │  暂存区（索引）
│    Area     │  准备提交的文件快照
└──────┬──────┘
       │ git commit
       ↓
┌─────────────┐
│ Repository  │  本地 .git 仓库
│             │  完整的项目历史
└─────────────┘
       │ git push
       ↓
┌─────────────┐
│   Remote    │  GitHub / GitLab
│ Repository  │  远程仓库
└─────────────┘
```

## 8.2 首次配置

### 配置 Git

```powershell
# 设置用户名（全局）
git config --global user.name "你的名字"

# 设置邮箱（全局）
git config --global user.email "你的邮箱@example.com"

# 查看配置
git config --list

# 查看特定配置
git config user.name
git config user.email

# 设置默认分支名
git config --global init.defaultBranch main

# 设置命令别名（简化输入）
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.lg "log --oneline --graph --all"
```

### 查看帮助

```powershell
git help
git help config
git config --help
git <command> -h  # 快速帮助
```

## 8.3 基础操作

### git init（初始化仓库）

```powershell
# 在当前目录初始化 Git 仓库
git init

# 初始化并指定目录
git init my-project

# 初始化裸仓库（用于服务器）
git init --bare my-repo.git
```

### git clone（克隆仓库）

```powershell
# 克隆仓库
git clone https://github.com/user/repo.git

# 克隆到指定目录
git clone https://github.com/user/repo.git my-folder

# 克隆特定分支
git clone -b develop https://github.com/user/repo.git

# 浅克隆（只下载最新版本，减少数据量）
git clone --depth 1 https://github.com/user/repo.git

# 克隆特定标签
git clone --branch v1.0.0 https://github.com/user/repo.git
```

### git status（查看状态）

```powershell
# 查看工作区状态
git status

# 简短格式
git status -s
# 输出：
# M file.txt       # M = Modified，已修改
# A  newfile.txt   # A = Added，已添加
# D  deleted.txt   # D = Deleted，已删除
# ?? untracked.txt # ?? = Untracked，未跟踪

# 显示更多信息
git status --long
```

### git add（添加文件到暂存区）

```powershell
# 添加单个文件
git add file.txt

# 添加所有文件
git add .

# 添加所有已跟踪的文件（不包括新文件）
git add -u

# 添加所有文件（包括新文件）
git add -A

# 添加特定模式的文件
git add *.txt
git add "*.txt"

# 添加所有修改和删除，但不包括新文件
git add -u

# 交互式添加
git add -i

# 添加文件的部分变更（patch）
git add -p
# 选项：
# y - stage this hunk
# n - skip this hunk
# s - split into smaller hunks
# e - manually edit the hunk
```

### git commit（提交变更）

```powershell
# 提交暂存区的文件
git commit

# 提交并添加消息
git commit -m "提交消息：修复了登录bug"

# 将已跟踪文件的变更直接提交（跳过 git add）
git commit -am "提交消息：快速提交已跟踪文件的修改"

# 修改最后一次提交（追加文件/修改消息）
git commit --amend

# 修改提交消息
git commit --amend -m "新的提交消息"

# 空提交（用于触发 CI）
git commit --allow-empty -m "触发CI"

# 指定提交作者
git commit --author="名字 <邮箱>" -m "消息"
```

## 8.4 查看历史

### git log（查看提交历史）

```powershell
# 查看完整历史
git log

# 每行一个提交
git log --oneline

# 图形化显示分支
git log --oneline --graph --all

# 显示最近 N 条
git log -5

# 显示统计信息（修改文件数）
git log --stat

# 显示差异（补丁）
git log -p

# 按文件名过滤
git log -- file.txt

# 按作者过滤
git log --author="张三"

# 按日期过滤
git log --since="2024-01-01"
git log --after="2024-01-01" --before="2024-12-31"

# 搜索提交消息
git log --grep="bug"

# 格式化输出
git log --pretty=format:"%h %s %an %ad" --date=short
```

### git diff（查看差异）

```powershell
# 查看工作区与暂存区的差异
git diff

# 查看暂存区与上一次提交的差异
git diff --staged
git diff --cached

# 查看工作区与特定提交的差异
git diff HEAD~3

# 比较两个提交
git diff abc123..def456

# 比较两个分支
git diff main..develop

# 只显示文件名
git diff --name-only

# 统计变更
git diff --stat

# 显示特定文件的差异
git diff -- file.txt
```

### git show（查看提交详情）

```powershell
# 查看特定提交
git show abc123

# 只查看提交信息
git show --no-patch abc123

# 查看某个提交修改的文件
git show --name-only abc123

# 查看某个文件的某个版本
git show abc123:path/to/file.txt
```

## 8.5 分支管理

### 查看分支

```powershell
# 列出本地分支
git branch

# 列出所有分支（包括远程）
git branch -a

# 列出分支并显示最后一次提交
git branch -v

# 列出已合并到当前分支的分支
git branch --merged

# 列出未合并的分支
git branch --no-merged
```

### 创建与切换分支

```powershell
# 创建新分支
git branch feature-login

# 切换分支
git checkout feature-login

# 创建并切换（新方式，推荐）
git switch -c feature-login

# 创建并切换（旧方式）
git checkout -b feature-login

# 切换到上一个分支
git checkout -
git switch -

# 基于特定提交创建分支
git checkout -b feature-login abc123

# 基于远程分支创建本地分支
git checkout -b develop origin/develop
git switch -c develop origin/develop
```

### 删除分支

```powershell
# 删除已合并的分支
git branch -d feature-login

# 强制删除分支（未合并也删除）
git branch -D feature-login

# 删除远程分支
git push origin --delete feature-login
```

### 重命名分支

```powershell
# 重命名当前分支
git branch -m new-name

# 重命名指定分支
git branch -m old-name new-name
```

## 8.6 远程操作

### 查看远程仓库

```powershell
# 查看远程仓库
git remote -v

# 查看远程仓库详情
git remote show origin

# 查看远程仓库名称
git remote

# 查看远程仓库 URL
git remote get-url origin
```

### 添加与修改远程仓库

```powershell
# 添加远程仓库
git remote add origin https://github.com/user/repo.git

# 修改远程仓库 URL
git remote set-url origin https://github.com/user/repo.git

# 重命名远程仓库
git remote rename origin upstream

# 删除远程仓库
git remote remove origin
```

### 推送（push）

```powershell
# 推送到远程仓库
git push

# 推送到特定分支
git push origin main

# 推送并设置上游分支（追踪关系）
git push -u origin feature-login
git push --set-upstream origin feature-login

# 推送所有分支
git push --all

# 强制推送（慎用！）
git push --force

# 推送标签
git push origin v1.0.0
git push --tags
```

### 拉取（pull / fetch）

```powershell
# 拉取并合并（常用）
git pull

# 拉取特定分支
git pull origin main

# 只拉取，不合并（fetch）
git fetch

# 获取所有远程分支
git fetch --all

# 查看远程分支
git branch -r

# 删除远程已删除的分支引用
git fetch --prune
git fetch -p
```

### 合并（merge）

```powershell
# 合并指定分支到当前分支
git merge feature-login

# 取消合并（如果有冲突）
git merge --abort

# 合并时创建合并提交（即使快进）
git merge --no-ff feature-login

# 查看即将合并的提交
git log main..origin/main
```

### 变基（rebase）

```powershell
# 变基到目标分支（将当前分支的提交应用到新基点）
git rebase main

# 交互式变基（修改提交历史）
git rebase -i HEAD~5

# 解决冲突后继续变基
git rebase --continue

# 取消变基
git rebase --abort

# 变基 vs 合并的选择
# 变基：保持线性历史，适合个人分支
# 合并：保留真实历史，适合合并主分支
```

## 8.7 撤销操作

### 撤销工作区修改

```powershell
# 撤销工作区的文件修改（恢复到暂存区/HEAD）
git checkout -- file.txt
git restore file.txt  # 新方式

# 撤销所有工作区修改
git checkout -- .
git restore .

# 使用交互式恢复
git restore -p
```

### 取消暂存

```powershell
# 取消暂存单个文件
git reset HEAD file.txt
git restore --staged file.txt  # 新方式

# 取消暂存所有文件
git reset HEAD
git restore --staged .
```

### 回退提交

```powershell
# 回退到上一个提交（保留工作区修改）
git reset HEAD~1

# 回退到上一个提交（保留暂存区）
git reset --soft HEAD~1

# 回退到上一个提交（不保留修改）
git reset --hard HEAD~1

# 回退到特定提交
git reset --hard abc123

# 回退远程仓库（慎用！）
git revert abc123  # 创建新提交来撤销指定提交
git push --force
```

### 恢复误删的文件

```powershell
# 从 HEAD 恢复
git checkout -- deleted-file.txt
git restore deleted-file.txt

# 从特定提交恢复
git checkout abc123 -- deleted-file.txt
git restore --source=abc123 deleted-file.txt
```

## 8.8 储藏（Stash）

### 保存工作进度

```powershell
# 保存当前工作进度
git stash

# 保存并添加消息
git stash save "修复到一半的bug"

# 保存包括未跟踪文件
git stash -u
git stash --include-untracked

# 保存特定文件
git stash push -m "message" file.txt

# 查看储藏列表
git stash list
# 输出：stash@{0}: WIP on main: abc123 修复到一半的bug

# 查看储藏内容
git stash show
git stash show -p stash@{0}

# 应用最新的储藏
git stash pop

# 应用特定储藏
git stash apply stash@{1}

# 删除储藏
git stash drop stash@{0}

# 清空所有储藏
git stash clear
```

### 常用场景

```powershell
# 场景：正在修改代码，突然要切换分支处理紧急bug
# 1. 保存当前进度
git stash

# 2. 切换分支修复bug
git checkout main
# ... 修复并提交 ...

# 3. 回到原分支恢复进度
git checkout feature-login
git stash pop
```

## 8.9 标签（Tag）

### 创建标签

```powershell
# 创建轻量标签
git tag v1.0.0

# 创建附注标签（推荐，包含更多信息）
git tag -a v1.0.0 -m "版本 1.0.0 发布"

# 为特定提交打标签
git tag -a v0.9.0 abc123 -m "版本 0.9.0"

# 查看所有标签
git tag

# 查看特定标签
git show v1.0.0

# 筛选标签
git tag -l "v1.*"
```

### 管理标签

```powershell
# 删除标签
git tag -d v0.9.0

# 推送标签到远程
git push origin v1.0.0

# 推送所有标签
git push --tags

# 删除远程标签
git push origin --delete v1.0.0

# 签名字签（需要 GPG）
git tag -s v1.0.0 -m "签名版本 1.0.0"
```

## 8.10 高级技巧

### 清理

```powershell
# 查看将被清理的内容
git clean -n

# 清理未跟踪的文件
git clean -f

# 清理未跟踪的文件和目录
git clean -fd

# 强制清理（包括 .gitignore 中的文件）
git clean -fx

# 清理所有未跟踪的目录
git clean -fd
```

### 搜索

```powershell
# 在提交历史中搜索
git log -S "搜索的字符串"

# 在工作区文件中搜索
git grep "搜索的字符串"

# 显示匹配的上下文
git grep -C 3 "搜索的字符串"

# 搜索并计数
git grep -c "搜索的字符串"
```

### 子模块（Submodule）

```powershell
# 添加子模块
git submodule add https://github.com/user/repo.git libs/repo

# 克隆包含子模块的仓库
git clone --recurse-submodules https://github.com/user/repo.git

# 初始化子模块
git submodule update --init

# 更新子模块
git submodule update --remote
```

### bisect（二分查找）

```powershell
# 开始二分查找
git bisect start

# 标记当前版本为有问题
git bisect bad

# 标记已知好的版本
git bisect good v1.0.0

# Git 会自动切换到中间版本测试，标记 good 或 bad
git bisect good  # 或 git bisect bad

# 完成二分查找
git bisect reset
```

## 8.11 工作流实战

### Git Flow 分支策略

```
main (生产环境)
  └── develop (开发分支)
        ├── feature-xxx (功能分支)
        ├── bugfix-xxx (修复分支)
        └── release-x.x (发布分支)
```

### 日常工作流程

```powershell
# 1. 开始新功能
git checkout -b feature/new-feature

# 2. 编码...
# 3. 提交
git add .
git commit -m "feat: 添加新功能"

# 4. 定期同步主分支
git fetch origin
git rebase origin/main

# 5. 功能完成，合并到主分支
git checkout main
git pull
git merge feature/new-feature
git push

# 6. 删除功能分支
git branch -d feature/new-feature
```
