# 第3课：多表连接与子查询

## 1. 为什么需要 JOIN？

### 问题
数据分散在多个表中：

```
users 表: id, name, age, city
orders 表: id, user_id, product, amount, order_date

想要: "查询每个用户的姓名和他们的订单金额"
  → 姓名在 users 表，金额在 orders 表
  → 需要 JOIN 把两个表连起来
```

### 关联条件
两个表通过**共同的字段**连接：`users.id = orders.user_id`

## 2. JOIN 类型

### 图解

```
表A (users):        表B (orders):
┌──┬───┐           ┌──┬────────┐
│1 │张三│           │1 │ user=1 │
│2 │李四│           │2 │ user=1 │
│3 │王五│           │3 │ user=2 │
│4 │赵六│           │4 │ user=5 │  ← user=5 在 users 中不存在
└──┴───┘           └──┴────────┘
  ↑ 赵六(4)没有订单    ↑ user=5 没有对应用户

INNER JOIN:  只保留两边都匹配的 → 张三(2条), 李四(1条)
LEFT JOIN:   保留左表所有 + 右表匹配的 → 张三(2), 李四(1), 王五(NULL), 赵六(NULL)
RIGHT JOIN:  保留右表所有 + 左表匹配的 → 张三(2), 李四(1), user=5(NULL)
FULL JOIN:   保留两边所有 → 全部
```

### 2.1 INNER JOIN（内连接，最常用）

```sql
-- 只返回两个表都匹配的行
SELECT u.name, o.product, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- 简写（INNER 可以省略）
SELECT u.name, o.product, o.amount
FROM users u
JOIN orders o ON u.id = o.user_id;

-- 结果：只有下过单的用户才会出现
```

### 2.2 LEFT JOIN（左连接，常用）

```sql
-- 保留左表（users）所有行，右表没匹配的填 NULL
SELECT u.name, o.product, o.amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- 结果：所有用户都会出现，没下单的用户 product 和 amount 为 NULL

-- 找出没有下过单的用户
SELECT u.name
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.id IS NULL;
```

### 2.3 RIGHT JOIN（右连接）

```sql
-- 保留右表所有行
SELECT u.name, o.product, o.amount
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- 实际中很少用，通常把表顺序换一下用 LEFT JOIN
```

### 2.4 多表连接

```sql
-- 三个表连接
-- users → orders → products
SELECT
    u.name AS 用户名,
    o.order_date AS 下单时间,
    p.product_name AS 商品名,
    o.amount AS 金额
FROM users u
JOIN orders o ON u.id = o.user_id
JOIN products p ON o.product_id = p.id
WHERE o.order_date >= '2024-01-01'
ORDER BY o.order_date DESC;
```

## 3. 表别名

```sql
-- 给表起别名，简化书写
SELECT u.name, o.amount
FROM users u              -- u 是 users 的别名
JOIN orders o             -- o 是 orders 的别名
ON u.id = o.user_id;

-- 当两个表有同名列时，必须用表名或别名区分
SELECT u.id, u.name, o.id AS order_id
FROM users u
JOIN orders o ON u.id = o.user_id;
```

## 4. 子查询（Subquery）

### 一句话解释
**子查询就是"查询里面套查询"** —— 先执行内层查询，结果给外层用。

### 4.1 WHERE 中的子查询

```sql
-- 查询下过单的用户信息
SELECT * FROM users
WHERE id IN (
    SELECT DISTINCT user_id FROM orders
);

-- 查询消费高于平均值的订单
SELECT * FROM orders
WHERE amount > (
    SELECT AVG(amount) FROM orders
);

-- 查询最近一天注册的用户
SELECT * FROM users
WHERE created_at >= (
    SELECT MAX(created_at) - INTERVAL 1 DAY FROM users
);
```

### 4.2 FROM 中的子查询（派生表）

```sql
-- 先算每个用户的总消费，再找总消费Top10
SELECT user_id, total_amount
FROM (
    SELECT user_id, SUM(amount) AS total_amount
    FROM orders
    GROUP BY user_id
) t
ORDER BY total_amount DESC
LIMIT 10;

-- 先算每个用户的订单数，再按订单数分层统计
SELECT
    CASE
        WHEN order_count = 1 THEN '新用户'
        WHEN order_count <= 5 THEN '普通用户'
        ELSE '活跃用户'
    END AS 用户类型,
    COUNT(*) AS 人数
FROM (
    SELECT user_id, COUNT(*) AS order_count
    FROM orders
    GROUP BY user_id
) t
GROUP BY 用户类型;
```

### 4.3 SELECT 中的子查询

```sql
-- 在每一行中显示全局统计
SELECT
    name,
    age,
    (SELECT AVG(age) FROM users) AS 全体平均年龄,
    age - (SELECT AVG(age) FROM users) AS 与平均的差距
FROM users;
```

### 4.4 EXISTS 子查询

```sql
-- 查询至少下过一单的用户（比 IN 效率更高）
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);

-- 查询没有下过单的用户
SELECT * FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);
```

## 5. UNION — 合并查询结果

```sql
-- UNION：合并并去重
SELECT city FROM users
UNION
SELECT city FROM stores;

-- UNION ALL：合并不去重（更快）
SELECT city FROM users
UNION ALL
SELECT city FROM stores;

-- 应用：合并不同来源的数据
SELECT '网站' AS 来源, COUNT(*) AS 注册数
FROM users WHERE source = 'web'
UNION ALL
SELECT 'APP' AS 来源, COUNT(*) AS 注册数
FROM users WHERE source = 'app';
```

## 6. 实用场景

### 6.1 用户消费详情

```sql
SELECT
    u.name AS 用户名,
    u.city AS 城市,
    COUNT(o.id) AS 订单数,
    COALESCE(SUM(o.amount), 0) AS 总消费,
    COALESCE(AVG(o.amount), 0) AS 平均消费
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id, u.name, u.city
ORDER BY 总消费 DESC;
```

### 6.2 产品销售排行

```sql
SELECT
    p.product_name,
    p.category,
    COUNT(o.id) AS 销量,
    SUM(o.amount) AS 总销售额,
    AVG(o.amount) AS 平均单价
FROM products p
JOIN orders o ON p.id = o.product_id
GROUP BY p.id, p.product_name, p.category
ORDER BY 总销售额 DESC
LIMIT 20;
```

### 6.3 用户首次与末次消费

```sql
SELECT
    u.name,
    MIN(o.order_date) AS 首次消费,
    MAX(o.order_date) AS 末次消费,
    DATEDIFF(MAX(o.order_date), MIN(o.order_date)) AS 活跃天数
FROM users u
JOIN orders o ON u.id = o.user_id
GROUP BY u.id, u.name;
```

## 8. 小结

| 语法 | 作用 | 特点 |
|------|------|------|
| `INNER JOIN` | 内连接 | 只保留匹配的行 |
| `LEFT JOIN` | 左连接 | 保留左表全部 |
| `RIGHT JOIN` | 右连接 | 保留右表全部 |
| `WHERE IN (子查询)` | 值在子查询结果中 | 简单直观 |
| `WHERE EXISTS` | 子查询有结果 | 大数据量更高效 |
| `FROM (子查询)` | 派生表 | 先算中间结果 |
| `UNION` | 合并去重 | 列数和类型须一致 |
