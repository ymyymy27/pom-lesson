# Lesson 6: IDE 环境配置（Cursor / VS Code）

> 这是解决你"安装了包但 IDE 找不到"问题的关键课程

---

## 6.1 问题的本质

先理解为什么会出现"终端能导入，IDE 报错"：

```
┌─────────────────────────────────────────────────────────────┐
│                    你的情况                                  │
│                                                             │
│  终端（PowerShell）          Cursor IDE                     │
│       │                              │                      │
│  where python                   Python Extension           │
│  → C:\Program Files\Python311   读取项目配置                │
│       │                              │                      │
│  pip install langchain          找到 python.exe             │
│  → 安装到 Python311              → ??? (哪个 python?)        │
│    的 site-packages              ↓                          │
│       │                     选择解释器                      │
│  python -c "import langchain"   ↓                          │
│  ✅ 成功                         选择了另一个 Python         │
│                                    ↓                        │
│                              找不到 langchain               │
│                              ❌ 报错                         │
└─────────────────────────────────────────────────────────────┘
```

**核心**：IDE 需要知道使用哪个 Python 解释器。默认它会猜测，但不一定猜对。

---

## 6.2 在 Cursor 中配置 Python 解释器

### 方法一：命令面板（推荐）

1. 按 `Ctrl+Shift+P` 打开命令面板
2. 输入 `Python: Select Interpreter`
3. 在列表中选择正确的 Python

**选择哪个？**

你应该选择与终端中 `where python` 输出相同的那个 Python 路径。

如果列表中没有你想要的，点击 **"Enter interpreter path..."** → **"Browse..."** 手动选择：

```
C:\Program Files\Python311\python.exe
```

或者（如果已创建虚拟环境）：
```
stage-05-llm-api\.venv\Scripts\python.exe
```

### 方法二：查看当前选择的解释器

1. 按 `Ctrl+Shift+P`
2. 输入 `Python: Display Python Path`
3. 查看当前 IDE 使用的 Python 路径

### 方法三：通过 settings.json 配置

按 `Ctrl+Shift+P`，输入 `Preferences: Open User Settings (JSON)`：

```json
{
    "python.defaultInterpreterPath": "C:\\Program Files\\Python311\\python.exe"
}
```

### 方法四：为单个项目指定解释器

在项目根目录的 `.vscode/settings.json` 中配置：

```json
{
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe"
}
```

## 6.3 VS Code 的 Python 扩展

### 推荐的 Python 扩展

| 扩展名 | 作用 |
|-------|------|
| Python | 核心支持（Linting、IntelliSense、调试） |
| Pylance | 快速类型检查和代码补全（强烈推荐） |
| Python Debugger | 调试器 |

### Pylance 的作用

Pylance 是一个基于 Pyright 的语言服务器，提供：
- 实时类型检查
- 精确的代码补全
- 跳转定义
- 导入路径解析

**注意**：Pylance 看到的包 = 当前选择的解释器的 site-packages。如果 Pylance 报错 `import 找不到`，但终端能运行，问题一定在**解释器选择**。

---

## 6.4 Python 解释器选择的工作原理

```
用户选择了解释器: C:\Program Files\Python311\python.exe
        │
        ↓
IDE 将该 python.exe 的 site-packages 目录加入 Python 语言服务器的搜索路径
        │
        ↓
语言服务器（Pylance）扫描 site-packages 中的 .pyi/.py 文件
        │
        ↓
生成代码补全、类型信息和导入错误提示
```

**所以**：解释器选对了，IDE 就能看到包；解释器选错了，IDE 就看不到。

## 6.5 虚拟环境 + IDE 配置的最佳实践

### Step by Step

**Step 1: 在项目目录创建虚拟环境**

```powershell
cd stage-05-llm-api
python -m venv .venv
```

**Step 2: 在 IDE 中选择虚拟环境的 Python**

1. `Ctrl+Shift+P` → `Python: Select Interpreter`
2. 选择 `stage-05-llm-api\.venv\Scripts\python.exe`

**Step 3: 在虚拟环境中安装包**

```powershell
# 先激活（可选，IDE 已选择后 pip 会自动使用正确的）
.\.venv\Scripts\Activate.ps1
pip install langchain langchain-openai
```

**Step 4: 在 IDE 中验证**

打开一个 `.py` 文件，输入 `import langchain`，如果没有红色下划线，配置成功。

## 6.6 为什么会选错解释器？

IDE 在以下位置按优先级查找 Python：

1. **当前项目 `.vscode/settings.json`** 中的 `python.defaultInterpreterPath`
2. **用户设置 `settings.json`** 中的 `python.defaultInterpreterPath`
3. **工作区推荐**（`.vscode/extensions.json` 推荐了 Python 扩展时会自动选择）
4. **PATH 中的 python**（IDE 会从 PATH 中找到的第一个 python 开始列举）
5. **已知的平台 Python 安装位置**

### 调试方法

```powershell
# 在终端中查看 IDE 可能"看到"的 Python
# Python 扩展会列举这些路径中的 python.exe：
# 1. conda envs
# 2. venv（当前项目上下文中）
# 3. virtualenvs（全局 virtualenvwrapper）
# 4. PATH 中的 python
# 5. 系统安装的 Python
```

如果你安装了多个 Python（Anaconda、官网 Python、系统 Python），IDE 列表会很长。**手动选择最可靠**。

## 6.7 重启语言服务器

有时候修改了解释器后 IDE 缓存没有更新，需要强制重启：

1. `Ctrl+Shift+P` → `Python: Restart LS`（重启 Python 语言服务器）
2. 或者直接按 `Ctrl+Shift+P` → `Developer: Reload Window`（重载窗口）

## 6.8 pytest / Jupyter 在 IDE 中的环境

### pytest

pytest 使用的是**当前激活的虚拟环境中的 pytest**（如果有的话），但 IDE 的 pytest 扩展可能使用不同的 Python。

在 VS Code settings.json 中指定：

```json
{
    "python.testing.pytestEnabled": true,
    "python.testing.pytestArgs": [],
    "python.defaultTestRunner": "pytest"
}
```

### Jupyter Notebook

Jupyter Notebook 的 kernel 也需要选择正确的 Python 环境：

1. 在 VS Code 中打开 `.ipynb` 文件
2. 点击右上角的 "Select Kernel"
3. 选择 `Python Environments...` → 选择对应的环境或 `.venv\Scripts\python.exe`

## 6.9 常见问题诊断流程

当你遇到"IDE 找不到已安装的包"时，按以下顺序排查：

```
Step 1: 在终端确认包确实已安装
  → python -c "import 包名" 成功？

Step 2: 查看包的安装位置
  → pip show 包名
  → 记录 "Location: ..."

Step 3: 查看安装包的 Python 是哪个
  → python -c "import sys; print(sys.prefix)"

Step 4: 在 IDE 中查看选择的解释器路径
  → Ctrl+Shift+P → "Python: Display Python Path"

Step 5: Step 3 和 Step 4 的路径是否一致？
  ├─ 一致 → 语言服务器缓存问题，重启 LS
  └─ 不一致 → 在 IDE 中切换到 Step 3 的 Python
```

## 6.10 多项目场景下的最佳实践

```
learn/
├─ stage-01-data-science/
│   ├─ .venv/                  # 每个项目独立的虚拟环境
│   ├─ requirements.txt
│   └─ ...
│
├─ stage-05-llm-api/
│   ├─ .venv/                  # 独立环境
│   ├─ requirements.txt
│   └─ ...
│
└─ .vscode/settings.json       # 可以在父目录配置，但建议各项目单独配置

    建议：为每个项目目录单独创建 .vscode/settings.json
```

每个项目目录下创建 `.vscode/settings.json`：

```json
{
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe",
    "python.linting.enabled": true,
    "python.linting.pylintEnabled": false,
    "python.linting.flake8Enabled": true,
    "python.formatting.provider": "black",
    "python.testing.pytestEnabled": false,
    "python.testing.unittestEnabled": false
}
```

## 6.11 .cursor/rules（Cursor 特定配置）

Cursor 支持在项目中添加 `.cursor/rules/` 目录，定义 AI 行为规范。你可以添加一条规则，让 AI 每次讨论代码时确认环境配置。

参考：https://www.cursor.com/docs/cursor-rules
