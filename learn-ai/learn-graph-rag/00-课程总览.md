# 第 00 课：课程总览与学习路线

## 1. 这门课解决什么问题

你大概已经学过 RAG：文档 → 分块 → Embedding → 向量检索 → 拼 Prompt → 生成。
它解决"从一堆文档里找到和问题语义相似的内容"，但有两个结构性的盲区：

1. **关系盲区**：向量检索不知道"张三的上司的上司是谁"这类跨实体关系，
   因为答案分散在多个文本块里，语义相似度拼不出一条关系链。
2. **全局盲区**："整个公司研发团队主要负责什么？"这类需要通读全局才能回答的问题，
   向量检索只能给出局部文本块，无法形成整体认知。

GraphRAG 的思路：先抽取实体与关系，把文档"编译"成一张图；
查询时不再只靠相似度，而是靠**图的拓扑结构**（路径、社区、中心性）做检索。

## 3. 学完后你应该能

- 说清 GraphRAG 与向量 RAG 的分工和边界
- 设计一个合理的知识图谱 Schema
- 用 LLM 做实体/关系抽取，并知道质量风险在哪
- 解释 Microsoft GraphRAG 的索引与检索全过程
- 根据业务场景选择合适的框架（GraphRAG / LightRAG / HippoRAG / KAG / 自研）
- 给 GraphRAG 设计评估集和指标
- 独立实现一个 mini GraphRAG（本课程配套代码）

## 5. 学习方法

1. 每课先读"核心问题"，再读正文，最后做练习。
2. 代码一定要自己跑一遍；跑完把参数改一改，观察结果变化。
3. 第 10 课是收口项目，建议把前 9 课的产出沉淀进去。
4. 用"五句话笔记法"收尾：概念 / 为什么 / 怎么做 / 坑 / 应用场景。

## 练习与自测

1. 用你自己的话定义 GraphRAG，和向量 RAG 的区别不超过三句话。
2. 写出你工作中/学习中最适合 GraphRAG 的一个场景，说明理由。
3. 预测一下：如果数据只有 20 个文本块，GraphRAG 值不值得上？为什么？

（第 3 题的思考方向：图索引有额外成本，规模小时纯向量 RAG 通常足够；
GraphRAG 的价值随"关系复杂度 × 文档规模"增长。）
