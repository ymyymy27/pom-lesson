# 第 04 课：图存储与检索基础

## 1. 核心问题

图抽出来了，存在哪？怎么查？这一课覆盖存储选型、Cypher 入门、
图检索的基本算法，以及"向量 + 图"怎么共存。

## 2. 存储选型

| 方案 | 特点 | 适用 |
|------|------|------|
| NetworkX（内存） | 纯 Python、无服务、适合原型 | 学习、小数据、快速验证 |
| Neo4j | 最流行属性图数据库，Cypher、向量索引、插件生态 | 生产首选 |
| Memgraph | Neo4j 兼容 Cypher，内存加速 | 高吞吐图查询 |
| NebulaGraph | 分布式，水平扩展 | 超大规模图 |
| Amazon Neptune | 托管云服务 | 云上免运维 |
| OpenSPG | 蚂蚁开源的语义增强图谱引擎 | KAG 配套、金融/医疗等专业域 |
| RDF Store | 标准 RDF 查询（SPARQL） | 开放数据、本体驱动 |

**学习路径建议**：先用 NetworkX 理解算法，再用 Neo4j 理解工程。
本课程实战代码用 NetworkX，第 10 课给出 Neo4j 的可选升级路径。

## 3. Cypher 入门（Neo4j 查询语言）

### 3.1 建节点和边

```cypher
CREATE (zs:Person {name: "张三", title: "工程师"})
CREATE (ls:Person {name: "李四", title: "总监"})
CREATE (rd:Department {name: "研发部"})
CREATE (px:Project {name: "项目X", stack: "Python, PostgreSQL"})

CREATE (zs)-[:REPORTS_TO]->(ls)
CREATE (ls)-[:MANAGES]->(rd)
CREATE (rd)-[:OWNS]->(px)
CREATE (zs)-[:WORKS_ON]->(px)
```

### 3.2 多跳查询

```cypher
// 张三的上级管理的部门负责什么项目？
MATCH (zs:Person {name: "张三"})-[:REPORTS_TO]->(boss:Person)
      -[:MANAGES]->(dept:Department)-[:OWNS]->(proj:Project)
RETURN boss.name, dept.name, proj.name
```

### 3.3 变长路径

```cypher
// 张三两跳以内能到达的所有节点
MATCH (zs:Person {name: "张三"})-[*1..2]-(n)
RETURN DISTINCT labels(n) AS label, coalesce(n.name, n.title) AS name
```

### 3.4 图投影与向量检索混合

Neo4j 5.11+ 原生支持向量索引：

```cypher
// 建向量索引
CREATE VECTOR INDEX project_emb IF NOT EXISTS
FOR (p:Project) ON (p.embedding)
OPTIONS {indexConfig: {
  `vector.dimensions`: 2560,
  `vector.similarity_function`: 'cosine'
}}

// 语义找项目 + 图关系扩展
CALL db.index.vector.queryNodes('project_emb', 3, $query_vector)
YIELD node, score
MATCH (node)<-[:OWNS]-(dept:Department)
RETURN node.name, score, dept.name
```

## 4. 图检索基础算法

### 4.1 遍历（BFS / DFS）

从种子节点出发，沿边扩展 k 跳。多跳问答的主力。

```python
import networkx as nx

# BFS 两跳邻居（含边信息）
for node, dist in nx.single_source_shortest_path_length(G, "张三", cutoff=2).items():
    print(node, dist)
```

### 4.2 社区检测

把图划分成"关系紧密的群组"，是全局检索的基础。
常见算法：Louvain、Leiden（GraphRAG 用 Leiden）、Label Propagation。

### 4.3 中心性 / 重要度

PageRank、Degree、Betweenness 可以回答"谁是最关键的人/项目"，
也用于检索时给候选节点加权。

### 4.4 个性化 PageRank（PPR）

以查询实体为"起点"做随机游走，得分高的节点 = 与起点关系密切的节点。
HippoRAG 的核心（第 7 课详述）。

## 5. 图检索的两种模式

### 5.1 精确查询（Text2Cypher）

自然语言 → Cypher → 精确结果。

```
"张三的上级管理的部门负责什么项目？"
        ↓ LLM
MATCH (zs:Person {name:"张三"})-[:REPORTS_TO]->(b)-[:MANAGES]->(d)-[:OWNS]->(p)
RETURN p.name
```

优点：精确、可解释；缺点：LLM 生成 Cypher 有语法/语义风险，需要校验。

### 5.2 子图检索（Traversal + Embedding）

实体链接到节点后，取 k 跳子图，把子图序列化成文本给 LLM。

优点：鲁棒（不依赖生成精确查询）；缺点：上下文可能膨胀，需要裁剪。

## 6. 序列化：把图"翻译"成 LLM 能读的文本

图本身不是文本，喂给 LLM 前要序列化：

```text
节点：
- 张三 (Person): 工程师，汇报给李四
- 李四 (Person): 总监，管理研发部
边：
- 张三 -REPORTS_TO-> 李四
- 李四 -MANAGES-> 研发部
路径：
- 张三 → 李四 → 研发部 → 项目X
```

序列化原则：

- 只送相关子图（k 跳裁剪 + 数量限制）
- 附上来源文档，保证可溯源
- 节点/边数量控制在 LLM 上下文可承受范围（通常 ≤ 50 节点）
