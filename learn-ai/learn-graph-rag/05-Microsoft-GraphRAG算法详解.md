# 第 05 课：Microsoft GraphRAG 算法详解

## 1. 核心问题

2024 年 Microsoft 发表 GraphRAG（arXiv:2404.16130），
目标是解决一个此前 RAG 解决不了的问题：**在大规模私有语料上做查询聚焦摘要（QFS）**。
这一课把它的索引管道和两种检索模式拆开讲。

## 2. 总览：GraphRAG 在做什么

```
输入：100 万字的企业文档
   │
   ▼
[索引阶段]（一次性、离线、昂贵）
  1. 分块（TextUnit）
  2. LLM 抽取实体/关系/描述
  3. 构建图（实体=节点，关系=边，描述=属性）
  4. Leiden 层次社区检测
  5. LLM 为每个社区写摘要（Map-Reduce）
  6. 社区摘要向量化 + 文本单元向量化
   │
   ▼
[查询阶段]（在线、按需）
  Local Search：从实体出发，局部子图 + 社区报告
  Global Search：跨社区摘要，Map-Reduce 生成全局答案
  DRIFT Search：混合两者并加入推理路径
```

## 3. 索引阶段逐步拆解

### 3.1 TextUnit：分块

把文档切成"文本单元"（Text Unit），默认约 300 token。
TextUnit 承担三重角色：

- 抽取输入（每块独立抽取实体关系）
- 检索单元（Local Search 会回溯到原文）
- 溯源单元（每个实体/关系记录来自哪些 TextUnit）

分块质量直接影响抽取质量：切得太碎，关系被截断；切得太整，超出上下文。

### 3.2 实体与关系抽取

对每个 TextUnit 调 LLM，输出实体（含类型、名称、描述）和关系（含描述）。
关键工程细节：

- 两次抽取：先抽实体，再基于实体抽关系（可配置，避免一次输出过长）
- 描述字段很重要：社区摘要的质量依赖实体描述
- 跨 TextUnit 的实体用规范名合并，关系的 `count`/描述做累加

### 3.3 建图

实体 → 节点；关系 → 有向边。
边带权重：跨文档重复出现的关系权重更高（`count`）。

权重的作用：

- Leiden 社区检测按权重聚类
- 子图扩展按权重排序裁剪

### 3.4 Leiden 层次社区检测

社区检测把"联系紧密的实体群"找出来。
GraphRAG 用 **Leiden 算法**（Louvain 的改进版），并输出**层次化**社区：

```
Level 0（最细）：研发部内的成员项目
Level 1：研发部整体
Level 2（最粗）：全公司组织
```

层次化的意义：不同粒度的问题对应不同层级的社区。
"项目X 用哪些技术"看 Level 0，"公司研发方向"看 Level 1/2。

Leiden 相对 Louvain 的优势：能保证社区内部连通，避免产生孤立碎片。

### 3.5 社区摘要（Map-Reduce）

每个社区 = 一堆节点和边。让 LLM 直接读大社区会超上下文，
所以 GraphRAG 用 Map-Reduce 生成社区摘要：

```
Map：把社区内的元素分批，每批让 LLM 总结成"发现报告"
Reduce：把多份发现报告合并成一份社区摘要
```

社区摘要相当于**自动生成的章节综述**，这是全局检索能工作的关键。

### 3.6 向量化

需要向量化的对象：

- 每个 TextUnit 的文本 → 向量（Local Search 定位原文）
- 每个社区摘要 → 向量（Global Search 选社区）

## 4. 查询阶段：三种检索

### 4.1 Local Search（局部检索）

适用：**实体级细节问题**（"张三汇报给谁？"）

流程：

1. 从问题中匹配实体（词法/向量匹配）
2. 以实体为中心扩展 k 跳子图（按权重裁剪）
3. 收集：相关节点、边、实体描述、所在 TextUnit 原文、社区摘要
4. 组合成上下文 → LLM 生成

特点：信息全、可溯源，但上下文大、token 成本高。

### 4.2 Global Search（全局检索）

适用：**需要通读全局的问题**（"公司所有部门的方向是什么？"）

流程（Map-Reduce）：

```
Map：对所有（或筛选后的）社区摘要，
     让 LLM 根据摘要生成"部分答案"并自评打分（0~10）
Reduce：按分数排序取 Top-N 部分答案，
       再让 LLM 汇总成最终答案
```

社区摘要多时（可能上千），Map 阶段做两件事：

- 向量相似度初筛（挑最相关的社区）
- 逐社区生成部分答案并打分

特点：能答全局问题，但成本高（每次查询要调多次 LLM）。

### 4.3 DRIFT Search（2025 年新增）

DRIFT = 结合 Local 与 Global 的"推理式"检索：

1. 先用全局社区摘要生成一组初步答案/假设
2. 从初步答案中提取关键实体，做局部子图扩展
3. 循环多轮，让检索路径跟随推理过程

它本质上是**把 Agentic 思想引入 GraphRAG**：
检索不是一次性的，而是跟着推理逐步展开。

## 5. 成本模型（为什么 GraphRAG 贵）

以一个 100 万 token 的语料为例（量级感受，非精确值）：

| 阶段 | 调用次数 | 成本占比 |
|------|---------|---------|
| 实体关系抽取 | 数千次（每 TextUnit 1~2 次） | ~60% |
| 社区摘要 | 数百~数千次（每社区 1 次 Map-Reduce） | ~30% |
| 全局查询 | 每次查询 10~100 次 | 查询侧 |

启示：

- 索引成本大头在抽取，优化抽取 = 优化成本
- Global Search 的每次查询都贵，只给"需要全局视角"的问题用
- 可以 Hybrid 路由：实体问题走 Local，主题问题走 Global

## 6. GraphRAG 的局限

1. **抽取噪声**：LLM 幻觉实体/关系会直接进图
2. **更新成本**：文档更新后要重跑相关抽取，增量更新复杂
3. **延迟**：全局检索多次 LLM 调用，交互体验差
4. **不适合**：纯语义模糊检索、情感分析、需要逐字引用的场景
