# 第 08 课：评估体系

## 1. 核心问题

GraphRAG 比向量 RAG 多了"建图"和"图检索"两层，评估也更复杂：
既要评估检索，又要评估生成，还要评估**图本身的质量**。

## 2. 评估的四个层面

```
① 图质量（离线）
   抽取准确率、实体消歧、Schema 合规
② 检索质量（在线）
   多跳召回、路径完整性、社区覆盖
③ 生成质量（端到端）
   正确率、忠实度、相关性、可溯源
④ 成本与延迟
   索引 token、查询 token、延迟
```

## 3. 图质量评估

### 3.1 指标

| 指标 | 定义 | 怎么测 |
|------|------|--------|
| 实体准确率 | 抽取的实体是否真实存在 | 抽样人工审计 |
| 关系准确率 | 关系是否与原文一致 | 抽样人工审计 |
| 召回率 | 原文关键实体是否被抽全 | 人工标注黄金三元组 |
| Schema 合规率 | 节点/关系类型是否符合 Schema | 程序校验 |
| 消歧错误率 | 错误合并/漏合并的比例 | 黄金实体表对比 |

### 3.2 实践建议

- 每批抽取抽 5%~10% 人工审计
- 把"黄金三元组"固化成测试集，回归跑
- 记录每条三元组的来源，错误可追溯

## 4. 检索评估

### 4.1 多跳检索指标

对每个多跳问题，标注"答案路径"（必须经过的边）。

| 指标 | 含义 |
|------|------|
| Recall@K | Top-K 检索结果覆盖了多少必要节点/边 |
| Path Completeness | 检索子图是否包含完整答案路径 |
| MRR | 第一个正确答案的排名倒数 |
| Hits@K | 正确答案是否出现在 Top-K |

GraphRAG 特有的检查：

- **路径完整性**：张三→李四→研发部→项目X 这条链是否完整出现在上下文
- **社区覆盖**：全局问题是否覆盖了相关社区

### 4.2 检索失败模式（调试清单）

```
[ ] 实体链接失败？（问题实体在图里没有对应节点）
[ ] 路径断裂？（中间节点/边缺失，或抽取漏了关系）
[ ] 子图被裁剪？（k 跳太小 / Top-N 太小）
[ ] 社区摘要泛泛而谈？（摘要没有具体事实）
[ ] 向量初筛把相关社区排掉了？
```

## 5. 生成评估

### 5.1 标准指标

| 指标 | 说明 |
|------|------|
| 正确率（EM / F1） | 与参考答案精确/词面匹配 |
| 忠实度（Faithfulness） | 回答是否都能从检索上下文找到依据 |
| 相关性（Relevance） | 回答是否切题 |
| 完整性（Completeness） | 是否覆盖问题所有子点 |
| 引用质量 | 引用的来源是否真实对应 |

### 5.2 忠实度怎么测

- 传统：NLI 模型判断"回答是否被上下文蕴含"
- 现代：LLM-as-Judge，让裁判模型逐句核验

```text
你是忠实度裁判。判断下面的回答是否完全基于提供的上下文。
逐句标注：SUPPORTED / NOT_SUPPORTED / CONTRADICTED，并给出原因。
```

### 5.3 多跳问题专项检查

多跳回答最常见错误：

- **跳错了**：路径中途替换了错误实体
- **跳断了**：只回答第一跳，漏掉后续
- **脑补跳**：上下文没给路径，模型自己补了一条

评估时按"跳数"分层统计：1-hop / 2-hop / 3-hop 各有多少正确。

## 6. 评测集设计

一份好的 GraphRAG 评测集至少包含：

| 类型 | 例子 | 数量占比 |
|------|------|---------|
| 单跳事实 | 张三的职位是什么？ | 30% |
| 两跳关系 | 张三汇报给谁？ | 30% |
| 多跳路径 | 张三上级的部门负责什么项目？ | 25% |
| 全局综述 | 公司研发方向是什么？ | 10% |
| 反例/拒答 | 文档里没有的问题 | 5% |

反例很重要：评估系统**会不会硬答**。

### 公开基准参考

- HotpotQA、2WikiMultiHopQA、MuSiQue：多跳问答
- ComplexWebQuestions：复杂关系查询
- CRAG：检索增强生成综合评测
- GraphQA / LCSKG：图谱问答

## 7. 成本与延迟评估

| 指标 | 说明 | 关注点 |
|------|------|--------|
| 索引 token 总量 | 抽取+摘要消耗 | 预算核心 |
| 每查询 token | 单次问答消耗 | 全局查询特别高 |
| P50/P95 延迟 | 端到端耗时 | 交互体验 |
| 缓存命中率 | 重复问题 | 优化空间 |

## 8. 评估流水线建议

```
固定语料 → 构建黄金评测集（≥50 题）
     ↓
建图（记录版本号） → 检索评估 → 生成评估
     ↓
回归对比：v1 vs v2 指标表
     ↓
每次改 Schema / 抽取 Prompt / 检索参数都重跑
```

## 练习与自测

1. 为你的场景设计 20 题评测集，覆盖 5 种题型。
2. 解释"路径完整性"为什么比单纯 Recall@K 更适合图检索。
3. 你的系统回答"信息不足"时，是真不足还是检索失败？怎么区分？
4. 画一个"图质量 → 检索 → 生成"三层指标联动表。

（第 3 题参考：检查实体链接与路径完整性；
如果图里有信息但没检到，是检索问题；图里没有，才是真信息不足。
第 2 题参考：多跳答案需要整条路径，单个节点命中不代表能回答。）
