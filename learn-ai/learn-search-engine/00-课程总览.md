# 第 00 课：课程总览与学习路线

## 1. 这门课解决什么问题

你刚学过 RAG：检索 + 生成。但 RAG 的"检索"在很多课程里被一笔带过——
实际上，**检索质量决定 RAG 的上限**：文档进不到上下文，模型再强也答不对。

这门课把检索这层彻底讲透：

- 文档是怎么被"索引"起来的（倒排索引）
- 为什么"关键词匹配 + BM25"到现在还是工业界主力
- 向量检索解决了什么、解决不了什么，怎么和 BM25 混合
- 怎么科学地评估"搜得好不好"

## 3. 学完后你应该能

- 说清"搜索"和"检索"的关系，以及它和 RAG 的关系
- 解释中文分词难点，并实现一个可用的小分词器
- 手写倒排索引构建与布尔查询
- 推导并解释 BM25 公式的每一个参数
- 设计 BM25 + 向量 + RRF 的混合检索
- 用 MRR / NDCG / Recall@K 评估一个搜索系统
- 独立实现一个可用的迷你搜索引擎

## 5. 学习方法

1. 先读"核心问题"，再读正文，最后做练习。
2. 四个实战脚本从零实现搜索引擎，务必亲手跑并改参数。
3. 第 10 课是收口项目：把前 9 课串起来。
4. 用"五句话笔记法"：概念 / 为什么 / 怎么做 / 坑 / 应用场景。

## 练习与自测

1. 用一句话说明"搜索引擎"和"向量数据库检索"的区别。
2. 回忆你最近一次搜索：查询词、结果、你判断相关性的标准是什么？
3. 预测：为什么关键词检索（BM25）到今天还没有被向量检索淘汰？

（第 3 题思考方向：精确匹配、可解释、低成本、冷启动友好；
向量检索强在语义泛化，但两者其实是互补关系。）
