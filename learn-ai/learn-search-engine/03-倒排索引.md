# 第 03 课：倒排索引

## 1. 核心问题

给 1000 万篇文档搜一个词，逐篇扫描要几分钟；倒排索引让它在毫秒级完成。
这一课讲清楚它的结构、构建过程，以及为什么它是搜索引擎的基石。

## 2. 什么是倒排索引

"正排"是"文档 → 词"：

```text
文档1：Python 爬虫 教程
文档2：Python 数据分析
```

"倒排"反过来："词 → 文档列表"：

```text
Python → [文档1, 文档2]
爬虫   → [文档1]
教程   → [文档1]
数据   → [文档2]
分析   → [文档2]
```

查询 "Python 教程" 时，取两个词的文档列表求交集，直接得到文档1。
不需要扫描全部文档。

## 3. 倒排索引的结构

```
倒排索引
├── 词典（Dictionary / Term Index）
│    词项 → 指向倒排列表的指针
├── 倒排列表（Posting List）
│    包含该词的文档 ID 列表
└── 可选扩展信息
     词频（TF）、位置（Position）、字段（Field）
```

### 3.1 词典

所有词项的集合，通常用哈希表、B+ 树或 FST（有限状态转换器）实现。

- 哈希表：查询 O(1)，但不支持前缀查询
- B+ 树：支持范围/前缀查询
- FST：内存占用极小，Lucene 用 FST 做词典

### 3.2 倒排列表（Posting List）

包含该词的文档 ID 列表，按文档 ID 升序存储：

```text
爬虫 → [1, 5, 12, 87]
```

升序的意义：两个词项的列表求交集（布尔查询）可以线性归并。

### 3.3 词频与位置

排序阶段需要词频（该词在文档中出现几次）；
短语查询（"机器学习 课程"作为一个短语）需要记录词在文档中的**位置**：

```text
机器学习 → 文档3: [pos 2, pos 15]
课程     → 文档3: [pos 3]
```

位置相邻且顺序正确 → 判定为短语匹配。

## 4. 构建过程

```
文档流
  → 文本分析（分词、规范化）
  → 生成 (词项, 文档ID, 词频, 位置)
  → 按词项分组排序
  → 写入词典 + 倒排列表
  → （可选）压缩、合并段
```

简化版伪代码：

```python
from collections import defaultdict

def build_inverted_index(docs):
    index = defaultdict(list)   # term -> [(doc_id, tf)]
    for doc_id, text in docs:
        for term, tf in tokenize_with_tf(text):
            index[term].append((doc_id, tf))
    return index
```

## 5. 布尔查询：AND / OR

```text
查询：Python AND 爬虫
→ 取 Python 和 爬虫 的倒排列表，求交集

查询：Python OR 爬虫
→ 取并集
```

布尔查询是"召回"的基石：先按布尔条件确定候选文档，
再进入排序阶段打分。搜索引擎实际流程通常是：

```
布尔过滤（必须满足的条件）
  → 候选集
  → BM25 打分
  → Top-K
```

## 6. 倒排列表的压缩

文档 ID 是整数且有序，可以用差量（delta）+ 变长编码压缩：

```text
原始： [1, 5, 12, 87]
差值： [1, 4, 7, 75]
```

小整数用更少的字节存储（Varint / Gamma 编码），
配合跳表指针（Skip Pointer）加速大列表的交集运算。

## 7. 更新与删除

倒排索引更新很昂贵，工业界用**分段（Segment）+ 合并（Merge）**：

```
新文档 → 写成一个新小段（不可变）
删除 → 打删除标记（墓碑）
后台 → 定期把小段合并成大段，真正清理
```

好处：写入不阻塞查询；代价：合并有 IO 成本，段数多时查询慢。
这正是 Elasticsearch 内部的工作方式。

## 8. 倒排索引 vs 向量索引

| 维度 | 倒排索引 | 向量索引（HNSW 等） |
|------|---------|-------------------|
| 匹配方式 | 精确词项匹配 | 近似语义相似 |
| 查询速度 | 极快 | 快（但建图开销大） |
| 可解释性 | 高（命中词可见） | 低 |
| 同义词 | 需词典扩展 | 天然部分解决 |
| 拼写错误 | 弱（可用 n-gram 缓解） | 较强 |
| 存储 | 小 | 大 |

两者不是替代关系，混合使用是当前主流（第 5 课）。

1. 手写 3 篇短文，构建它们的倒排索引（含词频）。
2. 解释为什么倒排列表按文档 ID 升序存储。
3. "位置"信息除了短语查询还能用来做什么？
4. 为什么删除文档不直接改索引，而是打墓碑标记？
5. 什么时候你会同时需要倒排索引和向量索引？

（第 3 题方向：邻近度打分（词距越近分越高）、高亮定位、同段加权。
第 5 题方向：精确词匹配（人名、编号）用倒排，语义泛化用向量，两者 RRF 融合。）
