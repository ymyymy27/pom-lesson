# 第 04 课：排序：从 TF-IDF 到 BM25

## 1. 核心问题

召回解决"能不能搜到"，排序解决"相关的是不是排前面"。
这一课从 TF-IDF 推导到 BM25，把工业界最常用的排序公式讲透。

## 2. 打分的基本直觉

一个词项对一篇文档的相关性贡献取决于三个因素：

1. **词频（TF）**：词在文档里出现越多，越可能相关（但收益递减）
2. **逆文档频率（IDF）**：词越稀有，区分度越高（"爬虫"比"的"值钱）
3. **文档长度**：同一词频，短文比长文更相关（归一化）

## 3. TF-IDF

### 3.1 TF：词频

最简单的形式：

```text
TF(t, d) = 词 t 在文档 d 中的出现次数
```

常用变体（对数归一）：

```text
TF(t, d) = 1 + log(count)
```

### 3.2 IDF：逆文档频率

```text
IDF(t) = log(N / df(t))
```

其中 N 是文档总数，df(t) 是包含词 t 的文档数。

### 3.3 打分

```text
score(q, d) = Σ TF(t, d) × IDF(t)
             t∈q
```

### 3.4 TF-IDF 的问题

1. **词频线性增长**：出现 10 次的分是 1 次的 10 倍，不符合直觉
2. **没考虑文档长度**：长文档天然词频高，被不公平地高估
3. **IDF 可能为负**：词出现在超过一半文档里时

## 4. BM25（Okapi BM25）

BM25 在 TF-IDF 基础上修正了这三件事，是 Lucene / Elasticsearch 的默认算法。

### 4.1 公式

```text
score(q, d) = Σ IDF(t) × [ tf(t,d) × (k1 + 1) ]
             t∈q        ──────────────────────────────
                          tf(t,d) + k1 × (1 - b + b × |d|/avgdl)
```

参数：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| k1 | 1.2~2.0 | 词频饱和曲线：越大，词频越"线性" |
| b | 0.75 | 文档长度归一化强度：0 = 不考虑长度 |
| avgdl | 语料均值 | 平均文档长度 |

### 4.2 直觉拆解

**词频饱和**：

```text
出现 1 次 → 很高贡献
出现 5 次 → 贡献增加，但不再线性
出现 20 次 → 和 10 次几乎没差别
```

k1 控制这个饱和速度。k1 越大，多次出现仍能加分；k1 越小，出现几次就封顶。

**长度归一化**：

```text
文档越长（|d|/avgdl 越大），分母越大，分数越低。
因为长文档里出现 3 次的"爬虫"，含金量不如短文档里的 3 次。
```

b = 0 时完全忽略长度；b = 1 时完全按长度惩罚。

### 4.3 IDF 在 BM25 中

```text
IDF(t) = log( (N - df(t) + 0.5) / (df(t) + 0.5) )
```

平滑项 0.5 保证：即使词出现在一半文档中，IDF 也不会变成负数。

## 5. 手算例子

语料 100 篇文档，平均长度 50 词。
文档 d 长 60 词，"爬虫"出现 3 次；"爬虫"出现在 2 篇文档中。

```text
IDF = log((100 - 2 + 0.5) / (2 + 0.5)) = log(39.4) ≈ 3.67

TF 项 = 3 × 2.2 / (3 + 1.2 × (1 - 0.75 + 0.75 × 60/50))
      = 6.6 / (3 + 1.2 × (0.25 + 0.9))
      = 6.6 / (3 + 1.38) ≈ 1.507

score ≈ 3.67 × 1.507 ≈ 5.53
```

如果同样的 3 次出现在 20 词短文档里：

```text
TF 项 = 6.6 / (3 + 1.2 × (0.25 + 0.3)) = 6.6 / 3.66 ≈ 1.80
score ≈ 3.67 × 1.80 ≈ 6.61   ← 短文档得分更高
```

这就是"长度归一化"在起作用。

## 6. 工程化改进

### 6.1 字段加权（Field Boosting）

标题命中 > 正文命中。打分时乘以字段权重：

```text
title 权重 3.0，body 权重 1.0
```

### 6.2 BM25F

把多个字段合并考虑长度归一化，避免标题+正文拼接后长度失真。

### 6.3 查询词加权

品牌词、用户明确强调的词权重更高（搜索引擎的 query boosting）。

### 6.4 精排（Learning to Rank）

BM25 只是召回后的粗排。生产系统常用：

```
召回：布尔 + BM25 / 向量
粗排：BM25 / 向量融合（几百条）
精排：LTR 模型 / Cross-Encoder（几十条）
```

## 7. BM25 的局限

- 纯词面匹配：同义词"人工智能"搜不到"AI"
- 不懂语义：问"怎么请年假"搜不到"休假申请"
- 无法利用点击数据：不会从用户行为中学习

这些局限正是向量检索和 LTR 存在的理由（第 5、8 课）。

## 练习与自测

1. 手算一个 BM25 例子（换一组数字）。
2. 解释 k1 和 b 分别控制什么；b=0 和 b=1 分别是什么极端。
3. 为什么词频收益要"饱和"？
4. 什么场景下你会调大 k1？什么场景下调大 b？

（第 4 题方向：标题党/短查询多 → k1 偏大让多次命中继续加分；
文档长度差异大 → b 偏大加强长度惩罚。建议用评估集调参，不要拍脑袋。）
