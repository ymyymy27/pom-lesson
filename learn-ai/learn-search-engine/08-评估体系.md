# 第 08 课：评估体系

## 1. 核心问题

"感觉搜得好不好"不可靠。这一课建立科学的搜索评估：
离线用标注集算指标，在线用用户行为做验证。

## 2. 离线评估的基础：测试集

一个搜索测试集包含三部分：

```text
查询集（Queries）      ：用户真实/代表性问题
相关文档标注（Qrels）  ：每个查询人工标注哪些文档相关
相关性分级            ：0=不相关 1=相关 2=高度相关
```

示例（TSV）：

```text
query_id  doc_id  relevance
q1        d3      2
q1        d7      1
q2        d1      0
```

## 3. 核心指标

### 3.1 Precision@K / Recall@K

只看前 K 个结果：

```text
Precision@5 = 前5个里相关数 / 5
Recall@5    = 前5个里相关数 / 总相关数
```

### 3.2 MAP（平均精度均值）

把"相关文档排得越靠前越好"编码进指标。

### 3.3 MRR（倒数排名）

第一个相关结果的位置：

```text
第一个相关结果在第 2 位 → RR = 1/2
MRR = 所有查询 RR 的平均值
```

适合"只有一个正确答案"的场景（问答、导航搜索）。

### 3.4 NDCG（归一化折损累计增益）

支持多级相关性，是目前最常用的排序指标：

```text
DCG@K = Σ (2^rel_i - 1) / log2(i + 1)
NDCG@K = DCG@K / IDCG@K（理想排序的 DCG）
```

直觉：

- 相关性分越高，增益越大（指数级）
- 排名越靠后，增益折扣越狠（log 惩罚）
- 除以 IDCG 归一化到 0~1，方便跨查询比较

### 3.5 手算 NDCG@3

标注：d1=2, d2=1, d3=0

```text
DCG@3 = (2^2-1)/log2(2) + (2^1-1)/log2(3) + (2^0-1)/log2(4)
      = 3/1 + 1/1.585 + 0/2 ≈ 3 + 0.631 = 3.631

理想排序是 d1, d2, d3（已经是最优）→ IDCG = 3.631
NDCG@3 = 1.0
```

如果排序是 d3, d1, d2：

```text
DCG@3 = 0 + 3/1.585 + 1/2.585 ≈ 1.893 + 0.387 = 2.280
NDCG@3 ≈ 2.280 / 3.631 ≈ 0.628
```

## 4. 指标怎么选

| 场景 | 首选指标 |
|------|---------|
| 只有一个正确答案（导航/问答） | MRR |
| 多个相关文档、看排序质量 | NDCG@K |
| 强调"别漏"（召回敏感） | Recall@K |
| 强调"别错"（精度敏感） | Precision@K |

## 5. 标注的坑

1. **未标注文档**：系统返回了但 qrels 里没有 = 不算相关？
   结论：视为不相关（但可能只是没标到，指标会低估真实质量）
2. **标注不一致**：两个人对"相关"理解不同 → 用 Kappa 一致性检查
3. **查询代表性不足**：测试集要覆盖高频查询、长尾查询、失败查询
4. **数据泄漏**：用调参时的查询评估调参，指标虚高

## 6. 在线评估

离线指标不能反映真实用户行为，上线后用在线指标验证：

| 指标 | 含义 |
|------|------|
| CTR | 搜索结果点击率 |
| 首点位置 | 用户第一个点击的位置（越靠前越好） |
| 无结果率 | 搜索返回空的比例 |
| 跳出率 | 点了结果立刻返回 |
| 转化率 | 搜索到成交/目标行为 |

### 6.1 A/B 测试

新排序 vs 旧排序分流量对比。注意：

- 提前确定指标和最小样本量
- 避免同时改多个变量
- 用**交错排序（Interleaving）**可以更高效地对比排序

## 7. 评估回归流水线

```
固定测试集（≥50 查询）
  → 跑旧版本 → 记录指标
  → 跑新版本 → 记录指标
  → 对比：NDCG 提升了吗？失败查询变多了吗？
  → 每次改分析器/排序/参数都重跑
```
