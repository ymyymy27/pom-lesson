# 第 09 课：生产实践

## 1. 核心问题

搜索系统上线只是开始。这一课讲相关性调试流程、
同义词与查询理解、监控和常见生产事故。

## 2. 相关性调试的标准化流程

```
收到"搜不到/排得不对"的反馈
  → 1. 复现查询，记录返回结果
  → 2. 检查分析器（分词结果是否合理）
  → 3. 检查召回（候选集是否包含目标文档）
  → 4. 检查排序（目标文档排名多少、为什么）
  → 5. 修复 → 加入回归测试集 → 验证
```

关键问题清单：

```text
[ ] 目标文档进索引了吗？（索引延迟？Mapping 过滤？）
[ ] 分词一致吗？（"FastAPI" vs "fastapi" vs "FASTAPI"）
[ ] 召回了吗？（布尔条件把文档过滤掉了？）
[ ] 排到第几？（分数来自哪个词项？BM25 归一化合理吗？）
[ ] 摘要/高亮显示正常吗？（用户可能根本没点）
```

## 3. 同义词与查询理解

### 3.1 同义词

"AI" 和 "人工智能"、"报销" 和 "费用申请"。

两种实现：

- **索引侧扩展**：把同义词都写入索引 → 召回变多，索引变大
- **查询侧扩展**：查询时展开同义词 → 更灵活，可加权重

同义词词表要按领域维护，放错位置会造成误召回
（"苹果"到底是水果还是公司？）。

### 3.2 查询改写

口语 → 检索友好：

```text
"报销咋整" → "报销流程"
"年假有几天" → "年假 天数"
```

可以用规则、同义词表，或 LLM（成本高但灵活）。

### 3.3 拼写纠错

```text
"pthon" → 提示/自动改 "python"
```

常见实现：编辑距离 + 词频 + 用户点击反馈。

## 4. 新鲜度

搜索"新闻"要新，搜索"文档"要准。处理方式：

- 时间衰减加权（function_score gauss）
- 缓存按新鲜度分级（新文档立即可见，旧结果可缓存）
- 紧急内容置顶（人工干预/运营位）

## 5. 监控体系

### 5.1 系统指标

```text
查询 QPS、P50/P95/P99 延迟
无结果率（Zero-result rate）
索引延迟（文档入库到可搜的时间）
分片健康、段数量、合并压力
缓存命中率
```

### 5.2 质量指标

```text
CTR、首点位置、无结果查询 TOP 榜
低质量查询监控（高频但低 CTR 的查询）
新索引版本上线后的指标对比
```

## 6. 安全与合规

- **查询注入**：用户输入不能直接拼查询语句
  （ES 的 query DSL 用参数，不要字符串拼接）
- **权限过滤**：文档级 ACL 必须在查询层强制注入
- **日志脱敏**：查询日志可能含个人信息，脱敏后存储
- **限流**：防爬虫、防恶意查询

## 7. 容量与成本

```text
内存：词典 + 向量索引常驻内存
磁盘：倒排索引 + 文档存储 + 日志
成本大头：向量索引和副本数量
```

省钱思路：

- 向量维度裁剪/量化（PQ）
- 副本按流量弹性扩缩
- 冷热分层（老数据用低成本存储）

## 8. 常见生产事故

| 事故 | 原因 | 预防 |
|------|------|------|
| 全部搜不到 | 索引重建失败/分析器配置错误 | 上线前 golden query 测试 |
| 某类文档消失 | Mapping filter 或 ACL 误配 | 数据巡检 |
| 延迟飙高 | 深分页/缓存击穿/段太多 | 游标、限流、段合并 |
| 排序突然变差 | 词典/同义词更新 | 变更走回归测试 |
| 缓存陈旧 | 新文档发布但缓存未失效 | 新鲜度分级缓存 |

## 练习与自测

1. 给你一个"搜不到"的反馈，列出排查顺序。
2. 索引侧同义词和查询侧同义词的取舍。
3. 设计 5 个必须监控的搜索质量指标。
4. 权限过滤为什么必须放在查询层而不是应用层？

（第 4 题方向：查询层过滤能防止"拿到结果再删"的越权泄漏，
也能利用索引过滤加速；应用层过滤既慢又不安全。）
