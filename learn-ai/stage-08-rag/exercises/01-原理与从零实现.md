# 练习 01：RAG 架构与原理

> 配套：`01-RAG架构与原理.md` + `learn-rag/01_rag_overview.py`

## 一、思考题

1. 为什么 RAG 比"把所有文档直接塞进 Prompt"更可扩展？
2. chunk 太大或太小，各会带来什么问题？
3. TF-IDF 或关键词检索与神经网络 Embedding 检索，本质区别是什么？
4. Top-K 和相似度阈值分别控制什么？阈值设太高或太低会怎样？
5. 什么情况下 RAG 应该"拒答"而不是硬答？

## 二、动手题

1. 修改 `01_rag_overview.py` 中的知识库，新增一条文档（例如"公司健身房开放时间"），
   然后提问验证能否被检索到、能否正确回答。
2. 把 `top_k` 从 2 改成 1 和 5，观察回答变化，想一想为什么。
3. 问一个知识库里完全没有的问题（例如"公司食堂几点关门？"），
   看模型是拒答还是编造。如果不理想，尝试修改系统提示词让它学会拒答。

## 三、参考答案

1. 塞满 Prompt 会迅速撑爆上下文窗口、增加推理成本，且文档一多就无法全部放入；
   RAG 先用检索把范围缩小到 Top-K，只把相关内容交给模型。
2. 太大：语义混杂、容易检索到"部分相关"的块，上下文浪费、超出窗口；
   太小：单个块信息不完整，回答时缺上下文。需要按文档结构 + 实验调参。
3. 关键词检索是字面匹配，同义词、改写、口语化问题容易漏检；
   神经网络 Embedding 把语义映射到向量空间，能匹配"意思相近但用词不同"的内容。
4. Top-K 决定给模型几块资料（召回范围），阈值决定"不够相关就宁可不要"（精度底线）。
   阈值太高会漏答，太低会让无关资料进上下文、增加幻觉风险。
5. 当最高相似度低于阈值、检索结果与问题无关时，应当拒答并提示用户换一种问法
   或补充资料，而不是让模型硬编。
