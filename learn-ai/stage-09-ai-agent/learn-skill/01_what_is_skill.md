# 第1课：Skill 是什么 & 核心概念

## 1. Skill 是什么？

### 一句话解释
**Skill 就是给 AI 的"岗位培训手册"** —— 把你的专业知识、工作流程、行为规范打包成一个 Markdown 文件，AI 读完就能按你的方式做事。

### 类比理解

| 你熟悉的 | 对应的 Skill 概念 |
|---------|------------------|
| 新员工入职手册 | SKILL.md（技能定义文件） |
| 手册里的岗位职责 | description（技能描述） |
| 手册里的 SOP 流程 | Instructions（执行指令） |
| 手册里的参考案例 | examples/（示例文件夹） |
| 手册里的规章制度 | Guidelines（行为准则） |
| 公司培训资料库 | skills/ 目录（技能仓库） |

### 为什么需要 Skill？

你平时用 AI（ChatGPT、Claude、Copilot 等）时，是不是经常这样：

1. 每次都要重复输入一大段提示词
2. AI 不了解你团队的代码规范，生成的代码风格不统一
3. 复杂流程要分好几步教 AI，下次还得重新教
4. 想把好用的提示词分享给同事，但没有标准格式

**有了 Skill，这些问题都解决了：**
- **一次编写，反复使用** —— 写好 SKILL.md，以后一句话触发
- **自动匹配** —— AI 根据你的任务自动加载对应的 Skill
- **团队共享** —— Skill 就是文件夹，用 Git 管理，团队直接用
- **按需加载** —— 不浪费 token，只在需要时才读取详细内容

## 2. Skill 的演变：从 Prompt 到 Context Engineering

### 技术演进路线

```
2022-2023: 盲目提示（Blind Prompting）
    "帮我写个 Python 函数"
        |
        v
2023-2024: 提示工程（Prompt Engineering）
    "你是一个资深 Python 开发者，请按照 PEP8 规范..."
        |
        v
2024-2025: 上下文工程（Context Engineering）
    系统提示 + 结构化输入 + 工具定义 + RAG + 记忆管理
        |
        v
2025-2026: Agent Skill（智能体技能）
    模块化、可复用、按需加载、跨平台的技能包
```

### 关键概念：上下文工程

Andrej Karpathy（前特斯拉 AI 总监、OpenAI 创始成员）说过：

> "Prompt Engineering 正在被 Context Engineering 取代。
> 真正的技术不只是写一句好的提示词，而是**架构整个上下文**。"

**上下文工程 = 设计并优化你提供给 AI 的所有信息**，包括：
- 系统提示词（System Prompt）
- 用户输入的结构化格式
- 工具定义与使用说明
- 检索增强生成（RAG）
- 短期/长期记忆管理
- 输入输出的结构化约束

**Skill 就是上下文工程的最佳实践产物** —— 它把上面这些东西打包成了一个标准化、可复用的模块。

## 3. Skill vs Prompt vs Rule vs MCP

你可能已经接触过这些概念，下面用一个表格说清它们的区别：

| 对比项 | 普通 Prompt | Rule / 规则文件 | MCP (工具协议) | Skill (技能) |
|--------|-----------|----------------|---------------|-------------|
| **本质** | 一句话指令 | 全局行为守则 | 外部工具连接 | 岗位培训手册 |
| **形式** | 文本输入 | .windsurfrules 等 | JSON 配置+服务端 | SKILL.md + 资源文件夹 |
| **加载方式** | 每次手动输入 | 始终生效 | 启动时全量加载 | 按需加载（渐进式） |
| **复用性** | 低（复制粘贴） | 中（项目级别） | 高（标准协议） | 高（文件夹即技能） |
| **Token 效率** | 低 | 中 | 低（全量加载） | 高（只加载需要的） |
| **共享性** | 差 | 中 | 好 | 好（Git/市场） |
| **适用场景** | 简单问答 | 代码风格规范 | API/数据库连接 | 复杂工作流程 |

### 用"实习生"来理解

把 AI 想象成一个聪明但没经验的实习生：

- **Prompt** = 你每次都从头教他怎么做（今天教一遍，明天还得重新教）
- **Rule** = 你在他工位上贴了一张"公司行为守则"（一直生效，但只管态度和格式）
- **MCP** = 你给他电脑装了各种软件和 API（他能用工具，但不知道什么时候该用、怎么组合）
- **Skill** = 你给他一整套"岗位培训大礼包"（SOP + 流程图 + 话术模板 + 脚本），告诉他："做这类事就按这个来"

## 4. Skill 的核心组成

一个 Skill 最简单的形式就是 **一个文件夹 + 一个 SKILL.md 文件**：

```
my-skill/
└── SKILL.md    （唯一必须的文件）
```

SKILL.md 里包含两部分：

```markdown
---
name: my-awesome-skill
description: 这个技能做什么、什么时候该用它
---

# 技能标题

## 使用场景
什么情况下应该触发这个技能...

## 执行指令
具体的步骤和规则...

## 示例
输入输出的例子...
```

**上半部分（--- 之间）** = 元数据（YAML frontmatter）
- `name`：技能名称（必填）
- `description`：什么时候用它（必填，AI 靠这个判断是否加载）

**下半部分** = 正文（Markdown）
- AI 被激活后真正执行的指令
- 写得越清晰、越具体，AI 表现越好

## 5. Skill 的工作流程

当你使用支持 Skill 的 AI 工具时，背后发生了三步：

```
第1步：发现（Discovery）
    AI 启动时只加载所有 Skill 的 name + description
    极小的 token 开销，不影响性能
        |
        v
第2步：激活（Activation）
    用户发送任务 → AI 判断匹配哪个 Skill
    → 读取该 Skill 的完整 SKILL.md 内容
        |
        v
第3步：执行（Execution）
    AI 按照 SKILL.md 中的指令执行任务
    需要时才加载额外的参考文件或运行脚本
```

**这就是"渐进式披露"（Progressive Disclosure）的核心思想：**
- 不是一次性把所有内容塞给 AI
- 而是像洋葱一样一层一层展开
- 只在需要时才加载更多信息
- 极大节省 token，保持 AI 响应速度

## 6. 支持 Skill 的工具和平台

目前（2025-2026年），以下主流 AI 工具已支持或兼容 Skill：

| 工具 | Skill 存放位置 | 说明 |
|------|--------------|------|
| **Claude Code** | `~/.claude/skills/` 或 `.claude/skills/` | 原生支持，体验最完整 |
| **GitHub Copilot** | `.github/skills/` | VS Code 中使用 |
| **Cursor** | `.cursor/skills/` | 支持从 GitHub 安装 |
| **Windsurf** | `.windsurf/workflows/` | 通过 workflow 实现类似功能 |
| **其他** | 标准正在统一中 | 参见 agentskills.io |

## 7. 一个真实的 Skill 示例

来看一个最简单的实际 Skill —— "代码注释专家"：

```markdown
---
name: code-comment-expert
description: >-
  为代码添加专业、清晰的中英双语注释。
  适合缺少文档、可读性差、需要分享审查的代码。
---

# 代码注释专家

## 核心原则
- 只在缺少注释或可读性明显不足处添加
- 优先使用英文 JSDoc / TSDoc 风格
- 复杂逻辑处额外加一行中文解释
- 注释精炼，每行不超过 80 字符
- 绝不修改原有逻辑

## 输出格式（严格遵守）
1. 先输出完整修改后的代码块
2. 再用 diff 形式展示只改动注释的部分
3. 最后说明加了哪些注释、理由
```

使用时，你只需对 AI 说：

```
帮我给这段代码加注释
```

AI 会自动匹配到 `code-comment-expert` 这个 Skill（因为 description 中提到了"加注释"），
然后按照 SKILL.md 中定义的规则和格式来执行。

## 8. 小结

| 概念 | 说明 |
|------|------|
| Skill（技能） | 给 AI 的模块化培训手册，Markdown 文件形式 |
| SKILL.md | 技能的核心文件，包含元数据和执行指令 |
| 上下文工程 | 设计并优化提供给 AI 的所有信息 |
| 渐进式披露 | 按需加载，不一次性塞满上下文窗口 |
| 元数据 | name + description，AI 靠它判断是否加载技能 |
| 正文指令 | AI 被激活后具体执行的规则和步骤 |

### 关键记忆点

```
Skill = 可复用的 Prompt + 结构化的格式 + 按需加载的机制

一个 Skill = 一个文件夹 + 一个 SKILL.md

SKILL.md = YAML 元数据 + Markdown 正文指令
```
