### 批处理（Batching）

```
vLLM 自动实现连续批处理（Continuous Batching）：
- 动态合并多个请求
- 不等待所有请求完成，先完成的先返回
- 大幅提升吞吐量

性能对比（A100 80GB, 7B 模型）：
- 无批处理：~30 tokens/s
- 静态批处理：~200 tokens/s
- 连续批处理（vLLM）：~500+ tokens/s
```

### KV Cache 优化

```
PagedAttention（vLLM 核心技术）：
- 将 KV Cache 分页管理，类似操作系统虚拟内存
- 减少内存碎片，提升显存利用率
- 支持更大批次和更长上下文

显存占用对比（7B 模型，4096 上下文）：
- 传统方式：~20GB
- PagedAttention：~14GB（节省 30%）
```

## 3. 性能评估

```python
import time
import asyncio
from openai import AsyncOpenAI

async def benchmark(
    base_url: str,
    model: str,
    num_requests: int = 50,
    prompt: str = "写一段100字的自我介绍",
):
    client = AsyncOpenAI(base_url=base_url, api_key="token")
    
    latencies = []
    tokens_per_second = []
    
    async def single_request():
        start = time.time()
        response = await client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}],
            max_tokens=200,
        )
        elapsed = time.time() - start
        output_tokens = response.usage.completion_tokens
        
        latencies.append(elapsed)
        tokens_per_second.append(output_tokens / elapsed)
    
    # 并发发送
    start = time.time()
    await asyncio.gather(*[single_request() for _ in range(num_requests)])
    total_time = time.time() - start
    
    print(f"总请求数: {num_requests}")
    print(f"总耗时: {total_time:.2f}s")
    print(f"QPS: {num_requests / total_time:.2f}")
    print(f"平均延迟: {sum(latencies)/len(latencies):.2f}s")
    print(f"P95 延迟: {sorted(latencies)[int(0.95*len(latencies))]:.2f}s")
    print(f"平均吞吐: {sum(tokens_per_second)/len(tokens_per_second):.1f} tokens/s")

# asyncio.run(benchmark("http://localhost:8000/v1", "Qwen/Qwen2.5-7B-Instruct"))
```

## 4. 模型选择与硬件规划

```
消费级显卡（RTX 3090/4090, 24GB）：
- 7B 模型 FP16 ✓
- 7B 模型 INT4 ✓（推荐）
- 13B 模型 INT4 ✓
- 70B 模型 ✗

专业级显卡（A100 80GB）：
- 7B 模型 FP16 ✓
- 70B 模型 INT4 ✓
- 70B 模型 FP16 需要 2 张

纯 CPU（无显卡）：
- Ollama + GGUF 量化模型
- 7B INT4 可用，但速度慢（~5 tokens/s）
- 适合开发测试，不适合生产
```
