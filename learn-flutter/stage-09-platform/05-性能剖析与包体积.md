# 第 05 节：性能剖析与包体积

## 本节目标

- 用 DevTools 找出卡顿与内存问题
- 掌握 Flutter 性能优化的核心手段
- 控制包体积

## 一、性能指标

Flutter 的"帧"目标：**16ms（60fps）或 8ms（120fps）** 内完成 build + layout + paint。超过就是卡顿。

常见瓶颈：

```text
build 慢    → Widget 树过大、无谓重建
layout 慢   → 复杂约束、大列表整页重建
paint 慢    → 大图、阴影、半透明叠加
IO 阻塞 UI  → 文件/JSON 解析在主 isolate
内存上涨    → 大图缓存、Stream 未取消
```

## 二、DevTools 用法

```powershell
flutter run --profile        # 用 profile 模式测性能（接近真实）
# 运行中按 o 打开 DevTools
```

| 面板 | 找什么 |
|------|--------|
| Performance | 帧耗时、build/layout/paint 分布 |
| Widget Inspector | 组件树与重建范围 |
| Memory | 内存曲线、泄漏对象 |
| Network | 请求耗时与并发 |

## 三、Build 优化

```dart
// 1. const 优先：编译期复用，跳过重建
const Text('标题');

// 2. 缩小重建范围：Consumer / select
Consumer<AuthController>(
  builder: (context, auth, _) => Avatar(user: auth.user),
)

// 3. 列表用 builder，且列表项尽量 const
ListView.builder(
  itemBuilder: (context, i) => const SizedBox(height: 8),  // 复用实例
)

// 4. RepaintBoundary：把复杂子图隔离，重绘不牵连
RepaintBoundary(child: ChartWidget())
```

## 四、图片与 IO 优化

```dart
// 按需解码，避免 4000px 原图
Image.network(url, cacheWidth: 300)

// 大 JSON 解析丢到 isolate
final tasks = await Isolate.run(() => parseTasks(jsonString));

// 列表图片懒加载
CachedNetworkImage(imageUrl: url, memCacheWidth: 200)
```

## 五、包体积优化

```powershell
flutter build apk --analyze-size
# 输出各组件体积分布
```

手段：

1. **Tree shaking 图标**：只打包用到的 Material Icons
2. **移除无用依赖**：定期 `flutter pub outdated` / `dart pub deps`
3. **延迟加载**（Web/桌面）：`DeferredLibrary` 按需加载大模块
4. **ABI 分包**：Android 按 CPU 架构分 APK（下节）
5. **资源压缩**：图片用 WebP、字体子集化
6. **不内置大文件**：引导页/教程图片放网络加载

## 六、性能报告模板

```markdown
# 性能报告

## 测试环境
- 设备 / Flutter 版本 / 模式（profile）

## 指标
| 页面 | 平均帧 | 最坏帧 | 内存峰值 |

## 发现
1. 任务列表首帧慢：图片未按需解码 → cacheWidth
2. 详情页滚动卡顿：阴影叠加 → RepaintBoundary

## 优化结果
首帧 320ms → 180ms（-44%）
```

## 动手练习

1. 用 Performance 面板找出 TaskFlow 最卡的页面
2. 做 3 项优化（const、cacheWidth、Consumer），量化前后帧耗时
3. 跑 `--analyze-size` 记录包体积，砍掉最大的非必要依赖

## 验收标准

- 能产出带数据的性能报告
- 明白"先测量再优化"，不凭感觉改代码
- 包体积与优化手段有据可查
