## 二、ER 图（实体关系图）

### 2.1 核心概念

| 概念 | 含义 | 示例 |
|------|------|------|
| **实体 (Entity)** | 现实世界中的一个对象 | 用户、任务、项目 |
| **属性 (Attribute)** | 实体的特征 | 用户名、邮箱、年龄 |
| **关系 (Relationship)** | 实体之间的关联 | 用户"拥有"任务 |

### 2.2 三种关系类型

```
一对一 (1:1)     用户 ←→ 用户详情
                  一个用户只有一份详情，一份详情只属于一个用户

一对多 (1:N)     用户 ←→ 任务
                  一个用户有多个任务，一个任务只属于一个用户

多对多 (M:N)     任务 ←→ 标签
                  一个任务有多个标签，一个标签属于多个任务
                  需要中间表 task_tags 来实现
```

### 2.3 TaskFlow 项目 ER 图

```
┌──────────┐     1:N      ┌──────────┐     M:N     ┌──────────┐
│  users   │─────────────→│  tasks   │←───────────→│   tags   │
│          │              │          │  (task_tags) │          │
│ id       │     1:N      │ id       │              │ id       │
│ username │←────────┐    │ title    │     N:1      │ name     │
│ email    │         │    │ status   │────────────→ │          │
│ password │         │    │ priority │  ┌──────────┐└──────────┘
```

## 三、数据库范式

范式是 **减少数据冗余、保证数据一致性** 的设计规则。

### 3.1 第一范式 (1NF) — 原子性

每个字段只存储一个值，不能是列表或集合。

```
❌ 违反 1NF：
| id | name | phones                    |
| 1  | 张三 | 13800138000, 13900139000  |   ← 一个字段存了两个电话

✅ 符合 1NF：
| id | name | phone       |
| 1  | 张三 | 13800138000 |
| 1  | 张三 | 13900139000 |

或者拆成单独的 phones 表：
users: id, name
phones: id, user_id, phone_number
```

### 3.2 第二范式 (2NF) — 完全依赖主键

在 1NF 基础上，非主键字段必须 **完全依赖** 于主键，不能只依赖主键的一部分。

```
❌ 违反 2NF（复合主键场景）：
| student_id | course_id | student_name | grade |
  student_name 只依赖 student_id，不依赖 course_id

✅ 符合 2NF：拆成两张表
students: student_id, student_name
enrollments: student_id, course_id, grade
```

### 3.3 第三范式 (3NF) — 消除传递依赖

非主键字段之间不能有依赖关系。

```
❌ 违反 3NF：
| id | name | department_id | department_name |
  department_name 依赖 department_id，而不是直接依赖主键 id

✅ 符合 3NF：
users: id, name, department_id
departments: id, name
```

### 3.4 实际开发中的平衡

> 严格遵循范式会导致表太多、JOIN 太多、查询变慢。

**实际原则：**
- **OLTP（在线事务处理）** — 遵循 3NF，保证数据一致性
- **OLAP（在线分析处理）** — 适度反范式化，用冗余换查询速度
- **读多写少** 的字段 — 可以适度冗余（如在任务表存用户名）
- **用缓存代替反范式** — Redis 缓存热点数据

## 四、索引

### 4.1 什么是索引？

索引是数据库中的 **查找目录**，类比一本书的目录。没有索引时，查询需要扫描整张表（全表扫描）；有索引后，可以快速定位到目标行。

```
没有索引：从第1页翻到第1000页找 "Django"     → O(N)
有索引：   查目录 → 第238页                   → O(log N)
```

### 4.2 创建索引

```sql
-- 单列索引
CREATE INDEX idx_users_email ON users(email);

-- 唯一索引（确保列值不重复）
CREATE UNIQUE INDEX idx_users_email_unique ON users(email);

-- 复合索引（多列）
CREATE INDEX idx_tasks_status_priority ON tasks(status, priority);

-- 部分索引（只索引满足条件的行）
CREATE INDEX idx_tasks_active ON tasks(status)
WHERE status != 'completed';

-- JSONB 索引
CREATE INDEX idx_profiles_metadata ON user_profiles USING GIN(metadata);

-- 查看索引
\di                                      -- psql 命令
SELECT * FROM pg_indexes WHERE tablename = 'users';
```

### 4.3 索引使用原则

**适合加索引的场景：**
- WHERE 条件中频繁使用的列
- JOIN 的连接列（外键）
- ORDER BY 排序的列
- 唯一性约束的列

**不适合加索引的场景：**
- 数据量很小的表（几百行）
- 频繁更新的列（索引维护有开销）
- 选择性很低的列（如 `gender` 只有男/女，区分度太低）

### 4.4 EXPLAIN — 查看查询执行计划

```sql
-- 查看查询计划
EXPLAIN SELECT * FROM users WHERE email = 'test@example.com';

-- 查看详细执行信息（实际执行）
EXPLAIN ANALYZE SELECT * FROM tasks WHERE status = 'pending' ORDER BY priority DESC;

-- 结果解读
-- Seq Scan    → 全表扫描（没用到索引）
-- Index Scan  → 使用了索引（好！）
-- Sort        → 内存排序
-- Hash Join   → 哈希连接
```

## 五、事务

### 5.1 什么是事务？

事务是一组操作的 **原子单元** —— 要么全部成功，要么全部失败回滚。

**经典例子：转账**
```
张三 → 李四 转 100 元：
1. 张三余额 -100
2. 李四余额 +100
这两步必须同时成功或同时失败，否则钱就"消失"或"凭空产生"了。
```

### 5.2 ACID 特性

| 特性 | 含义 | 说明 |
|------|------|------|
| **A (Atomicity)** | 原子性 | 事务要么全部执行，要么全部回滚 |
| **C (Consistency)** | 一致性 | 事务执行前后数据库保持一致状态 |
| **I (Isolation)** | 隔离性 | 并发事务之间互不干扰 |
| **D (Durability)** | 持久性 | 事务提交后数据永久保存 |

### 5.3 使用事务

```sql
-- 显式事务
BEGIN;                                       -- 开始事务

UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;

-- 如果没问题
COMMIT;                                      -- 提交事务

-- 如果出问题
ROLLBACK;                                    -- 回滚事务

-- SAVEPOINT — 部分回滚
BEGIN;
INSERT INTO tasks (title) VALUES ('任务1');
SAVEPOINT sp1;
INSERT INTO tasks (title) VALUES ('任务2');
ROLLBACK TO sp1;                             -- 只回滚到 sp1，任务1 保留
COMMIT;
```

### 5.4 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | PostgreSQL 默认 |
|------|------|-----------|------|----------------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | — |
| **READ COMMITTED** | 不可能 | 可能 | 可能 | **✅ 默认** |
| REPEATABLE READ | 不可能 | 不可能 | 可能 | — |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 | — |

```sql
-- 设置事务隔离级别
BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
-- ... 操作 ...
COMMIT;
```

## 六、约束

```sql
CREATE TABLE tasks (
    id          SERIAL PRIMARY KEY,                            -- 主键约束
    title       VARCHAR(200) NOT NULL,                         -- 非空约束
    email       VARCHAR(255) UNIQUE,                           -- 唯一约束
    priority    INTEGER DEFAULT 0 CHECK (priority BETWEEN 0 AND 10), -- 检查约束
    assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,     -- 外键约束
    created_at  TIMESTAMP DEFAULT NOW()                        -- 默认值约束
);

-- 外键的删除行为
-- ON DELETE CASCADE    → 主表删除时，子表关联行也删除
-- ON DELETE SET NULL   → 主表删除时，子表外键设为 NULL
-- ON DELETE RESTRICT   → 主表有关联数据时不允许删除（默认）
-- ON DELETE SET DEFAULT → 主表删除时，子表外键设为默认值
```

## 七、TaskFlow 数据库设计实战

```sql
-- 完整的 TaskFlow 建表 SQL

-- 用户表
CREATE TABLE users (
    id          SERIAL PRIMARY KEY,
    username    VARCHAR(50) UNIQUE NOT NULL,
    email       VARCHAR(255) UNIQUE NOT NULL,
    password    VARCHAR(255) NOT NULL,
    avatar      VARCHAR(500),
    is_active   BOOLEAN DEFAULT TRUE,
    is_staff    BOOLEAN DEFAULT FALSE,
    created_at  TIMESTAMP DEFAULT NOW(),
    updated_at  TIMESTAMP DEFAULT NOW()
);

-- 用户资料表 (1:1)
CREATE TABLE profiles (
    id          SERIAL PRIMARY KEY,
    user_id     INTEGER UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    bio         TEXT DEFAULT '',
    phone       VARCHAR(20),
    location    VARCHAR(100),
    settings    JSONB DEFAULT '{}'::jsonb
);

-- 项目表
CREATE TABLE projects (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    description TEXT DEFAULT '',
    owner_id    INTEGER REFERENCES users(id) ON DELETE CASCADE,
    is_archived BOOLEAN DEFAULT FALSE,
    created_at  TIMESTAMP DEFAULT NOW(),
    updated_at  TIMESTAMP DEFAULT NOW()
);

-- 项目成员表 (M:N — users 和 projects)
CREATE TABLE project_members (
    id          SERIAL PRIMARY KEY,
    project_id  INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    user_id     INTEGER REFERENCES users(id) ON DELETE CASCADE,
    role        VARCHAR(20) DEFAULT 'member',  -- owner / admin / member
    joined_at   TIMESTAMP DEFAULT NOW(),
    UNIQUE(project_id, user_id)                -- 同一项目中用户不重复
);

-- 标签表
CREATE TABLE tags (
    id   SERIAL PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL,
    color VARCHAR(7) DEFAULT '#666666'         -- 颜色代码
);

-- 任务表
CREATE TABLE tasks (
    id          SERIAL PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    description TEXT DEFAULT '',
    status      VARCHAR(20) DEFAULT 'pending'
                CHECK (status IN ('pending', 'in_progress', 'completed', 'cancelled')),
    priority    INTEGER DEFAULT 0 CHECK (priority BETWEEN 0 AND 10),
    project_id  INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    assignee_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
    creator_id  INTEGER REFERENCES users(id) ON DELETE SET NULL,
    due_date    DATE,
    created_at  TIMESTAMP DEFAULT NOW(),
    updated_at  TIMESTAMP DEFAULT NOW()
);

-- 任务-标签关联表 (M:N)
CREATE TABLE task_tags (
    task_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
    tag_id  INTEGER REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (task_id, tag_id)
);

-- 评论表
CREATE TABLE comments (
    id         SERIAL PRIMARY KEY,
    content    TEXT NOT NULL,
    task_id    INTEGER REFERENCES tasks(id) ON DELETE CASCADE,
    user_id    INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- 创建索引
CREATE INDEX idx_tasks_project ON tasks(project_id);
CREATE INDEX idx_tasks_assignee ON tasks(assignee_id);
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_created ON tasks(created_at);
CREATE INDEX idx_comments_task ON comments(task_id);
CREATE INDEX idx_project_members_user ON project_members(user_id);
```
