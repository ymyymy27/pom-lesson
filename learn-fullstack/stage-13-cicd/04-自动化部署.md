# 第 04 节：自动化部署

## 一、自动化部署流程

```
开发者 Push 到 main 分支
    ↓
GitHub Actions CI：运行测试
    ↓ 全部通过
GitHub Actions CD：
    1. 构建 Docker 镜像
    2. 推送到 Docker Hub（或 GitHub Container Registry）
    3. SSH 到服务器
    4. 拉取最新镜像
    5. 重启服务
    6. 运行迁移
    7. 健康检查
    ↓
部署完成，通知开发者
```

## 二、CD Workflow

```yaml
# .github/workflows/cd.yml
name: CD

on:
  push:
    branches: [main]
  workflow_dispatch:  # 手动触发

# 确保同时只有一个部署在运行
concurrency:
  group: production
  cancel-in-progress: false

jobs:
  # ==================== 先运行测试 ====================
  test:
    uses: ./.github/workflows/ci.yml  # 复用 CI Workflow

  # ==================== 构建并推送镜像 ====================
  build:
    name: Build & Push Images
    runs-on: ubuntu-latest
    needs: test

    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      # 构建并推送后端镜像
      - name: Build and push backend
        uses: docker/build-push-action@v5
        with:
          context: ./backend
          push: true
          tags: |
            ${{ secrets.DOCKER_USERNAME }}/taskflow-backend:latest
            ${{ secrets.DOCKER_USERNAME }}/taskflow-backend:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      # 构建并推送前端镜像
      - name: Build and push frontend
        uses: docker/build-push-action@v5
        with:
          context: ./frontend
          push: true
          tags: |
            ${{ secrets.DOCKER_USERNAME }}/taskflow-frontend:latest
            ${{ secrets.DOCKER_USERNAME }}/taskflow-frontend:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ==================== 部署到服务器 ====================
  deploy:
    name: Deploy to Production
    runs-on: ubuntu-latest
    needs: build
    environment: production  # 需要审批（可选）

    steps:
      - uses: actions/checkout@v4

      # 通过 SSH 部署
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd ${{ secrets.DEPLOY_PATH }}
            
            # 拉取最新代码
            git pull origin main
            
            # 拉取最新镜像
            docker compose -f docker-compose.prod.yml pull
            
            # 重启服务（零停机）
            docker compose -f docker-compose.prod.yml up -d --no-build
            
            # 运行迁移
            docker compose -f docker-compose.prod.yml exec -T backend \
              python manage.py migrate --noinput
            
            # 收集静态文件
            docker compose -f docker-compose.prod.yml exec -T backend \
              python manage.py collectstatic --noinput
            
            # 清理旧镜像
            docker image prune -f
            
            # 健康检查
            sleep 10
            curl -sf http://localhost/api/v1/health/ || exit 1
            
            echo "✅ 部署成功: $(date)"

      # 部署通知
      - name: Notify success
        if: success()
        run: echo "部署成功！Commit: ${{ github.sha }}"

      - name: Notify failure
        if: failure()
        run: echo "部署失败！请检查日志。"
```

## 三、部署脚本

```bash
#!/bin/bash
# scripts/deploy.sh — 服务器端部署脚本
set -e

DEPLOY_DIR="/home/deploy/taskflow"
COMPOSE_FILE="docker-compose.prod.yml"
ENV_FILE=".env.prod"

cd $DEPLOY_DIR

echo "========== 开始部署 $(date) =========="

# 1. 备份数据库
echo ">>> 备份数据库..."
./scripts/backup.sh

# 2. 拉取最新代码
echo ">>> 拉取代码..."
git pull origin main

# 3. 拉取最新镜像
echo ">>> 拉取镜像..."
docker compose -f $COMPOSE_FILE --env-file $ENV_FILE pull

# 4. 重启服务
echo ">>> 重启服务..."
docker compose -f $COMPOSE_FILE --env-file $ENV_FILE up -d --no-build

# 5. 运行迁移
echo ">>> 数据库迁移..."
docker compose -f $COMPOSE_FILE exec -T backend python manage.py migrate --noinput

# 6. 收集静态文件
echo ">>> 收集静态文件..."
docker compose -f $COMPOSE_FILE exec -T backend python manage.py collectstatic --noinput

# 7. 清理
echo ">>> 清理旧镜像..."
docker image prune -f

# 8. 健康检查
echo ">>> 健康检查..."
sleep 10
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost/api/v1/health/ || echo "000")

if [ "$HTTP_CODE" = "200" ]; then
    echo "========== ✅ 部署成功 $(date) =========="
else
    echo "========== ❌ 健康检查失败 (HTTP $HTTP_CODE) =========="
    echo "查看日志: docker compose -f $COMPOSE_FILE logs --tail=50"
    exit 1
fi
```

## 四、回滚策略

```bash
#!/bin/bash
# scripts/rollback.sh — 回滚到上一个版本
set -e

DEPLOY_DIR="/home/deploy/taskflow"
COMPOSE_FILE="docker-compose.prod.yml"

cd $DEPLOY_DIR

# 获取当前版本
CURRENT=$(git rev-parse HEAD)
echo "当前版本: $CURRENT"

# 回滚到上一个 Commit
git log --oneline -5
echo ""
read -p "输入要回滚到的 Commit Hash: " TARGET_HASH

git checkout $TARGET_HASH

# 重新构建并部署
docker compose -f $COMPOSE_FILE up -d --build

# 迁移（如果有 migration 回滚需要手动处理）
docker compose -f $COMPOSE_FILE exec -T backend python manage.py migrate --noinput

# 健康检查
sleep 10
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost/api/v1/health/ || echo "000")

if [ "$HTTP_CODE" = "200" ]; then
    echo "✅ 回滚成功"
else
    echo "❌ 回滚后健康检查失败"
    exit 1
fi
```

## 五、健康检查端点

```python
# apps/core/views.py
from django.http import JsonResponse
from django.db import connection
from django.core.cache import cache

def health_check(request):
    """健康检查端点"""
    status = {'status': 'ok', 'checks': {}}
    http_status = 200
    
    # 检查数据库
    try:
        with connection.cursor() as cursor:
            cursor.execute("SELECT 1")
        status['checks']['database'] = 'ok'
    except Exception as e:
        status['checks']['database'] = f'error: {str(e)}'
        http_status = 503
    
    # 检查 Redis
    try:
        cache.set('health_check', 'ok', timeout=10)
        if cache.get('health_check') == 'ok':
            status['checks']['redis'] = 'ok'
        else:
            raise Exception('Cache read failed')
    except Exception as e:
        status['checks']['redis'] = f'error: {str(e)}'
        http_status = 503
    
    if http_status != 200:
        status['status'] = 'unhealthy'
    
    return JsonResponse(status, status=http_status)
```

```python
# config/urls.py
from apps.core.views import health_check

urlpatterns = [
    path('api/v1/health/', health_check, name='health-check'),
    ...
]
```

## 六、Git 分支策略

```
main        ─────●─────●─────●─────●────── 生产环境（自动部署）
                 ↑     ↑     ↑     ↑
develop     ──●──●──●──●──●──●──●──●────── 开发分支
              ↑     ↑        ↑
feature/*   ──●──●──●        │              功能分支
                              ↑
hotfix/*                   ───●──           紧急修复
```

```
功能开发流程：
1. 从 develop 创建 feature/xxx 分支
2. 开发完成后，创建 PR 到 develop
3. CI 自动运行测试
4. Code Review 通过后合并
5. develop → main 时触发自动部署
```
