# 第1课：AI 技术认知 — 产品经理必知的 AI 全景图

## 1. 为什么 AI PM 需要懂技术？

```
AI PM 不需要写代码，但需要：
  1. 判断可行性：这个需求 AI 能不能做？做到什么程度？
  2. 沟通算法：和算法工程师对话时不被"技术忽悠"
  3. 设计产品：理解 AI 的能力边界，才能设计合理的交互
  4. 评估效果：看得懂模型指标，判断模型是否达标

你不需要知道 Transformer 的数学公式
你需要知道"大模型能做什么、不能做什么、什么场景该用什么方案"
```

## 3. 机器学习基础概念

### 3.1 三大学习范式

| 范式 | 特点 | AI PM 需要知道的 |
|------|------|-----------------|
| 监督学习 | 有标签数据，学习输入→输出映射 | 需要标注数据，数据质量决定效果 |
| 无监督学习 | 无标签，发现数据结构 | 用户分群、异常检测 |
| 强化学习 | 与环境交互，通过奖励学习 | 推荐系统、游戏AI、RLHF |

### 3.2 模型训练流程（PM视角）

```
数据准备 → 模型训练 → 模型评估 → 部署上线 → 监控迭代

PM 在各环节的参与：
  数据准备: 定义标注标准、验收数据质量
  模型训练: 了解进度，不参与具体训练
  模型评估: 参与制定评估标准，审核badcase
  部署上线: 设计灰度策略，定义兜底方案
  监控迭代: 收集反馈，推动模型优化
```

### 3.3 模型 vs 规则

```
什么时候用模型？什么时候用规则？

用规则：
  · 逻辑明确、不常变化（"订单金额>10000需审核"）
  · 数据不够训练模型
  · 需要100%可控和可解释

用模型：
  · 规则写不完（"判断一张图是不是猫"）
  · 场景复杂多变（"根据用户兴趣推荐内容"）
  · 有大量历史数据可学习

最佳实践：规则 + 模型结合
  例：AI客服
    规则: 用户说"退款" → 直接跳转退款流程（确定性高）
    模型: 用户描述模糊问题 → AI理解并分类（不确定性高）
```

## 4. 大语言模型（LLM）— 最核心的技术认知

### 4.1 什么是大模型？

```
大语言模型 (Large Language Model, LLM) = 
  在海量文本上训练的超大神经网络

核心能力：
  1. 语言理解：理解文本含义、意图、情感
  2. 语言生成：生成流畅的回复、文章、代码
  3. 推理：一定程度的逻辑推理和问题解决
  4. 上下文学习：给几个例子就能学会新任务

主流大模型：
  国外: GPT-4o, Claude, Gemini, Llama
  国内: 文心一言, 通义千问, Kimi(Moonshot), 豆包(字节), DeepSeek
```

### 4.2 大模型的能力边界（面试必考！）

```
✅ 大模型擅长的：
  · 文本生成（写作、总结、翻译）
  · 对话交互（聊天、问答）
  · 代码生成（写代码、Debug）
  · 信息提取（从长文本中提取关键信息）
  · 创意任务（头脑风暴、文案创作）

❌ 大模型的局限性：
  · 幻觉（Hallucination）：一本正经地编造事实
  · 时效性：训练数据有截止时间
  · 数学/逻辑推理：复杂推理容易出错
  · 私有知识：不知道公司内部数据
  · 确定性：同一问题可能给出不同答案
  · 长文本：超长输入可能遗漏中间内容

面试回答模板：
  "大模型的核心能力是语言理解和生成，但存在幻觉问题和
   知识时效性问题。在产品设计中需要：
   1. 用 RAG 补充私有/实时知识
   2. 用工具调用解决确定性任务（计算、查询）
   3. 设计人工审核机制处理高风险场景
   4. 明确告知用户AI可能出错"
```

### 4.3 大模型关键概念

| 概念 | 解释 | PM 需要知道 |
|------|------|-----------|
| Token | 模型处理文本的最小单位 | 影响成本和速度，中文1字≈1-2 token |
| 上下文窗口 | 模型一次能处理的最大文本量 | 决定能输入多少内容（4K/32K/128K/200K） |
| Temperature | 控制输出的随机性 | 0=确定性高, 1=创造性高 |
| Prompt | 给模型的指令/提示 | Prompt 设计直接影响效果 |
| Fine-tuning | 用专有数据微调模型 | 成本高但效果好，需要标注数据 |
| RAG | 检索增强生成 | 让模型回答基于自己的知识库 |
| Agent | 智能体 | 模型+工具+记忆+规划 |
| 多模态 | 处理文本+图片+语音+视频 | GPT-4o, Gemini 等支持 |

### 4.4 技术方案选型（PM 决策树）

```
用户需求
  │
  ├── 需要私有知识？
  │     ├── 是 → RAG（知识库检索+LLM生成）
  │     └── 否 → 直接调用 LLM API
  │
  ├── 需要执行操作？（查天气/订机票/发邮件）
  │     ├── 是 → Agent（LLM + 工具调用）
  │     └── 否 → 纯对话
  │
  ├── 需要高度定制化？
  │     ├── 是 → Fine-tuning（微调）
  │     └── 否 → Prompt Engineering（提示词工程）
  │
  ├── 成本敏感？
  │     ├── 是 → 小模型/开源模型（Qwen/Llama）
  │     └── 否 → 商业API（GPT-4o/Claude）
  │
  └── 延迟要求？
        ├── 实时（<1s）→ 小模型 + 缓存
        └── 可等待（3-10s）→ 大模型
```

## 5. AI 产品技术架构（PM视角）

### 5.1 典型 AI 对话产品架构

```
用户输入
  ↓
[前端] 对话界面
  ↓
[网关] 鉴权/限流/负载均衡
  ↓
[业务层] 
  · 用户管理
  · 对话管理（历史/上下文）
  · 安全过滤（敏感词/Prompt注入检测）
  ↓
[AI层]
  · Prompt 构建（系统提示词 + 用户消息 + 上下文）
  · RAG 检索（如需要知识库）
  · 模型调用（LLM API / 本地部署）
  · 工具调用（如需要 Agent）
  ↓
[输出处理]
  · 安全过滤（输出内容审核）
  · 格式化（Markdown渲染）
  · 流式返回（打字机效果）
  ↓
用户看到回复
```

### 5.2 关键技术指标

| 指标 | 含义 | 参考值 |
|------|------|--------|
| 首字延迟 (TTFT) | 用户发送到看到第一个字的时间 | < 2秒 |
| 生成速度 | 每秒输出的token数 | > 30 token/s |
| 准确率 | 回答的正确程度 | 看场景，通常 > 80% |
| 安全率 | 不产生有害内容的比例 | > 99.9% |
| 可用性 | 服务正常运行时间 | > 99.9% |
| 单次成本 | 每次对话的API成本 | 几分钱~几毛钱 |

## 6. AI 行业生态

### 6.1 AI 产业链

```
基础层（算力+数据）
  · GPU芯片：NVIDIA(A100/H100), 华为昇腾
  · 云服务：AWS, 阿里云, 腾讯云
  · 数据标注：Scale AI, 数据堂

模型层（大模型+平台）
  · 闭源：OpenAI, Anthropic, Google
  · 开源：Meta(Llama), 阿里(Qwen), DeepSeek
  · 平台：HuggingFace, ModelScope

应用层（AI产品）
  · 通用助手：ChatGPT, Kimi, 豆包
  · 垂直场景：AI客服, AI编程, AI设计
  · 工具平台：Coze, Dify（低代码AI搭建）

你的机会主要在 应用层 和 模型层与应用层的交界处
```

### 6.2 AI PM 的四种方向

```
1. AI 原生应用 PM
   做全新的 AI 产品（如 ChatGPT, Kimi）
   核心：产品创新 + 用户体验

2. AI+ 行业 PM
   将 AI 能力融入传统行业（如 AI+医疗, AI+教育）
   核心：行业理解 + AI 落地

3. AI 平台 PM
   做 AI 开发平台/工具（如 Coze, Dify）
   核心：技术理解 + 开发者体验

4. AI 数据 PM
   做数据标注、数据管理、模型评估平台
   核心：数据思维 + 工具设计
```
