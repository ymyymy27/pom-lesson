# 第2课：模型评估与数据思维

## 1. 为什么 AI PM 必须懂模型评估？

```
场景1：算法同事说"模型准确率95%"，你能上线吗？
  → 不一定。95%的准确率在不均衡数据中可能毫无意义

场景2：老板问"AI客服效果怎么样？"
  → 你需要定义"效果好"的标准，并用数据回答

场景3：两个模型方案，选哪个？
  → 你需要知道用什么指标比较，权衡取舍

AI PM 不需要自己调模型，但需要：
  ✅ 定义评估标准（什么算"好"）
  ✅ 看懂评估报告（模型达标了吗）
  ✅ 识别 badcase（哪些场景效果差）
  ✅ 推动优化（告诉算法团队优化方向）
```

## 2. 分类模型评估指标（复习+PM视角）

### 2.1 核心指标速查

| 指标 | 计算 | 一句话解释 | 什么时候看 |
|------|------|-----------|-----------|
| Accuracy | 正确数/总数 | 总正确率 | 数据均衡时 |
| Precision | TP/(TP+FP) | 预测为正的里面多少真的正 | 误报代价高时（垃圾邮件） |
| Recall | TP/(TP+FN) | 真正为正的里面抓到多少 | 漏报代价高时（疾病检测） |
| F1 | 2×P×R/(P+R) | P和R的调和平均 | P和R都重要时 |
| AUC | ROC曲线下面积 | 模型区分正负例的能力 | 不确定阈值时 |

### 2.2 PM 视角的指标选择

```
面试题："你们的AI客服分类模型，应该看什么指标？"

回答思路：
  1. 先分析业务场景中 FP 和 FN 的代价
     FP（误分类）：用户问退款，AI分到了咨询类 → 用户体验差但不严重
     FN（漏分类）：用户投诉被分到了普通咨询 → 投诉处理延迟，严重！

  2. 确定指标优先级
     投诉类别：优先看 Recall（不能漏掉投诉）
     普通分类：看 F1（平衡即可）
     整体：看 Weighted F1 和 AUC

  3. 设定达标阈值
     "投诉类 Recall > 95%，整体 F1 > 85% 可上线"
```

### 2.3 不均衡数据的陷阱

```
你们的欺诈检测模型：
  正常交易：99%
  欺诈交易：1%

模型全部预测为"正常" → Accuracy = 99%！
但 Recall = 0%，一个欺诈都没抓到

PM 如何应对：
  1. 不能只看 Accuracy
  2. 重点看少数类的 Precision 和 Recall
  3. 要求算法用 F1 或 AUC 作为优化目标
  4. 评估时看 classification_report（每个类别的指标）
```

## 3. 大模型/生成式 AI 的评估

### 3.1 传统 ML vs 大模型评估的区别

```
传统 ML 评估：
  · 有标准答案（分类/回归）
  · 指标明确（Accuracy/F1/MSE）
  · 自动化评估

大模型评估：
  · 没有唯一标准答案（"写一首诗"的好坏？）
  · 需要人工评估 + 自动评估结合
  · 多维度评估（准确性/流畅性/安全性/有用性）
```

### 3.2 大模型评估维度

| 维度 | 评估内容 | 评估方式 |
|------|---------|---------|
| **准确性** | 回答是否正确，有无事实错误 | 人工标注 + 知识库比对 |
| **相关性** | 回答是否切题，是否回答了用户的问题 | 人工评分 (1-5分) |
| **完整性** | 信息是否充分，有无遗漏 | 人工评分 |
| **安全性** | 是否有有害/违规/偏见内容 | 安全模型自动检测 + 人工 |
| **幻觉率** | 编造的信息占比 | 对比知识库，标注幻觉 |
| **流畅性** | 语言是否通顺自然 | 自动指标 + 人工 |
| **延迟** | 首字延迟、总响应时间 | 自动监控 |
| **用户满意度** | 用户是否满意 | 👍👎反馈、NPS |

### 3.3 大模型评估方法

```
方法1: 人工评估（最可靠但最贵）
  · 标注员对回答打分（1-5分多维度）
  · 优点：最接近真实体验
  · 缺点：成本高、速度慢、主观性
  · 适用：上线前评估、定期抽检

方法2: 模型互评（LLM-as-Judge）
  · 用 GPT-4 等强模型评估其他模型的回答
  · 优点：成本低、速度快、可大规模
  · 缺点：有偏差，不如人工准确
  · 适用：日常迭代、大规模评估

方法3: 自动指标
  · BLEU/ROUGE：与参考答案的文本相似度
  · Perplexity：模型对文本的困惑度
  · 优点：完全自动
  · 缺点：和人类判断相关性有限
  · 适用：技术迭代中的快速对比

方法4: 用户反馈
  · 👍👎 按钮、满意度问卷
  · 优点：最真实的用户声音
  · 缺点：反馈率低、有偏
  · 适用：上线后持续监控

最佳实践：四种方法结合
  开发阶段: 自动指标 + 模型互评
  上线前:   人工评估（抽样100-500条）
  上线后:   用户反馈 + 自动监控 + 定期人工抽检
```

### 3.4 Badcase 分析（PM 核心工作）

```
什么是 Badcase？
  模型回答得不好的案例

PM 如何做 Badcase 分析：

1. 收集 Badcase
   · 用户 👎 反馈
   · 人工抽检发现
   · 特定测试集

2. 分类 Badcase
   ┌────────────────┬──────────────────────────┐
   │ 类型           │ 示例                      │
   ├────────────────┼──────────────────────────┤
   │ 事实性错误     │ "北京是日本的首都"         │
   │ 幻觉           │ 编造不存在的论文/数据       │
   │ 拒绝回答       │ 该回答的问题说"我不知道"    │
   │ 过度回答       │ 简单问题给了超长答案         │
   │ 不安全         │ 输出有害/违规内容            │
   │ 格式错误       │ 要求JSON但输出了纯文本       │
   │ 上下文遗忘     │ 忘了之前对话说过的内容       │
   └────────────────┴──────────────────────────┘

3. 分析原因
   · Prompt 不够好？→ 优化 Prompt
   · 知识库没覆盖？→ 补充知识库
   · 模型能力不足？→ 换更强的模型 / Fine-tuning
   · 安全策略过严？→ 调整安全过滤规则

4. 推动修复
   · 按严重程度排优先级
   · 制定具体优化方案
   · 修复后回归测试
```

## 4. 数据思维

### 4.1 数据质量 > 数据数量

```
"Garbage In, Garbage Out" — 烂数据训练不出好模型

数据质量的维度：
  准确性：标注/内容是否正确？
  完整性：是否有缺失值、遗漏场景？
  一致性：相同情况的标注是否一致？
  时效性：数据是否过时？
  代表性：是否覆盖了各种用户和场景？

PM 的数据职责：
  1. 制定标注标准（标注指南）
  2. 抽检标注质量（一致性/准确率）
  3. 发现数据盲区（哪些场景数据不足）
  4. 推动数据补充
```

### 4.2 标注管理

```
标注流程：
  1. 制定标注指南（详细的规则和示例）
  2. 标注员培训（确保理解标准）
  3. 试标注（小批量验证标准是否合理）
  4. 正式标注
  5. 质检（交叉验证、抽样检查）

标注质量指标：
  标注一致性（Kappa系数）：两个标注员对同一数据标注一致的程度
    Kappa > 0.8:  很好
    Kappa 0.6-0.8: 还行
    Kappa < 0.6:  标注标准有问题，需要修改

PM 经常踩的坑：
  ❌ 标注指南太模糊 → 标注员理解不一致
  ❌ 不做质检 → 标注质量参差不齐
  ❌ 标注标准中途改 → 前后数据不一致
```

### 4.3 数据飞轮

```
好产品 → 更多用户 → 更多数据 → 更好的模型 → 更好的产品
                          ↑                      │
                          └──────────────────────┘
                              数据飞轮

AI 产品的核心竞争力往往是数据飞轮：
  · 用户使用产品产生数据
  · 数据用于改进模型
  · 模型改进提升用户体验
  · 更好的体验吸引更多用户

PM 需要设计数据收集机制：
  · 用户反馈（👍👎、文字反馈）
  · 行为数据（点击、停留、重新生成）
  · 主动标注（让用户帮助改进）
```

## 5. 评估体系搭建（PM 实战）

### 5.1 评估集（Evaluation Set）设计

```
为你的 AI 产品建立标准评估集：

1. 覆盖主要场景
   · 常见问题（60%）
   · 边界问题（20%）
   · 极端/对抗问题（10%）
   · 安全问题（10%）

2. 每个问题有参考答案和评分标准

3. 定期更新（每月新增+淘汰）

4. 自动化运行（每次模型更新后跑一遍）

示例评估集（AI客服）：
  Q: "我的订单什么时候发货？"
  期望: 引导用户提供订单号 → 查询物流信息
  评分: 准确性(1-5) + 有用性(1-5) + 礼貌性(1-5)
```

### 5.2 上线评估 Checklist

```
□ 自动评估指标通过（F1/AUC 达标）
□ 评估集测试通过（整体达标率 > XX%）
□ 人工抽检通过（100条 badcase 率 < 5%）
□ 安全测试通过（有害内容检出率 > 99%）
□ 性能测试通过（延迟 < 阈值）
□ 与旧版对比有提升（或至少不退化）
□ badcase 已分析并有兜底方案
```

## 6. 动手练习

1. **指标选择**：为以下场景选择合适的评估指标并说明理由
   - AI辅助医疗诊断
   - AI内容推荐
   - AI代码生成
2. **Badcase 分析**：使用 Kimi 或豆包问 10 个问题，记录 badcase，分类并分析原因
3. **评估集设计**：为一个"AI面试助手"产品设计 20 条评估用例（覆盖不同场景）
4. **标注指南**：为"AI回答质量"写一份标注指南（评分标准 1-5 分，每分有明确定义和示例）

## 7. 小结

| 概念 | PM 需要掌握的 |
|------|--------------|
| 分类指标 | Precision/Recall/F1/AUC 的含义和选择 |
| 大模型评估 | 多维度评估（准确/安全/幻觉/延迟） |
| 评估方法 | 人工+模型互评+自动指标+用户反馈 |
| Badcase | 收集→分类→分析原因→推动修复 |
| 数据质量 | 准确/完整/一致/代表性 |
| 标注管理 | 标注指南+培训+质检 |
| 数据飞轮 | 用户数据→模型改进→体验提升→更多用户 |
