# 第1课：产品思维与需求分析

## 1. 什么是产品经理？

### 一句话定义
**产品经理是"发现问题并推动解决问题的人"** —— 找到用户痛点，设计解决方案，协调团队把方案做出来。

### 产品经理的核心职责

```
发现问题 → 定义方案 → 推动落地 → 验证效果

1. 发现问题：用户调研、数据分析、市场洞察
2. 定义方案：需求文档(PRD)、原型设计、优先级排序
3. 推动落地：需求评审、项目管理、跨部门协调
4. 验证效果：数据复盘、用户反馈、迭代优化
```

### 产品经理 ≠ 项目经理

| | 产品经理 (PM) | 项目经理 (PMO) |
|---|---|---|
| 关注点 | 做什么、为什么做 | 怎么做、什么时候做完 |
| 核心能力 | 用户洞察、商业判断 | 进度管理、风险控制 |
| 决策权 | 产品方向和功能 | 项目计划和资源 |
| 衡量标准 | 产品指标（DAU/留存） | 项目按时交付率 |

## 2. 产品思维

### 2.1 用户思维

```
不是"我觉得用户需要什么"
而是"用户在什么场景下遇到了什么问题"

错误：用户需要一个更快的马
正确：用户需要更快地从A到B → 汽车

核心问题框架：
  谁（Who）：目标用户是谁？
  什么场景（When/Where）：在什么情况下？
  什么问题（What）：遇到了什么困难？
  为什么（Why）：这个问题为什么值得解决？
  怎么解决（How）：最优解决方案是什么？
```

### 2.2 场景思维

```
场景 = 用户 + 时间 + 地点 + 动机 + 行为

示例（外卖APP）：
  用户：上班族小王
  时间：工作日中午12点
  地点：办公室
  动机：午饭时间短，不想出去排队
  行为：打开外卖APP，搜索附近餐厅，下单

从场景出发设计功能：
  → 午餐时段推荐（时间）
  → 附近商家排序（地点）
  → 快速复购上次订单（行为习惯）
  → 预计送达时间显示（核心关注）
```

### 2.3 商业思维

```
产品不只是好用，还要能赚钱（或支撑公司战略目标）

三个核心问题：
  1. 市场有多大？（TAM/SAM/SOM）
  2. 怎么赚钱？（商业模式）
  3. 竞争壁垒是什么？（护城河）

常见商业模式：
  广告模式：   免费使用，广告变现（抖音、今日头条）
  订阅模式：   按月/年付费（Netflix、ChatGPT Plus）
  交易抽成：   平台抽取佣金（美团、淘宝）
  增值服务：   基础免费，高级收费（QQ会员、Notion）
  API调用：    按使用量计费（OpenAI API、阿里云）
  硬件+服务：  卖设备+增值服务（iPhone+iCloud）
```

## 3. 用户需求分析

### 3.1 需求来源

| 来源 | 方法 | 特点 |
|------|------|------|
| 用户反馈 | 客服工单、应用商店评论、社群 | 直接但可能偏颇 |
| 用户调研 | 访谈、问卷、焦点小组 | 深入但样本小 |
| 数据分析 | 行为数据、漏斗分析、留存 | 客观但不知原因 |
| 竞品分析 | 分析竞品功能和策略 | 启发性但不能照搬 |
| 老板/业务 | 商业目标、战略方向 | 必须理解并翻译成产品语言 |

### 3.2 需求分类

```
功能需求 vs 非功能需求：
  功能：用户能做什么（搜索、下单、支付）
  非功能：体验要求（加载 < 2秒、99.9%可用性）

真需求 vs 伪需求：
  真需求：解决真实痛点，用户愿意付费/时间
  伪需求：听起来不错但没人用（过度设计）

判断方法：
  1. 频率：多久遇到一次？（高频 > 低频）
  2. 强度：多痛？不解决会怎样？（刚需 > 可有可无）
  3. 规模：影响多少人？（大众 > 小众）
  4. 付费意愿：愿意花多少钱/时间？
```

### 3.3 需求优先级 — RICE 模型

```
RICE 评分 = (Reach × Impact × Confidence) / Effort

Reach（影响人数）：这个功能影响多少用户？
  例：10000人/季度

Impact（影响程度）：对用户体验的改善程度
  3 = 巨大  2 = 高  1 = 中  0.5 = 低  0.25 = 极低

Confidence（确信度）：你有多确定这个判断？
  100% = 有数据支撑  80% = 有调研  50% = 直觉

Effort（开发成本）：需要多少人月？
  例：2人月

示例：
  功能A: (10000 × 2 × 80%) / 2 = 8000 分
  功能B: (5000 × 3 × 50%) / 4 = 1875 分
  → 先做 A
```

### 3.4 用户故事

```
格式：
  作为一个 [用户角色]，
  我想要 [功能/行为]，
  以便 [价值/目的]。

示例：
  作为一个 外卖用户，
  我想要 查看骑手的实时位置，
  以便 知道外卖还有多久送到。

验收标准（Acceptance Criteria）：
  1. 下单后显示骑手位置地图
  2. 每30秒自动刷新位置
  3. 显示预计剩余时间
  4. 骑手到达500米内发送通知
```

## 5. 用户调研方法

### 5.1 用户访谈

```
准备：
  1. 明确调研目标（想验证什么假设？）
  2. 准备访谈提纲（5-10个开放式问题）
  3. 找到目标用户（5-8个即可发现主要模式）

提问技巧：
  ✓ "你上次遇到XX问题是什么时候？" （具体场景）
  ✓ "当时你是怎么解决的？" （现有方案）
  ✓ "这个过程中最困扰你的是什么？" （痛点）
  ✗ "你觉得XX功能好不好？" （引导性问题）
  ✗ "你会不会用XX功能？" （用户说的≠用户做的）

记录：
  录音（需征得同意）+ 关键词笔记 + 用户表情/情绪
```

### 5.2 问卷调查

```
设计原则：
  1. 题目 < 15 道（太长没人填）
  2. 先简单后复杂
  3. 选择题为主，开放题 1-2 道
  4. 避免引导性问题
  5. 预留"其他"选项

样本量参考：
  定性研究：5-10 人
  问卷调查：100-500 人
  A/B测试：按统计显著性计算
```

## 6. 动手练习

1. **用户画像**：为你最常用的一款 AI 产品（如 Kimi/豆包）画一个用户画像
2. **场景分析**：列出 3 个用户使用该 AI 产品的典型场景
3. **需求优先级**：假设你是该产品的PM，用 RICE 模型给以下需求排序：
   - 支持上传 PDF 文件对话
   - 增加语音输入功能
   - 优化首次回复速度
   - 增加多模态图片理解
4. **用户故事**：为"AI智能客服"写 3 条用户故事

## 7. 小结

| 概念 | 核心要点 |
|------|---------|
| 产品思维 | 用户思维 + 场景思维 + 商业思维 |
| 需求分析 | 从场景出发，区分真伪需求 |
| 优先级 | RICE 模型量化评估 |
| 用户画像 | 具象化目标用户 |
| 用户调研 | 访谈（深度）+ 问卷（广度）+ 数据（客观）|
