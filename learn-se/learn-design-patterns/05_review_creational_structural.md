# 复习：23 个设计模式全景（理念优先版）

> 覆盖 00~04 全部课程的理念优先总结。代码细节见各课与 `practice/`。

## 使用方法：三层阅读法

1. **第一遍**：只看"一句话"和"机关"，建立全图；
2. **第二遍**：对照"隔离的变化"和"代价"，理解每个模式**为什么**长这样；
3. **第三遍**：做最后的鉴别题，把"场景 → 模式"的反应练成肌肉记忆。

---

## 总纲：三大类 = 三个问题

| 类别 | 回答的问题 | 隔离的变化 | 数量 |
|---|---|---|---|
| 创建型 | 对象**怎么诞生** | new 这个动作 | 5 |
| 结构型 | 对象**怎么组合** | 对象间的关系形状 | 7 |
| 行为型 | 对象**怎么协作** | 运行时的通信与分工 | 11 |

贯穿心法只有三条：

1. **封装变化**——每个模式都在一个变化点上开口子；
2. **面向抽象**——接口 + 实现 + 只认接口的持有者，是所有模式的公共 DNA；
3. **复杂度住哪边**——让"频繁变化的那一边"变便宜，另一边保持干净。

## 创建型：对象的五种出生方式

| 问题 | 模式 | 一句话 | 机关 | 代价 | AI 场景 |
|---|---|---|---|---|---|
| 全系统只能一份？ | 单例 | 拦在出生门口 | `__new__` 拦截 | 全局状态难测试 | 全局配置（现代用 DI） |
| 造哪种？（一种） | 工厂方法 | 子类决定造谁 | Creator 调抽象方法 | 每种产品一个子类 | 按类型建模型客户端 |
| 造哪种？（一族） | 抽象工厂 | 保证整族配套 | 一个工厂 = 一族 | 加新产品要改所有族 | 供应商全家桶 |
| 怎么一步步造？ | 建造者 | 链式拼装 + 交付质检 | 每步返回 self，build 校验 | 步骤多了才值得 | 拼 prompt |
| 复制现成的？ | 原型 | 深拷贝模板再改 | `copy.deepcopy` | 共享对象要不可变 | 会话模板克隆 |

**选型链**：要几份？→ 一份：单例（慎用）→ 多种：造一种走工厂方法，造一整套走抽象工厂 → 构造复杂：建造者 → 有现成模板：原型。

**深层理解**：

- 工厂方法本质上是**模板方法在创建场景的应用**（`export()` 是骨架，`create_document()` 是可变步骤）；
- 抽象工厂 = 用一组工厂方法保证"整族配套"；它管"选择"，不管"怎么造"；
- 建造者管"流程"，Director（可选）管"配方"——Python 里常退化成函数/模板字典；
- 原型 = "复制规则由对象自己定"，`deepcopy` 是默认规则，`clone()` 是定制规则（共享什么、重置什么）。

## 结构型：对象的七种相处方式

| 问题 | 模式 | 一句话 | 机关 | 代价 | AI 场景 |
|---|---|---|---|---|---|
| 接口不匹配？ | 适配器 | 包一层翻译 | 实现目标接口，内部调第三方 | 多一层间接 | 各家模型 API 统一 |
| 两轴独立扩展？ | 桥接 | 两个家族任意组合 | 抽象持有实现引用 | 两轴真的会变才值 | 能力 × 供应商 |
| 树形统一对待？ | 组合 | 叶子和容器同一接口 | 容器持有 children + 递归 | 树才有意义 | 任务树、组件树 |
| 动态叠加功能？ | 装饰器 | 不改原件包洋葱 | 转发前后加料 | 层数多了难调试 | 模型调用加日志/重试 |
| 复杂子系统？ | 外观 | 给个前台 | 一个方法编排子系统 | 别变上帝对象 | `agent.run()` |
| 大量相似对象？ | 享元 | 共享不变的部分 | 池按 key 复用 | 共享对象必须不可变 | 上千 Agent 共享工具定义 |
| 控制访问？ | 代理 | 请替身把关 | 同一接口 + 延迟/拦截 | 不需要控制就是多余 | SDK 客户端、缓存、权限 |

**选型链**：接口对不上→适配器；两轴→桥接；树→组合；想增强→装饰器；太复杂→外观；太多→享元；要控制→代理。

**深层理解**：

- 适配器**改**接口（翻译），外观**加**入口（编排）——一个改旧的，一个加新的；
- 装饰器**必转发**（加功能），代理**可能不转发**（控访问）——结构一样，意图相反；
- 享元是"按 key 的单例池"；共享的前提是内部状态不可变；
- 装饰器、代理、适配器、桥接都长着"接口 + 持有引用"的相似脸——**用意图区分，不用结构区分**。

## 行为型：对象的十一种协作方式

| 问题 | 模式 | 一句话 | 机关 | 代价 | AI 场景 |
|---|---|---|---|---|---|
| 算法可切换？ | 策略 | 策略靠选 | Context 持有策略，运行时换 | 分支少就是多余 | Prompt 策略、折扣 |
| 一对多通知？ | 观察者 | 广播给订阅者 | 事件源持有订阅者列表，逐个调 | 顺序/异常/泄漏要管 | 流式 token 回调 |
| 行为随状态变？ | 状态 | 状态靠变 | 状态对象自己决定转换 | 状态少就是多余 | Agent 生命周期 |
| 操作要撤销？ | 命令 | 动作封装成对象 | 命令存接收者 + 之前状态 | 动作多则类多 | 工具调用记录/重放 |
| 流程固定步骤可变？ | 模板方法 | 骨架固定步骤可变 | 父类调抽象方法（好莱坞原则） | 骨架常变会拖累子类 | Agent 主循环 |
| 请求沿链处理？ | 责任链 | 谁合适谁停 | 每个处理器持"下一个" | 链长难调试 | 守卫链、中间件 |
| 统一遍历？ | 迭代器 | 位置 + 移动规则 | `__iter__`/`__next__` | Python 已内置 | 流式输出、懒加载分块 |
| 多对象协调？ | 中介者 | 传话不走蜘蛛网 | 同事只认中介者 | 中介者变上帝对象 | Agent 调度、聊天室 |
| 保存/恢复状态？ | 备忘录 | 快照不透明 | Originator 存/取，Caretaker 保管 | 状态大要增量 | Agent 检查点 |
| 新操作不改结构？ | 访问者 | 操作搬去 Visitor | 双分派：accept → visit | 加节点要改所有 Visitor | AST 分析 |
| 语法解释执行？ | 解释器 | 每个规则对象解释自己 | 递归 interpret | 语法复杂用解析器库 | 规则 DSL、表达式引擎 |

**深层理解**：

- **策略靠选，状态靠变**——结构几乎一样，谁决定切换是关键；
- 观察者是"点名"，中介者是"传话"，总线是"广播"——同一个事件思想的耦合度递进；
- 命令 + 备忘录 = 编辑器的撤销/重做（动作记录 + 状态快照）；
- 模板方法 vs 策略：**继承固定骨架 vs 组合换算法**；
- 访问者 vs 解释器：逻辑在节点里（解释器） vs 逻辑在外部（访问者）；
- 责任链 vs 装饰器：**谁能处理谁停 vs 层层都执行**；
- 中介者 vs 外观：双向协调 vs 单向入口。

## 容易混的九组"亲戚"

| 组 | 区别口诀 |
|---|---|
| 工厂方法 / 抽象工厂 / 建造者 | 造一种 / 造一族 / 一步步造 |
| 适配器 / 外观 | 改造接口（翻译） / 新增入口（编排） |
| 装饰器 / 代理 | 加功能（必转发） / 控访问（可能不转发） |
| 策略 / 状态 | 主动选 / 自动变 |
| 观察者 / 中介者 / 总线 | 点名 / 传话 / 广播 |
| 组合 / 装饰器 / 解释器 | 树 / 洋葱 / 语法树 |
| 命令 / 备忘录 | 动作可撤销 / 状态可恢复（常配合） |
| 模板方法 / 策略 | 继承固定骨架 / 组合换算法 |
| 访问者 / 解释器 | 操作外置 / 逻辑内嵌 |

## 模式嵌套：常见组合地图

```
享元工厂（创建）→ 享元池（结构）→ 大量共享对象
抽象工厂（创建）→ 适配器族（结构）→ 插进六边形端口
命令（行为）→ 备忘录（行为）→ 撤销/重做
状态（行为）→ 观察者（行为）→ 状态变化广播
模板方法（行为）→ 工厂方法（创建）→ 框架骨架 + 产品创建
组合（结构）→ 访问者（行为）→ 树结构 + 外部操作
装饰器（结构）→ 策略（行为）→ 增强 + 算法切换
```

## 鉴别题（先自己猜，再看答案）

1. 两家模型 API 不同，业务统一成一个 `chat()` → **适配器**
2. 给模型调用加日志、重试、缓存，顺序可换 → **装饰器**
3. 对外只暴露 `agent.run()`，内部编排一堆组件 → **外观**
4. 一千个 Agent 共享同一份工具定义 → **享元**
5. 大模型客户端第一次调用才初始化 → **代理（虚拟）**
6. 任务树统一 `run()`，不区分叶子和组 → **组合**
7. 机器人能力 × 模型供应商两轴扩展 → **桥接**
8. 相同提问不重复调 API → **代理（缓存）**
9. 购物车折扣算法可切换 → **策略**
10. 模型吐 token，UI/日志/统计同时收到 → **观察者**
11. 订单状态：待支付→已支付→已发货，非法操作被拦 → **状态**
12. 工具调用可记录、可重放、可回滚 → **命令**
13. 请求先过认证、再过限流、最后业务 → **责任链**
14. Agent 主循环固定，各角色换实现 → **模板方法**
15. 大文档分块懒加载，`for` 遍历不占内存 → **迭代器**
16. 研究员、编码员、审查员不互持引用，靠调度器传话 → **中介者**
17. 多步任务失败后回滚到最近安全点 → **备忘录**
18. 表达式树加"求值""打印"操作，节点类不改 → **访问者**
19. 简单 DSL"当置信度>0.8 时触发工具"求值 → **解释器**
20. 会话模板复制出多个新会话 → **原型**
