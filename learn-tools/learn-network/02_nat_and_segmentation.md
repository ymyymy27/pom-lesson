# 第2课：NAT 与网段隔离 —— 为什么不同网段、不同地区连不通

## 1. 典型场景

先看三个真实协作场景：

### 场景 A：家宽 vs 公司内网

同事 A 在家（`192.168.1.x`），同事 B 在公司（`10.20.30.x`）。
A 想直接访问 B 电脑上的 `http://localhost:3000`。

结果：**失败**。两人的地址都是私网地址，互联网上根本不存在
`192.168.1.5` 或 `10.20.30.7` 这些"门牌号"。

### 场景 B：云服务器 vs 本地

你的电脑连不上云服务器上的数据库，但服务器能 `ping` 通。

结果：**可能失败**。公网能到服务器，但数据库端口没放行，或数据库只监听了
内网地址。

### 场景 C：两边都有公网 IP

公司有一台带公网 IP 的服务器，家里宽带也申请了公网 IP。

结果：**不一定通**。公网 IP 可能被运营商做了 NAT（CGNAT），
或入站端口被运营商/防火墙拦截。

---

## 2. 什么是 NAT

**NAT（Network Address Translation，网络地址转换）** 就是"把私网地址翻译成
公网地址"的技术。

```text
你的电脑 192.168.1.10
    │  源地址: 192.168.1.10:54321
    ▼
路由器做 NAT，改成自己的公网 IP
    │  源地址: 100.64.0.2:54321（或公网 IP）
    ▼
互联网上的服务器
```

### 2.1 为什么需要 NAT

IPv4 公网地址不够用，运营商和路由器通过 NAT 让**成百上千台私网设备**
共享一个公网地址。

### 2.2 NAT 带来的副作用

**外面的设备无法主动连接你**。因为路由器只记录"由内向外"的连接映射，
外部发来的新连接没有对应映射，直接被丢弃。

这就是"为什么同事 ping 不通你电脑"的根本原因之一：

1. 你的地址是私网的，互联网上不可路由；
2. 即使路由器有公网 IP，NAT 默认不开放入站连接；
3. 运营商可能还套了一层 NAT（CGNAT），你连自己的"公网 IP"都管不了。

---

## 3. CGNAT：运营商级 NAT

### 3.1 什么是 CGNAT

很多家宽用户拿到的"公网 IP"其实是 `100.64.0.0/10` 网段（CGNAT 专用段），
或者被运营商做了端口级共享。

判断方法：

```powershell
# 1. 查看路由器 WAN 口 IP，或浏览器访问:
#    https://myip.ipip.net  /  https://ip.sb

# 2. 如果 WAN 口 IP 是 100.64.x.x ~ 100.127.x.x
#    说明你处于运营商 CGNAT 后面
```

### 3.2 遇到 CGNAT 怎么办

| 方案 | 说明 |
|------|------|
| 向运营商申请公网 IP | 部分运营商可免费/付费开通 |
| 使用内网穿透工具 | 第 6 课：frp / ngrok / Cloudflare Tunnel |
| 使用 Mesh VPN | 第 4 课：Tailscale / ZeroTier（不需要公网 IP） |
| 使用中继服务器 | 第 5 课：TURN / DERP 中继 |

## 4. 网段隔离：不止 NAT

即使没有 NAT 问题，网段隔离也会让协作失败：

### 4.1 企业内网分段

公司网络通常分成多个网段：

```text
办公网     10.10.0.0/16     员工电脑
开发网     10.20.0.0/16     开发/测试服务器
生产网     10.30.0.0/16     生产环境（严格隔离）
数据库网   10.40.0.0/16     数据库（仅内部可访问）
```

网段之间通过防火墙策略控制访问：**开发网可以访问数据库网，
办公网默认不行**。这是安全设计，不是故障。

### 4.2 云 VPC

云服务器在 VPC（虚拟私有云）内也有自己的网段。不同 VPC 之间默认隔离，
需要做 VPC 对等连接或通过 VPN/专线打通。

### 4.3 地区差异

不同地区之间还可能有这些差异：

| 差异 | 例子 | 影响 |
|------|------|------|
| DNS 解析结果不同 | 公司内网域名在外部解析不到 | 需要 VPN 后才能用内网域名 |
| 运营商路由绕路 | 跨运营商/跨境延迟高 | 表现为"慢"而不是"不通" |
| 网络策略不同 | 校园网禁止入站、酒店网络隔离设备 | 设备间互相不可见 |
| 防火墙规则不同 | 公司只放行 80/443 | 自定义端口无法入站 |

## 5. 排查思路：可达性 vs 服务问题

连不上时，先定位是哪一层的问题：

```text
第1层  DNS      域名能解析吗？
第2层  路由/可达  ping 通吗？（服务器是否禁 ping 另说）
第3层  防火墙   端口放行了吗？
第4层  服务      目标端口有进程监听吗？
第5层  应用      服务本身健康吗？（鉴权、绑定地址、依赖）
```

### 5.1 快速判断命令

```powershell
# 1. 域名解析
nslookup your-server.example.com

# 2. 网络可达性
ping your-server.example.com

# 3. 端口是否放行（TCP）
Test-NetConnection your-server.example.com -Port 443

# 4. 本机端口是否监听
netstat -ano | findstr :443
```

Linux/macOS 对应：

```bash
dig your-server.example.com
ping your-server.example.com
nc -zv your-server.example.com 443
ss -tlnp | grep 443
```

### 5.2 "ping 不通"不等于"服务不可用"

很多服务器默认禁 ping（ICMP），但 443 端口是好的。**以端口探测为准**。

## 6. 动手练习

1. 查看你当前网络属于哪种类型：
   - 运行 `ipconfig`，记录 IP、网关、DNS；
   - 打开 `https://ip.sb`，对比路由器 WAN 口 IP；
   - 判断是否处于 CGNAT（WAN IP 是否为 `100.64.x.x`）。
2. 找出三个"互联网上访问不到你"的原因，写在一张纸上。
3. 用 `Test-NetConnection www.baidu.com -Port 443`（Windows）或
   `nc -zv www.baidu.com 443`（macOS/Linux）验证端口探测方法。
4. 尝试连接一个你已知"连不上"的同事服务，用 5 层排查法定位问题出在哪一层。

---

## 7. 小结

| 概念 | 关键点 |
|------|--------|
| NAT | 私网地址 ↔ 公网地址的翻译，导致外部无法主动连入 |
| CGNAT | 运营商再套一层 NAT，公网 IP 也可能"不公网" |
| 网段隔离 | 企业/云平台按安全策略隔离网段，默认不通是设计 |
| 地区差异 | DNS、路由、策略、延迟都会影响协作 |
| 排查分层 | DNS → 可达 → 防火墙 → 端口 → 应用 |

**结论：跨网段/跨地区协作，"直连"不是默认能力，而是需要专门方案。**

- 第 6 课：内网穿透（把本地服务发布到公网）
